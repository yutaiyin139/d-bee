## 二、实现要点（对照 11:58 修订版规格）

- **单态渲染**：`HealthPlanSheet` 只读 `profile.goal` 对应的一态，不渲染 segment、不遍历 `GOAL_LABELS`、不持有本地目标态；首次登录选减脂 → 只出减脂 Sheet，另两态不进 DOM。
- **确认后自动调整**：复用了项目既有能力 `ProfileScreen.submitBody()`（`calcTarget({goal})` → `saveProfile()` 重算 7 个派生字段 → `onProfileChanged(saved)`）。新增的只是保存成功后 `setPlanOpen(true)`，父级 `profile` 一变，方案 Sheet 自动重渲染成新目标态；首页「还可吃」、报告页同步更新，无需刷新页面。
- **确认前零写库**：目标草稿只在编辑 Sheet 的本地 `goal` state，点「保存并重新计算」才落库。
- **历史不回溯**：沿用 `ProfileScreen.tsx` 既有提示「历史记录不会被改动」，确认层再列「会改变 / 不会改变」两栏。
- **两条口径护栏**：方案页只读落库值、不现场重算（防与首页漂移）；完全不引用 `plan_summary`（AI 首次建议改目标后不重生成，避免「增重 + 减脂建议」矛盾）。
- **保持体重态**：无目标体重 / 进度 / 达成日，显示 ±1.0 kg 参考波动带；空档案显示「先完善身体数据」，不展示 `emptyTarget()` 的 1800 兜底值。
- **实施期收敛 3 处**（相对规格文档，均为降复杂度，已在本文件留痕）：
  1. 文案真源先放主端 `src/lib/healthPlan.ts`，**不下沉 `@dbee/shared`** —— 本轮 Web 先行，避免重建 shared/dist 牵动 mini；待 Web 验收通过、其他端同构时再下沉。
  2. 首次引导 Sheet 只给「开始记录」一个主操作 + 一句「可在我的 › 健康管理方案随时调整」，**不做跨层直开编辑 Sheet**，避免 App 与 ProfileScreen 双向耦合。
  3. 复用既有编辑 Sheet 的「保存并重新计算」按钮与右上角关闭作为确认/取消，**按钮文案未改**，只补确认层说明。
- **三目标标签沿用 `GOAL_LABELS`**：减脂 / 保持体重 / **增重增肌**（用户口中的「增重」= `gain`），未改名、未新增第四种目标。
