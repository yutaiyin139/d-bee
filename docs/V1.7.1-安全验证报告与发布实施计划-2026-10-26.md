```

```

**风险定性**：这是当前**最严重的线上漏洞**，优先级高于本轮修的全部 ①–⑥。
持万能码 + 任意手机号即可登录**任何用户账号**，读取其全部健康档案

因为攻击者是「合法登录」。

**阻断性**：`config.validate()` 已内置守卫（`DBEE_PROD=1` + `log` → 拒绝启动），
说明设计上就认定这是不可上线状态。

**修复不是纯配置**：`server/lib/sms.mjs` 的 `tencent()` / `aliyun()` 目前只有占位 stub：
```js

```
→ 需要**采购短信服务 + 实现 provider + 清空万能码 + 开启 DBEE_PROD**，是一项开发任务。

**双重风险**：

   漂移后要么本地工具连不上（可用性故障），要么为图方便放成 `0.0.0.0/0`（安全性崩塌）。

**注**：网关与 PostgREST 都在服务器本机走回环，**生产链路完全不需要 5432 对外开放**。
这条白名单纯粹是为本地开发调试留的，可用 SSH 隧道替代。

### 🟡 P1-4 无 HTTPS，域名未解析 —— 四端上架硬阻断

实测：
```

https://150.158.51.106/ → 握手失败

当前站点：http://150.158.51.106/ → 200（裸 IP + 明文 HTTP）
```

**为什么是硬阻断**（三端各自强制要求）：
- **iOS**：App Store 审核要求 ATS（HTTPS），且 App Store Server Notifications V2
  webhook **必须**是 HTTPS URL
- **微信小程序**：request 合法域名**必须** HTTPS + **已备案**域名（裸 IP 直接不可用）
- **支付宝/抖音小程序**：同上
- **Android**：明文 HTTP 需在 `network_security_config` 显式放行（当前靠此妥协）

**依赖链**（不可乱序）：
```
域名过户到公司 → ICP 备案主体变更（管局 1–20 工作日）
   → DNS A 记录解析到 150.158.51.106
      → certbot HTTP-01 签发证书（需 80 公网可达 + 备案完成，否则腾讯云拦截）
         → deploy/setup-https.sh（已有脚本，自动改写 nginx + 301 跳转）
```
`setup-https.sh` 的注释已明确写出这三条前置，缺一不可。

> 📌 **对 V1.7.1 的影响判断**：若 V1.7.1 的定位是「**Web + Android 内部可用/灰度**」，
> HTTPS 非阻断（Android 已放行明文、Web 走 IP 可用）。
> 若定位是「**四端全部上架**」，HTTPS + 备案是**前置阻断项**，且备案周期最长（管局 1–20 工作日），
> **必须立刻启动**，否则会卡住整条发布链。
