## 二、🔴 资质就绪后会立刻踩到的架构差异（必须现在决策）

**Apple 是拉模式，微信/支付宝是推模式，两者的核销时序相反。**

- Apple：客户端拿到 `receipt` → 主动调服务端验签 → 验签通过才 `finish`。`settlePurchase`（`checkout.ts:101-132`）就是为这个时序写的。
- 微信/支付宝：客户端 `sendPaymentRequest` resolve 只代表**用户侧付完了**，权益的权威信号是**服务端异步收到支付平台回调**。回调到达时间不可控，通常**晚于**客户端的核销调用。

按现设计直接接会发生什么（沿代码走一遍）：

1. `wechatPay.purchase()` 成功返回 `{ providerTxnId, receipt: prepayId }`
2. `settlePurchase` → `verifyPaymentOrder` → 服务端此刻**还没收到回调**，订单仍 `pending` → 返回 `false`
3. 微信/支付宝 adapter **没有 `finishPurchase`**（`wechatPay.ts:105-160` 只有 fetchProducts/purchase/restore），故 `mustFinish = false`
4. `checkout.ts:161-164` 落入 else 分支 → **返回 `{ status:'error', message:'支付校验失败，请稍后重试或联系客服' }`**

**结果：用户已扣款，App 却报「支付校验失败」。** 这不是边缘情况，是主路径——回调延迟是常态。

### 必须做的两个决策（不依赖资质，现在就能定）

| 决策 | 建议 |
| ---- | ---- |
| **A. 微信/支付宝的核销改为「查订单状态 + 有限重试」** | 客户端 `verifyPaymentOrder` 对 wechat/alipay 语义改为**查询订单是否已 paid**（幂等、可重复调），配合短间隔重试（如 1.5s × 4 次，共 ~6s）。重试窗口内仍 pending → 返回**新状态 `settling`**（文案「支付已完成，权益正在到账，稍后自动刷新」），**绝不能报 error**。到账由服务端回调驱动，客户端下次进入付费墙/启动恢复时再查一次。 |
| **B. 权益发放唯一权威 = 服务端回调** | 回调端点必须：验签 → 幂等标记 `paid` → 写 `entitlements`。客户端回传的 `prepayId` **只作核销定位，不作为信任依据**（`wechatPay.ts:150-152` 注释已这么写，需在服务端实现时守住）。 |

> 这两条落定前不要开始写下单端点，否则写完还要改客户端状态机。

## 四、验收标准（对齐审计文档）

原计划验收：「沙盒下单→支付→回调→权益生效全链路通；幂等与退款覆盖」。细化为：

1. **正向链路**：沙盒下单 → 拉起收银台 → 支付 → **服务端回调** → 权益生效（客户端不刷新也能在下次进入时读到）
2. **回调延迟**：人为延迟回调 10s，客户端必须显示 `settling` 而非 `error`，且**最终权益到账**（§二 的核心场景）
3. **幂等**：同一 `order_no` 回调重放 3 次 → 权益只发一次；`verify_payment_order` 重复调用 → 恒 true 不重复发
4. **退款**：退款回调 → `status='refunded'` → 权益回收 → 用户端会员标识消失
5. **并发**：同一用户同时发起两笔同商品订单 → 不出现双份权益
6. **安全**：devtools 直调 `verify_payment_order` 传伪造 `prepayId` → **必须 false**（守住 `0021:150-157` 的默认拒绝）
7. **华为渠道**（若上华为）：华为包内**看不到任何支付方式名称/logo**，走 IAP Kit 收银台完成支付

## 五、明确不做的事（防范围蔓延）

- ❌ 不做订阅自动续期。微信/支付宝按**预付费周期**（月/年一次性买断时长），`wechatPay.ts:96-99` 注释已固化，`restore()` 返回空数组是对的
- ❌ 不做 Google Play（见 §一「范围待定」）
- ❌ 不把验签逻辑塞进 plpgsql（10-22 决策 #6）
- ❌ 不动 `mini/`：小程序端**当前没有任何支付入口**——`paywall.tsx:22-31` 是 2026-11-02 的整改结果，刻意不展示价格、不提供支付，解锁只靠兑换码（且 legal.ts 已公示「不销售任何商品或服务，不涉及在线支付」）。未来若要在小程序内收费，走的是**微信虚拟支付（xpay）**，与本文的微信/支付宝直连是两套完全不同的东西，须单独立项，不要混进 P1-D
- ❌ 资质未就绪前不写任何下单端点：当前「诚实降级」（占位 `return null` + 「正在接入中」提示）是**正确状态**，提前接线只会引入不可测的半吊子链路
