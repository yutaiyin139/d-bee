# 分享卡片（O-3）详细规划设计

> 版本：V1.4 · 状态：规划稿（待拍板后实施）
> 目标：用「打卡卡片 / 徽章卡片」做精美分享图，零 UGC 合规风险地拿到社交传播，赶超自律茄子的社群氛围优势。

---

## 一、为什么做分享卡片（而不是完整社区）

| 维度 | 完整社区（自律茄子） | 分享卡片（本方案） |
|---|---|---|
| 合规风险 | UGC 内容审核、敏感信息、涉政涉暴，需内容安全体系 | **零 UGC**：只有系统生成的固定模板，无用户输入正文 |
| 开发量 | 社区/评论/关注/消息推送，数月 | 2–3 天（前端模板 + 截图 + 分享） |
| 传播效果 | 站内封闭，拉新弱 | 发朋友圈/微信群，**天然带品牌露出 + 下载入口** |
| 维护成本 | 持续运营 + 审核团队 | 一次性做完，几乎零维护 |

**结论**：分享卡片是「社群传播效果 / 合规风险 / 开发成本」三者最优解。先把卡片做扎实，社区留到有真实用户量 + 内容安全体系后再评估。

---

## 二、分享内容设计（3 类卡片）

### 卡片 1：每日打卡卡（核心，最高频）

**触发场景**：每日完成全部打卡（记餐 + 饮水达标 + 运动）后，Dashboard 顶部「今日打卡」完成态出现「分享我的自律」按钮。

**卡片内容**（自上而下）：
```
┌─────────────────────────┐
│  🐝 自律蜜蜂 · 今日打卡   │  ← 品牌区（logo + 名称）
│                         │
│  连续自律  7 天           │  ← 核心数据（大字号，streak.current）
│  ▓▓▓▓▓▓░░░░ 距 14 天     │  ← 进度条（当前连续 / 下一里程碑）
│                         │
│  今日完成                │  ← 三格打卡项（打勾态）
│  ✓ 记一餐  ✓ 饮水  ✓ 运动 │
│                         │
│  今日摄入 1,820 / 目标 2,000 kcal  │  ← 热量小结（可选）
│                         │
│  我在「自律蜜蜂」坚持记录饮食， │  ← 一句话文案（固定模板，非用户输入）
│  一起变自律吧！            │
│                         │
│  [ 下载自律蜜蜂 ]          │  ← CTA（二维码 + 短链）
└─────────────────────────┘
```

### 卡片 2：成就徽章卡（解锁瞬间的荣誉分享）

**触发场景**：InviteCenter 里每枚已解锁徽章旁加「分享」；或徽章刚解锁时弹「分享我的成就」。

**卡片内容**：
```
┌─────────────────────────┐
│  🐝 自律蜜蜂 · 成就徽章   │
│                         │
│        🏆               │  ← 徽章 emoji（大字）
│     百日蜂王             │  ← 徽章名
│   连续打卡 100 天         │  ← 徽章 desc
│                         │
│  我在「自律蜜蜂」解锁了新成就， │
│  坚持记录让我更自律！      │
│                         │
│  [ 下载自律蜜蜂 ]          │
└─────────────────────────┘
```

### 卡片 3：邀请卡（拉新场景，已有邀请码分享的升级）

**触发场景**：InviteCenter「邀请好友」按钮，从「纯文字口令」升级为「精美邀请卡」。

**卡片内容**：品牌 + 「邀请码」大字号 + 二维码 + 「下载自律蜜蜂，输入邀请码，双方都得积分」。

## 三、技术实现方案

### 3.1 核心：DOM → Canvas 截图 → 图片分享

分享卡片用 **HTML/CSS 画模板 → html2canvas 或 canvas 手绘 → 生成 PNG → 分享**。

**两个可选路线，推荐路线 A**：

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 纯 Canvas 手绘（推荐）** | 用 canvas API 直接绘制卡片，不依赖 DOM | 零第三方依赖、跨端一致、体积小 | 需手写绘制逻辑 |
| B. html2canvas 截图 | 隐藏 DOM 渲染卡片再截图 | 布局用 CSS 方便 | 引入 ~100KB 依赖、iOS WebView 兼容性差 |

**推荐 A 的理由**：项目当前 Web 主包已 428KB，引入 html2canvas 会再 +100KB；且 iOS WKWebView 对 html2canvas 的截图（尤其跨域字体/图片）兼容性差。纯 Canvas 手绘可控、轻量、三端（Web/Android/iOS）行为一致。

### 3.2 模块划分（符合架构约定：平台差异走抽象层）

```
src/lib/sharecard.ts          ← 新增：卡片绘制核心（纯 Canvas，无平台依赖）
  ├── drawCheckinCard(canvas, data)   → 绘制打卡卡
  ├── drawBadgeCard(canvas, data)     → 绘制徽章卡
  ├── drawInviteCard(canvas, data)    → 绘制邀请卡
  └── canvasToBlob(canvas)            → PNG Blob

src/lib/share.ts              ← 扩展：shareImage(blob, opts)
  ├── Web：downloadBlob（下载 PNG）
  └── 原生：@capacitor/share（系统分享面板）

src/pages/Dashboard.tsx       ← 接入：打卡完成态「分享我的自律」按钮
src/pages/InviteCenter.tsx    ← 接入：徽章「分享」+ 邀请卡入口
```

### 3.3 关键数据源（全部已存在，无需新查询）

| 卡片 | 数据 | 来源 |
|---|---|---|
| 打卡卡 | streak.current / nextMilestone | `computeStreak()` 已有 |
| 打卡卡 | 今日三项打卡 | `dailyCheckinHoney()` 已有 |
| 打卡卡 | 今日摄入/目标 kcal | Dashboard `totals.kcal` / `target.calories` 已有 |
| 徽章卡 | 徽章 name/desc | `BADGES` / `badgeByKey()` 已有 |
| 邀请卡 | 邀请码 | `getMyInviteCode()` 已有 |

**无需任何新增数据库表或 API**，纯前端模板 + 已有数据。

### 3.4 下载入口（二维码 + 短链）

卡片底部的「下载自律蜜蜂」需要二维码。方案：
- **二维码内容** = Web 站地址 `http://150.158.51.106/`（或将来正式域名）
- **生成方式**：项目已有 `zxing`（条码扫描用，966KB wasm）。二维码生成可用更轻的纯 JS 库（如 `qrcode-generator`，~20KB），**不要**复用 zxing（那是解码器，且 wasm 体积大）。
- **V1 简化**：卡片底部先放「自律蜜蜂」品牌 + 文字下载提示，二维码留到有正式域名/备案后（ICP 备案完成前不放二维码，避免跳转裸 IP 的观感差）。

### 3.5 分享/保存通路

| 端 | 行为 |
|---|---|
| Web（http） | 生成 PNG → `a.download` 保存到相册/下载目录（用户再手动发朋友圈） |
| 原生 Android | `@capacitor/share` 直接唤起系统分享面板（微信/朋友圈/保存图片） |
| 原生 iOS | `@capacitor/share` + 若将来接 `@capacitor/filesystem` 存相册 |

> ⚠️ 原生分享目前 `share.ts` 是占位（未接 `@capacitor/share` 插件）。分享卡片落地时需**一并接入 `@capacitor/share`**（这也是 share.ts 注释里预留的 P1 事项，正好借分享卡片一并完成）。

## 四、实施步骤（写 → 验 → 报）

| 阶段 | 内容 | 验收 |
|---|---|---|
| 1 | `sharecard.ts`：drawCheckinCard/drawBadgeCard/drawInviteCard 三个纯 Canvas 绘制函数 + canvasToBlob | 单测：给定数据，生成 PNG 尺寸/内容断言 |
| 2 | `share.ts` 加 `shareImage()`；Web 走 downloadBlob，原生预留 Capacitor Share 分支 | typecheck + Web 端下载成功 |
| 3 | Dashboard 打卡完成态接「分享我的自律」按钮 | 打卡后按钮出现、点开生成卡片 |
| 4 | InviteCenter 徽章加「分享」+ 邀请卡入口 | 徽章卡、邀请卡可生成 |
| 5 | 视觉打磨：卡片配色/字体/品牌一致 | 三端截图对比 |
| 6 | （可选）接入 `@capacitor/share` 让原生直接分享 | 真机唤起分享面板 |

**估计工期**：阶段 1–4 约 1.5 天；阶段 5 视觉打磨 0.5 天；阶段 6 原生分享 0.5 天。合计 **2–3 天**。

## 五、风险与注意

1. **卡片文案合规**：所有文案走固定模板（非用户输入），无 UGC 风险；不出现「拉人头返利」「躺赚」等涉传措辞。
2. **Canvas 字体**：Web 端用系统字体栈（`-apple-system, PingFang SC, sans-serif`），原生端一致；避免引用需下载的 webfont（http 环境跨域 + 体积）。
3. **二维码延后**：ICP 备案完成前不放二维码（裸 IP 观感差 + 备案合规），先用文字 CTA。
4. **不要复用 zxing 生成二维码**：zxing 是解码器且 wasm 大，用轻量生成库或不放二维码。
5. **隐私**：卡片只展示「自己的」打卡数据与徽章，不泄露他人信息；不展示体重绝对值（减重榜已砍，卡片同理只放「减重 3kg」这类相对值）。
