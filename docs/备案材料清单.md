> 本网站是北京迪蜂科技有限公司运营的个人饮食与生活习惯记录工具，供用户记录每日饮食内容与热量、饮水量、体重变化和运动情况，并以图表形式查看统计结果，用于个人自我管理。不涉及医疗健康咨询、商品销售和在线交易。本单位无固定电话，应急联系电话为备案填报的法人手机号。

> 自律蜜蜂是一个面向个人用户的饮食与生活习惯记录工具，由北京迪蜂科技有限公司开发并运营。

> 主要功能：
> 1. 用户注册登录后，记录每日饮食内容及其热量估算值；

> 5. 提供常见食物的公开营养成分查询（数据来源为 Open Food Facts 等公开数据库），以及基于图像识别的食物名称辅助填写功能。

> 数据说明：用户填写的记录数据仅本人可见，不对外公开，网站不提供用户间的社交互动、评论、发帖等电子公告服务。
>
> 免责与合规：本网站提供的热量与营养数值均为参考估算值，不构成医疗建议；不提供医疗诊断、健康咨询、药品或保健品推荐，不涉及疾病治疗；不销售任何商品或服务，不涉及在线支付。

   ✅ **「不要设 `DBEE_DOMAIN`」纪律已随 B2 完成而解除**，今后常规部署**应当**设 `DBEE_DOMAIN=d-bee.cn`。

   📌 **B2 域名范围（实测确定）**：`d-bee.cn` + `www.d-bee.cn` 已签（SAN 一张证书覆盖）。
   `d-bee.com.cn` 无 A 记录，**签进去 `setup-https.sh:49-56` 会直接 exit 1**，须先加解析再补签。
   🔴 **更正本节原有一句错误结论**：原文写「实测 `www.d-bee.cn` 经主站 catch-all `_` 正常返回 200，
   nginx 能接住 —— 此前担心的『缺 server_name』实测不成立」。**这个结论对「能否访问」成立，
   对「能否签证书」不成立**，本轮已实测推翻：`certbot --nginx` 靠 **`server_name` 显式名字**定位
   server 块，catch-all `_` 匹配不到 → 缺 `d-bee.cn` 时会报

   📌 教训：**「nginx 能接住请求」与「certbot 能定位 server 块」是两套判据**，
   前者看 `listen`/`default_server`/catch-all，后者只看 `server_name` 里有没有那个确切名字。

## 7. 流程与时间

```
腾讯云提交备案
   ↓  腾讯云初审                    1–2 个工作日（可在控制台催审 / 撤单修改）
   ↓  工信部短信核验                ⚠️ 24 小时内必须完成，超时订单自动失效、
                                    管局直接驳回，需要重新提交
   ↓  省通信管理局终审              5–20 个工作日（提交管局后无法撤回、无法催办）
   ↓  管局通过后数据同步            6–24 小时，同步完成后备案号才正式生效
   ↓  公安联网备案                  网站开通后 30 日内
```

### ⚠️ 短信核验：提交后唯一会「过期作废」的一步

提交后工信部会发短信到备案时填的手机号，需要在 **24 小时内**到工信部备案系统完成核验。**不核验 = 订单自动失效**，前面的材料全部白填。

- 完成核验后申请将直接进入管局审核，**此时无法撤回**
- 所以核验前如果发现填错了，应该**不核验**，等订单自动失效后重新提交

### 关于域名解析：首次备案期间不要加解析

腾讯云官方规则：**首次备案，域名在备案成功之前不能做解析**。原因有两个 ——

1. 未备案域名解析到腾讯云大陆服务器会被自动拦截，访问只会看到备案提示页
2. 首次备案的审核**不依赖**域名可访问，审核方通过备案系统的材料核验

所以：

| 项目 | 正确做法 |
|---|---|
| 备案期间 | ❌ 不加 A 记录。`@` 和 `www` 都保持无解析 |
| 备案通过后 | ✅ 再加 A 记录 `@` → `150.158.51.106`，然后绑域名 + 上 HTTPS |
| 备案期间用 IP 访问 | ✅ 不受影响，`http://150.158.51.106/` 全程可用 |

> 注：如果是「接入备案」（域名已在别处备过案，转到腾讯云），规则相反 —— 腾讯云初审通过后就要解析过去才能解除拦截。本站属**首次备案**，按上表执行。

## 8. 后续接入收费入口，需要怎么做

### 8.1 性质变了：从「备案」升级为「许可」

一旦站内出现真实收款（微信/支付宝、苹果内购、会员订阅、付费内容），网站就从**非经营性**互联网信息服务变为**经营性**互联网信息服务 —— 性质从「备案」变成「许可」。

| 后果 | 说明 |
|---|---|
| 备案信息与内容不符 | 个人备案不得含在线支付、会员收费。先收到整改通知，逾期注销备案号、暂停域名解析 |
| 无证经营 | 《互联网信息服务管理办法》第 19 条：责令限期改正、没收违法所得、处违法所得 3–5 倍罚款、责令关闭网站 |

所以个人备案**接不了任何支付入口**，必须先把主体换成公司。

### 8.2 ICP 经营许可证的硬性条件（缺一不可）

| 条件 | 具体要求 |
|---|---|
| 主体 | 中国大陆**有限责任公司 / 股份有限公司**。⚠️ 个体工商户、个人独资企业、合伙企业**都不能申请** |
| 注册资本 | ≥ 100 万元人民币（**认缴**即可，无需实缴） |
| 经营范围 | 营业执照需含「第二类增值电信业务」 |
| 人员社保 | ≥ 3 名员工在公司名下缴社保（近 1 个月记录，部分地区要求连续 3 个月），至少 1 人计算机相关专业 |
| 网站 | 服务器在境内、已完成 ICP 备案、内容与申请业务一致 |
| 域名 | 必须归公司所有（WHOIS 与公司一致）→ 需从个人过户到公司 |
| 页面 | 需有用户协议、隐私政策、免责声明、收费说明等必备板块 |
| 审批 | 省通信管理局，20–60 个工作日；有效期 5 年，每年需年报 |

**⚠️ 最容易踩的坑**：个体工商户**能**申请微信支付/支付宝商户号（拿得到收款通道），但**拿不到** ICP 经营许可证。所以「注册个体户 + 网页上收费」这条路是不通的，必须是公司。

### 8.3 迁移顺序（2026-10-27 更新实际进度）

1. ✅ 注册公司（北京迪蜂科技有限公司），经营范围含「第二类增值电信业务」——**已完成**
2. ✅ 域名 `d-bee.com.cn` 从个人**过户**到公司名下（阿里云）——**已完成（2026-10-27 WHOIS 实测）**
3. 🔴 备案主体由个人改为公司——**路径已定死：北京不允许「个人→企业」直接变更，必须「注销原备案 → 以企业主体重新备案」**，注销期间域名不能解析（本站 IP 直连，无实际停服）
4. ⬜ 补齐合规页面：用户协议、隐私政策、免责声明均已上线（`/legal/terms`、`/legal/privacy`、`/legal/disclaimer`）；**收费说明页待接入支付前补**
5. ⬜ 提交 ICP 经营许可证申请（前提：3 人社保——当前唯一硬缺口）
6. ⬜ **拿到证之后**才上线网页端支付入口

时间约 2–4 个月。成本：代办 5000–15000 元 + 每年记账报税 2000–5000 元 + 3 人社保（主要成本，约每月 4000 元量级）。

> 顺带一个好处：企业备案的网站名称可用公司简称或品牌名，自由度更大，「自律蜜蜂」在个人备案下的那点措辞隐患也一并消失。

### 8.4 不办证的替代路径

| 路径 | 做法 | 口径情况 |
|---|---|---|
| **原生 App + 应用商店内购** | 打包成 Apk/Ipa 上架，收入由 Apple / 安卓商店代收结算 | **个人开发者账号即可上架**，实践中普遍可行；严格口径下仍属经营性，但交易与收款发生在平台侧 |
| **第三方平台代收** | 服务或内容放到第三方平台售卖，站内不出现支付入口 | 站内合规压力最小，代价是分成与流量受平台控制 |
| **保持免费** | 只用兑换码解锁，不涉及任何收款 | 完全干净，但没有收入 |

> 关于「卖兑换码」：只要存在**对价**（付费换取会员权益），性质上仍属经营性服务，不建议作为长期方案，只适合过渡期。
