## 一、口径：Android 的「上线」与「收费」为什么必须拆开

| | 上线（可被安装使用） | 收费（能收到钱） |
| --- | --- | --- |
| 卡点性质 | **合规 + 分发载体**：App 备案、软著、商店账号、包名/label 一致、下载页 | **资金链路**：DB 结算函数、网关端点、商户凭据、平台资质、真机联调 |
| 当前开关 | 无开关（vc30 已可安装） | `D_BEE_APPPAY_ENABLED`（构建期字面量，**默认 false**） |
| 可独立推进 | ✅ **可以**（备案已下证，自建分发页现在就能做） | ❌ 9 项必须**全部**就绪，缺一即「可点但收不到钱」 |

🔴 **不可互推**：`blockPublicDistribution=false` **只代表可以分发**，与能不能收款无关。反过来，收款就绪也不代表可以上架商店（软著仍卡）。

🔴 **双开关同源纪律**（`vite.config.ts:73-90` / 护栏 **20-B** `tools/apppay-consistency.test.ts:149-151`）：`D_BEE_APPPAY_ENABLED` **一个变量同决定**「Android 付费墙是否出支付按钮」+「Web 定价页是否出『去 App 购买』引导」，两端必须同值。`resolveApppaySaleFlag()` 只接受字面 `'true'/'false'`，其他值**构建期抛错**（防半开）。

🔴 **Android 收款架构既定**（2026-10-25 / 11-09 拍板）：走**微信 APP 支付（V3 普通商户号）+ 支付宝 App 支付（RSA2）**，**不走 Google Play**（国行无 GMS）。

🔴 **Android 独有的一个好消息**：三档商品**不需要在任何平台后台建道具**。`wechatOfferItemId`（mini 虚拟支付用）与 `ascProductId`（iOS 用）对 Android **均不适用**；Android 的商品真源只有服务端 `payment_products` 表（`apppay.mjs` 下单时查价，**客户端不参与算价**，防篡改）。→ 少一整类平台配置工作。

## 六、绝对禁止（Android 相关红线汇总）

| 禁止动作 | 后果 |
| --- | --- |
| 🔴🔴 跑 `deploy-gateway.sh` | 缺 `IDENT_PEPPER` → **全站身份永久失效**（只读/备份也不行） |
| 🔴🔴 整搬本地 `auth.mjs` 覆盖生产 | 覆盖 werun 4 锚点 → **微信运动链路当场断裂** |
| 🔴 原生包用 `npm run build` | **白屏**（须走 `npm run native:sync`） |
| 🔴 只部署 `apppay.mjs` 不带 `config.mjs` | 生产 config 不解析支付键 → **填 env 静默无效**，半配拦截也失效 = 裸奔 |
| 🔴 倒序应用 0047→0046 | `verify_payment_order` 覆盖关系错乱 → xpay 核销逻辑被 Android 版覆盖 |
| 🔴 分发 vc30/vc31 以外的任何归档 APK（**37 个**） | 复盘/教练被 0052 网关**静默重写为食物识别**，不报错难察觉 |
| 🔴 恢复 `inferTextFeature` 做兼容 | 被护栏 22-C 堵死 = 给 Pro 墙开客户端可控后门 |
| 🔴 `0047` 未应用就开 `D_BEE_APPPAY_ENABLED` | 结算表/函数不存在 → **资损** |
| 🔴 缺 `WECHAT_PAY_PLATFORM_CERT` / `ALIPAY_PUBLIC_KEY` 就上 | 回调验签必失败 → **用户付了钱发不出权益（资损级）** |
| 🔴 `WECHAT_PAY_APIV3_KEY` 非 32 字节 | 回调 AES-256-GCM 解密失败 |
| 🔴 只开 Android 不同批发 Web | Web 引导与 Android 按钮**必须同源同值**（护栏 20-B），否则「引导去不能收款的端」= 虚假宣传 |
| 🔴 `8000`/处理中态报 error | 可能已扣款 → 必须落 `settling`，异步通知 + 查单兜底 |
| 🔴 调 `redeem_by_code` 做测试 | **真烧码**（0048 护栏永不写明文） |
| 🔴 跳过真机验证宣称「已修复上线」 | 违反**铁律 #13**（本地绿 ≠ 线上绿） |
| 🔴 未经确认删除/清理归档 APK | 违反用户既定删除纪律（须先出清单 + 原因 + 影响评估 + 替代方案，等明确确认；「全部允许」不豁免） |
