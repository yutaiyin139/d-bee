## 四、代码合规缺口 🔴🟡（本次核查新发现，收费清单未记录）

### 4.1 🔴 P0 · 首次启动隐私政策弹窗**缺失**

- **现状**：全仓搜索无首启隐私弹窗逻辑（`App.tsx` 无 `firstLaunch/privacyAgreed` 等；唯一「同意并继续」在 `AiConsent.tsx:62`，那是 AI 功能同意弹窗，非首启隐私弹窗）。
- **要求**：华为/小米**直接拒审**；OPPO 明确驳回「首次必须在登录页面出现前独立弹框展示隐私政策」。硬性四要素：①独立、不可跳过、**不能默认勾选**；②《用户协议》《隐私政策》**可点击链接**（点了能打开）；③「同意」+「不同意/退出」两按钮，点不同意**直接关闭 App**；④文字明确「点击同意即表示已阅读并同意上述协议」。
- **整改**：`App.tsx` 顶层加 `PrivacyGate`，kv 存 `privacy_agreed` 标志；未同意时渲染全屏弹窗，链接打开 `LegalPage`；「不同意并退出」调原生退出（Capacitor `App.exitApp()` 或等价）。**纯代码，不依赖任何资质，可立即做。**

### 4.2 🔴 P0 · 隐私政策第三方 SDK 公示不全

- **现状**：`src/content/legal.ts:191` 「四、第三方服务」**只公示了腾讯云**。但 release APK 实测含多个第三方 SDK（dex 扫描）：`com.tencent.mm.opensdk`（微信 OpenSDK，188 处）、`com.google.gson`、`org.apache.cordova`、`com.capacitorjs.plugins`、`io.ionic.libs`。
- **要求**：OPPO **重点审查**，要求隐私政策公示的 SDK 与**全国 SDK 管理服务平台**登记信息**完全一致**（SDK 名称 / 开发者 / 收集信息范围 / 目的 / SDK 隐私政策链接）。微信 OpenSDK 标准公示名：「微信 OpenSDK Android / 深圳市腾讯计算机系统有限公司」。
- **整改**：法律文案补全 SDK 清单。⚠️ 注意 `WECHAT_LOGIN_ENABLED=false`（`src/lib/wechat.ts:67`）但 SDK 仍在包里 → **要么公示、要么彻底移除依赖**，不能「装了但不说」。

### 4.3 🟡 P1 · AI 生成内容显式标识不足

- **法规**：《人工智能生成合成内容标识办法》+ 强标 GB 45438-2025，2025-09-01 施行、6 个月过渡期 → **2026-03-01 后全面强制**（现已适用）。要求显式标识（界面文字/图形，用户可明显感知）+ 隐式标识（文件元数据）。
- **现状**：已有部分标识——`ReportScreen.tsx:403`「由 AI 根据上面的数据生成」、`LogSheet.tsx:184`「AI 估算，份量请按实际核对」✅；但 **`CoachSheet.tsx`（问问小蜜）的 AI 回答气泡无逐条显式标识**（仅靠 `AiConsent` 首次告知，不充分）。
- **整改**：AI 问答气泡加「AI 生成」角标/前缀；评估 `sharecard.ts` 分享卡片若含 AI 内容是否触发隐式标识义务。

### 4.4 🟡 P1 · 账号注销为「降级实现」

- **现状**：`ProfileScreen.tsx:368` 注销是「清空本地数据 + 登出」，:737「彻底注销请通过『关于→联系我们』与客服联系」。
- **要求**：各商店要求 **5 步内便捷注销**，「联系客服」式有被判不便捷风险（iOS 5.1.1(v) 已合规，安卓口径类似）。
- **整改**：评估是否需服务端真删除接口，让 App 内一键彻底注销。

### 4.5 🟡 P1 · 隐私政策需静态 HTML 可爬

- **现状**：legal 是 SPA 路由（`/legal/privacy`），`index.html` 未预渲染隐私政策正文（grep「隐私政策」=0）。
- **要求**：OPPO 明确要**静态 html 页面**，不能是 PDF/图片/需登录/需 JS 渲染，否则自动化审核爬取失败 → 驳回。
- **整改**：为 `/legal/privacy` 等出静态 HTML（SSG 或 nginx 直出），确保无 JS 也能读到全文。

### 4.6 🟡 P1 · 证书 DN 与备案主体地址不符

- **现状**：keystore 证书 `O=D-Bee, L=Shenzhen, ST=Guangdong`，而备案主体是**北京**迪蜂科技有限公司。
- **要求**：备案要求「证书指纹与备案信息一致」；主体地址口径不一致有核验风险。
- **整改**：确认商店/管局是否校验证书 L/ST 字段；如需要，评估是否重签（⚠️ 重签 = 换证书 = App 备案须重做，权衡后再动）。

### 4.7 🟢 P2 · release APK 混入 JUnit 测试框架

- **现状**：`classes.dex` 含 `org/junit/*`（声明为 `testImplementation` 却进了 release 包，疑 `org.apache.cordova:framework` 传递依赖）。
- **影响**：增包体积；部分商店安全扫描标记「测试代码残留」。非阻塞。
- **整改**：`packagingOptions` 排除或定位传递依赖来源后 `exclude`。

## 五、数据面与域名 · 上线前必切 🔴

- **现状**：APK 实测连 `https://zilv-mifeng.app.workbuddy.host`（WorkBuddy 云）。原因：`src/cloudConfig.ts` 原生端 endpoint = `VITE_NATIVE_ENDPOINT`（**从未注入**）→ 回退 `CLOUD_HOST`。
- **问题**：①正式商用数据应落在公司**已备案**的自托管服务器；②隐私政策称数据「由腾讯云承载」，与当前实际链路（WorkBuddy 云）主体不一致。
- **整改**：ICP 备案 + HTTPS 就绪后，`VITE_NATIVE_ENDPOINT=https://d-bee.cn npm run build` → `cap sync` → 重打 APK（vc+1）→ 分发。**这是上架包的最终形态，当前 APK 仅可用于内测。**
