## 四、代码合规缺口 🔴🟡（本次核查新发现，收费清单未记录）

### 4.1 ✅ P0 · 首次启动隐私政策弹窗（2026-10-29 已实现，2026-11-02 复核确认）

> ⚠️ **本节原记载「缺失」已过时**（写于整改前）。2026-11-02 复核代码实证：已完整落地，
> 且实现优于当初的整改方案。保留原「要求」四条作为验收基准，勿再重复开发。

- **实现**：`src/components/PrivacyGate.tsx`，挂在 `src/main.tsx` 最外层（`BootErrorBoundary` 之内、
  `<App />` 之外）—— 未同意时 `<App />` **根本不挂载**，故 PlanProvider 的
  `getEntitlement`/`getPhotoQuota` 一次都不会发出，真正做到「同意前零采集」。
  （原方案是「App.tsx 顶层加门控」，实际实现更靠外，合规性更强。）
- **四要素逐条对照**：
  | 要求 | 实现位置 | 状态 |
  |---|---|---|
  | ① 独立弹框、不可跳过、**不默认勾选** | 无任何 checkbox，只能点按钮表态（`PrivacyGate.tsx:107-138`） | ✅ |
  | ② 《用户协议》《隐私政策》**可点击链接** | 两个 `button.privacy-link` → `setViewing()` 打开 `LegalPage` 全文 | ✅ |
  | ③ 「同意」+「不同意并退出」，点不同意**直接关闭 App** | `handleDecline()` → `exitApp()`（原生走 Capacitor `App.exitApp()`；Web 降级为不可用页，不放行） | ✅ |
  | ④ 明示「点击同意即表示已阅读并同意」 | `.privacy-tip` 文案原文照做 | ✅ |
- **额外加固**（超出四要素）：
  · **法律深链放行**：审核员/OPPO 爬虫直达 `/legal/privacy` 时，未同意态**只渲染 LegalPage 全文**
    （不挂载 App → 零网络请求），读完「返回」清掉深链落回同意门；不用 `history.back()`
    （审核员直接落地无历史记录，会退到空白页）。
  · **同意态以 `LEGAL_UPDATED`（政策更新日期）为版本标识**，政策改版会重新弹（PIPL 要求）；
    日期不变则不打扰老用户。
  · **Web 端同步预览**（`peekPrivacyConsent()`）避免首屏白屏 —— 白屏期被抓取会被判「页面无法加载」。
- 📌 iOS 侧已知降级（非阻断）：`@capacitor/preferences` 虽在 `package.json`，但
  `capacitor.config.ts:47` 的 ios.includePlugins **已含**该插件；若仍回落 localStorage，
  WKWebView 存储紧张被清时会重新弹同意门 —— 属「宁可多弹不可漏弹」的安全降级。


### 4.2 🔴 P0 · 隐私政策第三方 SDK 公示不全

- **现状**：`src/content/legal.ts:191` 「四、第三方服务」**只公示了腾讯云**。但 release APK 实测含多个第三方 SDK（dex 扫描）：`com.tencent.mm.opensdk`（微信 OpenSDK，188 处）、`com.google.gson`、`org.apache.cordova`、`com.capacitorjs.plugins`、`io.ionic.libs`。
- **要求**：OPPO **重点审查**，要求隐私政策公示的 SDK 与**全国 SDK 管理服务平台**登记信息**完全一致**（SDK 名称 / 开发者 / 收集信息范围 / 目的 / SDK 隐私政策链接）。微信 OpenSDK 标准公示名：「微信 OpenSDK Android / 深圳市腾讯计算机系统有限公司」。
- **整改**：法律文案补全 SDK 清单。⚠️ 注意 `WECHAT_LOGIN_ENABLED=false`（`src/lib/wechat.ts:67`）但 SDK 仍在包里 → **要么公示、要么彻底移除依赖**，不能「装了但不说」。

### 4.3 🟡 P1 · AI 生成内容显式标识不足

- **法规**：《人工智能生成合成内容标识办法》+ 强标 GB 45438-2025，2025-09-01 施行、6 个月过渡期 → **2026-03-01 后全面强制**（现已适用）。要求显式标识（界面文字/图形，用户可明显感知）+ 隐式标识（文件元数据）。
- **现状**：已有部分标识——`ReportScreen.tsx:403`「由 AI 根据上面的数据生成」、`LogSheet.tsx:184`「AI 估算，份量请按实际核对」✅；但 **`CoachSheet.tsx`（问问小蜜）的 AI 回答气泡无逐条显式标识**（仅靠 `AiConsent` 首次告知，不充分）。
- **整改**：AI 问答气泡加「AI 生成」角标/前缀；评估 `sharecard.ts` 分享卡片若含 AI 内容是否触发隐式标识义务。

### 4.4 🟡 P1 · 账号注销为「降级实现」

- **现状**：`ProfileScreen.tsx:368` 注销是「清空本地数据 + 登出」，:737「彻底注销请通过『关于→联系我们』与客服联系」。
- **要求**：各商店要求 **5 步内便捷注销**，「联系客服」式有被判不便捷风险（iOS 5.1.1(v) 已合规，安卓口径类似）。
- **整改**：评估是否需服务端真删除接口，让 App 内一键彻底注销。

### 4.5 ✅ P1 · 隐私政策需静态 HTML 可爬（2026-11-02 已实现）

- **要求**：OPPO 明确要**静态 html 页面**，不能是 PDF/图片/需登录/需 JS 渲染，否则自动化审核爬取失败 → 驳回。
- **整改（已完成）**：新增 `tools/gen-legal-static.mjs`，用 vite `ssrLoadModule` 直接加载
  `src/content/legal.ts` 的 DOCS/SITE（**单一真源**，不手抄第二份 → 不会与站内政策漂移），
  产出 `dist/legal/{terms,privacy,disclaimer}/index.html`：**零 JS、内联 CSS、无外部资源**。
  已串入 `npm run build`（`vite build && node tools/gen-legal-static.mjs`）；原生构建
  `build:native*` **不**串入（原生端法律文档由 React 在 App 内渲染，不需要静态页）。
- **为什么用目录 + index.html**：对外填报 URL 保持 `/legal/privacy` 不变，nginx
  `try_files $uri $uri/ /index.html` 的 `$uri/` 分支命中目录 index（已模拟验证），
  SPA 路由（`legalRoute.ts` 正则允许尾斜杠）行为不变，两套并存。
- **实测证据**（2026-11-02）：3 份产物 `<script>` 计数均 = 0；隐私政策裸文本 4253 字，
  「个人信息处理者/北京迪蜂科技有限公司/第三方服务/阿里云百炼/注销账号/未成年人」关键条款全在；
  `VITE_ICP_BEIAN` 注入通路验证通过（未传时不渲染备案块 = 不展示假备案号，与 SiteFooter 口径一致）；
  正文 <500 字即拒产（守卫）。
- 📌 **部署侧无需改 nginx**：现有 `location /` 的 try_files 已能直出静态页。上线时把
  `dist/legal/` 一并 rsync 到 `/var/www/d-bee/` 即可。

## 五、数据面与域名 · 上线前必切 🔴

- **现状**：APK 实测连 `https://zilv-mifeng.app.workbuddy.host`（WorkBuddy 云）。原因：`src/cloudConfig.ts` 原生端 endpoint = `VITE_NATIVE_ENDPOINT`（**从未注入**）→ 回退 `CLOUD_HOST`。
- **问题**：①正式商用数据应落在公司**已备案**的自托管服务器；②隐私政策称数据「由腾讯云承载」，与当前实际链路（WorkBuddy 云）主体不一致。
- **整改**：ICP 备案 + HTTPS 就绪后，`VITE_NATIVE_ENDPOINT=https://d-bee.cn npm run native:sync` → 重打 APK（vc+1）→ 分发。`native:sync` 已强制校验正式数据面；备案前如需云库内测，必须改用 `VITE_ALLOW_CLOUD_NATIVE=true npm run native:sync:internal`。**这是上架包的最终形态，当前 APK 仅可用于内测。**
