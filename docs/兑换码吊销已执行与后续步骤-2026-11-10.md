### 步骤 2 · 发新码

0048 应用后才能跑。**强烈建议一律带 `--expires-days`** —— 这是 0048 带来的止损能力
（码泄露了能自动过期，不用手动删库）。

```bash
cd /c/Users/yuty/WorkBuddy/2026-10-13-09-29-42/zilv-mifeng

# 先演练（不连库、不落盘，只打印 3 张样例）
node tools/gen-redeem-codes.mjs --plan lifetime --count 3 --note "演练" --dry-run

# 终身码（内测/合作/补偿用）
node tools/gen-redeem-codes.mjs --plan lifetime --count 5 --note "2026-11 内测"

# 月卡码，30 天内有效
node tools/gen-redeem-codes.mjs --plan pro --months 1  --count 20 --note "月卡首发" --expires-days 30

# 年卡码，90 天内有效
node tools/gen-redeem-codes.mjs --plan pro --months 12 --count 20 --note "年卡首发" --expires-days 90
```

**参数速查**：

| 参数 | 必填 | 说明 |
|---|---|---|
| `--plan` | 是 | `lifetime`（终身）/ `pro`（限时） |
| `--months` | pro 时必填 | 月卡=1、年卡=12；lifetime 不能带 |
| `--count` | 是 | 1~500 |
| `--note` | 是 | 批次备注，**对账唯一线索**，不能空 |
| `--expires-days` | 建议填 | 码有效期（天），缺省=永久有效 |
| `--print` | 否 | 把明文打印到终端（默认只落文件） |

**你会得到**：`release/redeem-codes-<档位>-<时间戳>.txt`

🔴 **库内只存 SHA-256 哈希，反推不出明文。这个 txt 是唯一明文来源。**
丢了文件 = 这批码作废（你也不知道明文了）。它等同现金：勿外发、勿提交、勿贴聊天。


## 四、本次事故的经验教训（已入档）

**「已修复」≠「已止损」。** 10-16 把码从前端移除时，判定为已修复；但仓库是 public，
`git` 历史里的明文永久可下载。删文件不等于删历史。

三条已固化的纪律：
1. **公开仓库里，任何写进过代码的密钥/码都视为已泄露** —— 必须显式吊销，不能只靠「删掉」。
2. **护栏自身不得含敏感值** —— 护栏 23 只钉 SHA-256 哈希，明文留在 gitignored 的 `release/`。
3. **生产变更要独立二次核验** —— 不复用同一事务的输出，另跑只读脚本确认（铁律 #13：本地绿 ≠ 线上绿）。
