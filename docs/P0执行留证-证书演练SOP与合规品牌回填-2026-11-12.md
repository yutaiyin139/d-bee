## 二、P0.5 · 证书续期演练（D6）

### 2.1 🔴 关键发现：可重入补丁脚本**早就存在**，不需要新写

实施计划 §1.3 把「写可重入 308 恢复补丁」列为 P0 动作，但实证发现
`deploy/fix-nginx-301-to-308.sh` **本身已经具备幂等**：

| 实证 | 位置 |
| --- | --- |
| 幂等分支 `ALREADY=1`：已是 308（2 行）时跳过备份/替换/reload，直接验证 | `:62-68` |
| 注释原文：「certbot renew 若把 301 注回来，BEFORE 会重新变 2，**本脚本可原样重跑**（这正是『续期后须复核』的处置手段）」 | `:57-59` |
| `nginx -t` 不过立即回滚、reload 失败自动恢复备份 | `:80-105` |
| `sleep 8` + 最多重试 3 次（nginx reload 优雅退出，旧 worker 持旧配置 → 立即验证会假红） | `:107-127` |

结论：**P0.5 的交付从「写新脚本」降级为「留证 + 演练 SOP」**，避免造一份重复脚本。

### 2.2 演练 SOP（服务端变更，须单独评审后执行）

```bash
# 1) 只做 dry-run，不触发真实续期
sudo certbot renew --dry-run

# 2) 复核 renewal 配置（关键：installer = nginx 会重新注入 return 301）
sudo grep -n "installer\|authenticator\|return 30" /etc/letsencrypt/renewal/d-bee*.conf

# 3) 若 301 被注回，原样重跑现成可重入脚本（它会自己判断 ALREADY）
bash deploy/fix-nginx-301-to-308.sh

# 4) 验收（脚本自带 sleep 8 + 重试 3 次）
curl -sI http://d-bee.cn/   # 期望 308，不是 301
# 判据：308=2 / 301=0；三法务页 200
```

官网 `E:/DEV/d-bee-website/FACTS.md:95-96` 已明确写：

> 计费方式**因购买渠道而异**：iOS App 内购按月/按年为**自动续期订阅**，
> 其余已开放渠道为一次性预付、不自动续费。官网**绝不**写「全渠道都不自动续费」。

所以对外口径必须是「**微信/支付宝等已开放渠道为一次性预付、不自动续费；iOS 内购为自动续期订阅，
可随时取消**」。若写成「全渠道不自动续费」，与用户协议「六、订阅与自动续费说明」直接冲突，
构成《广告法》第 4 条层面的虚假宣传。这是把承诺写出去之前必须先过的口径关。
