## 十、B7 详解：支付宝「应用 AppID」获取路径（2026-11-21 补写）

> 官方口径核实（2026-11-21 查证）：《创建应用》`docs.open.alipay.com/300/ynpz1w`、《接入准备》`opendocs.alipay.com/mini/03w0a7`、《三步快速接入 APP 支付》`opendocs.alipay.com/support/01raxx`、《接口加签方式说明》`docs.open.alipay.com/58/103541`、《应用平台信息如何配置(Android 版)》`opendocs.alipay.com/support/01rgk5`、《FAQ 如何创建网页&移动应用》`opensupport.alipay.com/support/knowledge/01/201602482183`。
> 项目侧实测锚点：`server/lib/config.mjs:249-251,562-570`、`server/lib/apppay.mjs:203-206,353-370`、`src/lib/payment/alipay.ts:73-96`、`tools/apk-distribution.baseline.json:9,16`、`public/icon-512.png`（实测 512×512 / 121,821 B）。

### 10.1 一句话答案

**支付宝侧的 AppID 不叫「移动应用 AppID」，而是「网页&移动应用」类型的应用 APPID：用企业支付宝账号登录开放平台（`open.alipay.com`）→ 创建「网页/移动应用」（应用类型选「移动应用」）→ 绑定商家账号 + 配 RSA2 密钥 + 绑定「App 支付」产品 → 提交审核（约 1 个工作日）→ 通过后应用详情页即显示 APPID → 🔴 再手动「上线」+ 商家平台「开通」才能在生产调用。**

🔴 **两个平台的 AppID 别搞混**（承接 §9.1 那张表）：

| 你要的东西 | 去哪拿 | 拿到后填哪个键 |
| --- | --- | --- |
| **微信**移动应用 AppID（`wx` 开头 18 位） | `open.weixin.qq.com`（**开放平台**，非小程序后台、非商户平台）→ 见 §九 | `VITE_WECHAT_APPID` + `WECHAT_PAY_APPID` |
| **支付宝**应用 APPID（纯数字） | `open.alipay.com`（**开放平台**，非 `b.alipay.com` 商家平台）→ 本节 | `VITE_ALIPAY_APPID` + `ALIPAY_APP_ID` |

### 10.2 🔴 先搞清一个机理差异：支付宝的客户端 AppID 只是「门禁」，不决定支付成败

这是与微信侧**最本质的不同**，也是最容易埋雷的地方：

- **微信侧**：客户端 AppID 会真的交给原生 SDK（`wechatPay.ts:136` `plugin.initialize({ appId })`），填错 → SDK 初始化/拉起阶段就失败，**报错早、看得见**。
- **支付宝侧**：客户端**不签名、不算价、不传 AppID 给支付宝**。真实链路是「客户端只要 orderStr」→ `alipay.ts:129` `plugin.pay({ orderStr: prepay.orderStr })`，而 orderStr 完全由**服务端**构造并本地 RSA2 签名（`apppay.mjs:353-370`：`alipay.trade.app.pay` + `product_code=QUICK_MSECURITY_PAY` + `appId: cfg.alipayAppId`）。客户端那个 `VITE_ALIPAY_APPID` 的唯一作用是 `alipay.ts:94,110` 的**非空门禁**（空 → `isAlipayAvailable()` 返回 false → 诚实降级，不产假按钮）。

**由此得到两条结论（重要）：**

1. 🔴 **两处必须同一个值，但填错的后果不对称**：
   - 服务端 `ALIPAY_APP_ID` 填错 = 下单参数错/验签错 → **下单即失败或回调验签失败（资损级：用户付了钱权益发不出）**。
   - 客户端 `VITE_ALIPAY_APPID` 填了**任意非空垃圾值** = 门禁被骗过 → **假按钮**（点下去服务端才报错）→ 体验级故障，且**比微信侧更隐蔽**（微信假按钮会在 SDK 阶段就挂）。
2. 🟢 **建议补一条护栏**（与 §6.1 那条 `VITE_WECHAT_APPID` 护栏同批做）：断言「构建期 `VITE_ALIPAY_APPID` 与服务端 `ALIPAY_APP_ID` 同源同值」，防止将来只改一处。🔴 新增断言**必须先做红验证**（故意让两者不同，确认 FAIL），否则等于没有护栏。

### 10.3 🟢 本轮查证推翻一个既有疑虑：公钥模式合规，项目实现零改造

项目旧文档 `docs/P1-D在线支付实装前置清单-2026-11-03.md:84` 曾写「推荐**证书模式**而非公钥模式」，而项目实现是**公钥模式**（`apppay.mjs:203-206` `verifyAlipayNotifySignature` 直接用 `alipayPublicKey` 验签，无证书链、无 `app_cert_sn`）。本轮查官方《接口加签方式说明》原文：

> 密钥（公钥）方式适用场景：**除资金支出类场景外，都可以使用密钥加签方式**；红包（原「现金红包」）、转账到支付宝账户**必须**使用证书加签方式，其他场景可以选择使用密钥或证书。

**APP 支付（`alipay.trade.app.pay`）属收单类，不是资金支出类 → 公钥模式完全合规，项目现有实现无需改造。** 🟢 这条把 B7 的工程量从「可能要重写验签」降为「只填 env」。

🔴 **但留两个决策痕**：
- **一个 APPID 只能配一种加签方式**（官方限制）。将来若要做**发红包 / 转账到支付宝账户**（例如拉新奖励、退款到账户），必须整体切证书模式 → 届时全量重配密钥 + 网关重新部署（属生产变更）。**现在选公钥模式 = 明确暂不做资金支出类玩法。**
- `config.mjs:251` 的注释已特别点明陷阱：🔴 **`ALIPAY_PUBLIC_KEY` 是「支付宝公钥」，不是「应用公钥」**，填错则异步通知验签必失败 → 资损级。三个「公钥/私钥」的归属见 §10.4 第 4 步。

### 10.4 五步流程（含每步的坑 + 项目现成可抄的值）

**第 1 步 · 企业支付宝账号入驻开放平台**
- 入口：`open.alipay.com` → 用**已实名的企业支付宝账号**登录 → 入驻开放平台，服务范围选**「自研开发服务」**（本项目是自研，官方明写「网页&移动应用只支持商户自研创建，不支持服务商 ISV 代创建」）。
- 前置：**营业执照 + 对公账户**。🟢 **前置已满足**（见 §10.6 订正）。
- 🟢 **与微信侧的关键差别：支付宝没有 ¥300 开发者资质认证这道单独收费门槛**（微信有，见 §9.2）→ **支付宝侧更快、更省钱**。
- 🔴 坑：**个人账户虽然也能创建网页/移动应用，但 App 支付这类需签约产品必须绑定商家账号（企业）** → 别用个人号创建，否则后面签约走不通，等于白建一个 APPID。

**第 2 步 · 创建「网页/移动应用」，应用类型选「移动应用」**
后台必填项与项目现成可抄的值（全部实测）：

| 后台字段 | 填什么 | 出处 |
| --- | --- | --- |
| 应用名称 | **自律蜜蜂** | 与软著名/App 备案名/vc31 `application-label` 逐字一致（baseline:18） |
| 应用类型 | 🔴 **移动应用**（不是「网页应用」） | 官方：移动应用适用于 App，且「应用平台为必填项」 |
| 绑定商家账号 | 你的企业支付宝账号 | 官方：应用须绑定商家账号才能调用需商家开通的产品 |
| 应用图标 | `public/icon-512.png`（实测 **512×512 / 121,821 B ≈ 119 KB**） | 官方「建议 320×320 且小于 3M」→ 🟢 体积达标；尺寸偏大通常可接受，**若被驳回就缩放到 320×320 重传** |
| 应用包名 | **`cn.com.dbee.app`** | baseline:9 `packageName` |
| 应用签名 | 🔴 **见下方专项警告** | — |

🔴🔴 **应用签名专项警告（本节最高危的一条）**：
- 官方口径（`opendocs.alipay.com/support/01rgk5`）：应用签名**必须用支付宝官方的 `GenSignature.apk` 工具在真机上获取** —— 从「Android 接入指南」下载 Android 分享 SDK / DEMO 包（内含 `GenSignature.apk`）→ 装到手机 → **先把你的 APK（vc31）装上手机**（工具靠包名反查已安装应用的签名；未安装会报「应用签名报错请检查包名是否正确」）→ 打开 GenSignature，输入包名 `cn.com.dbee.app` → 点「获取签名并复制」。
- 🔴 **不要直接把 baseline:16 的 `signerMd5 = 0abe7fc5005987ed9b6eae9a45fb9dc9` 填进去**。那是 `apksigner verify --print-certs` 口径的证书 MD5；微信开放平台要的正是这种 32 位小写无冒号 MD5，但**支付宝 `GenSignature` 的输出算法/格式口径不保证与 apksigner 一致**。两者若一致最好；**若不一致，一律以支付宝工具实测输出为准**，否则线上拉起会签名校验失败（且这种失败只在真机复现，本地测不出）。
- 🟢 **与 A1 天然耦合，一次真机拿两个证据**：A1 本来就要把 vc31 装到华为/小米真机验证。**装完之后顺手跑一次 `GenSignature.apk`**，同时拿到「真机安装成功」+「支付宝要的应用签名」两份证据，不多花一次真机成本。

**第 3 步 · 产品绑定「App 支付」+ 商家平台签约开通**
- 应用详情页 → **产品绑定 → 绑定产品 → 勾选「App 支付」→ 确定添加**。

- 🔴 **「绑定」≠「开通」**，两步都要做。官方《三步快速接入 APP 支付》明写：「应用上线后，还需要完成**开通**才能在线上环境（生产环境）使用功能。」只做绑定不做开通 → 线上调用报无权限。

**第 4 步 · 开发设置：接口加签方式（必填）+ 应用网关（必填）**
- 用支付宝官方**密钥工具**生成 **RSA2（SHA256withRSA）** 密钥对 → 在「开发设置 > 接口加签方式」选**公钥**模式（理由见 §10.3）→ 上传**应用公钥** → 平台回给**支付宝公钥**。
- 🔴 **三个密钥别搞混**（`config.mjs:562-570` 已做成半配拦截：3 项缺 1 即启动报错，不会静默 503）：

| 密钥 | 谁生成 | 去哪 | 填错的后果 |
| --- | --- | --- | --- |
| **应用公钥** | 你（密钥工具） | 上传给支付宝 | — |
| **应用私钥**（PKCS8） | 你（密钥工具） | 🔴 **仅服务端 `ALIPAY_PRIVATE_KEY`**（`config.mjs:250`，已做 `\n` 还原）→ **禁入库、禁进 `VITE_*`、禁进终端** | 下单签名错 → 支付宝拒单 |
| **支付宝公钥** | 支付宝给你 | 服务端 `ALIPAY_PUBLIC_KEY`（`config.mjs:251`，验异步通知） | 🔴 **回调验签必失败 → 用户付了钱拿不到会员（资损级）** |

- **应用网关**（必填，接收异步通知的公网 HTTPS 地址）→ 填 **`https://d-bee.cn`**。本项目 notify 端点实测 = **`https://d-bee.cn/.cloud/payment/alipay/notify`**（`apppay.mjs:366` 用 `cfg.publicBaseUrl` 拼接，`config.mjs:234` 默认值 `https://d-bee.cn`）。
- 🔴 **别把「应用网关」和「支付宝网关」搞混**：支付宝网关是**固定值** `https://openapi.alipay.com/gateway.do`（你调支付宝接口的目标地址），不用你填；应用网关是**你的**地址（支付宝回调你）。
- 域名口径提醒：本项目 = **`d-bee.cn`**（`京ICP备2026075565号-2`）；`d-bee.com.cn` 是公司门户（`-1`），**不要填错**（`packages/shared/src/constants` 已登记此区分）。

**第 5 步 · 🔴 手动上线（这一步最容易漏）**
- 官方明写：**小程序应用审核通过后自动上线；网页/移动应用需要手动上线。**
- 路径：应用总览 → **提交审核** → 预计 **1 个工作日** → 审核通过后**手动点「上线」**。

### 10.5 拿到后填哪里（两处，🔴 键名不同）

| 位置 | 键名 | 当前实测 | 谁执行 |
| --- | --- | --- | --- |
| 服务端（生产 env） | 🔴 **`ALIPAY_APP_ID`**（中间**多一个下划线**，`config.mjs:249,563`；**不是** `ALIPAY_APPID`） | 未配置 | B8（我执行，**须你批准**） |

```ts
setPayChannels(APPPAY_SALE_ENABLED && isAndroid()
  ? { wechat: isWechatPayAvailable(), alipay: isAlipayAvailable() }
  : { wechat: false, alipay: false })
```

即：`wechat` / `alipay` 是**两个独立布尔**，各自按自己的门禁（AppID 非空 + 插件在场）决定亮不亮。**支付宝先就绪就只显示支付宝按钮，不需要为了等微信而整体拖延。** 🔴 但注意 `APPPAY_SALE_ENABLED` 是**总闸**，一开两个渠道都按各自门禁亮 → 若只想先放支付宝，就让微信侧的 `VITE_WECHAT_APPID` 保持空（即 B0 置空的直接收益，见 §6.1）。

### 10.8 本节新增红线（补进 §五）

1. 🔴 **应用签名以 `GenSignature.apk` 真机实测输出为准**，不得凭 baseline 的 `signerMd5` 直接填（§10.4 第 2 步）。

6. 🔴 **服务端键名是 `ALIPAY_APP_ID`（多一个下划线）**，与构建期 `VITE_ALIPAY_APPID` 不同形，且两处必须同值。
