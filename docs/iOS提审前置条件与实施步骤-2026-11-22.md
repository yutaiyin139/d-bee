**处置选项**（🔴 按你的删除纪律，我给出评估后**等你明确确认**，「全部允许」不豁免删除）：

### 1.4 DB 迁移验证的唯一正解（裁定后的标准做法）

**范式**：生产 PG 上 `BEGIN…ROLLBACK` 单事务 + 合成前缀数据 + `trap` 兜底清理。

已落地实现（本轮复核其安全边界，全部通过）：

| 文件 | 规模 | 复核结果 |
| --- | --- | --- |
| `tools/server-apply-0056.sh` | 37,800 B | ✅ `bash -n` 通过 · ✅ 纯 LF（服务器端脚本会用 `grep -qU $'\r'` 拒绝 CRLF）· ✅ 探针全程一个 `BEGIN…ROLLBACK` · ✅ 合成数据一律 `TEST-0056-` 前缀（绝不碰审核账户 `dbeesupport@163.com`、绝不碰任何 19 位数字形态真实 owner_id）· ✅ `trap` 兜底按前缀 DELETE · ✅ 应用前 `pg_dump -Fc` + `pg_restore --list` 验 TOC ≥100 否则 FATAL 退出 · ✅ ⑦ 段回滚后独立复查四表行数与基线一致 |
| `tools/apply-apple-txn-anonymize-prod.py` | 9,113 B / 182 行 | ✅ `py_compile` 语法合法 · ✅ 凭据只从 `.env` 读 · ✅ 输出 `redact()` 过滤 JWT / `wbpk_` / 32 位 hex · ✅ 上传文件 LF 化 + 权限 644（🔴 必须 644：服务器端 psql 以 postgres 身份跑，700/600 会读不到）· ✅ 带 `--check` **只读预检**模式（零写操作） |
