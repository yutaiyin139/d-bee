> 主体变更完成后必须重新备案，而**新备案完成前不能提交发布小程序新版本**（备案期 1–20 工作日）。

小程序端刚修好「问问小蜜」超时+打字机（networkTimeout 180s + 流式 UI），还没上传发布。两条路线二选一：

| 路线 | 做法 | 适合 |
|---|---|---|
| **A. 先发后变**（推荐） | 周一/周二先在开发者工具**上传并发布**修复版（当前个人主体），周三再发起主体变更 | 想让线上用户先拿到修复；变更备案期不影响已发布版本运行 |

**结论：除非本周就要变更备案且能接受发版冻结，否则选 A——今明两天先把修复版发出去。**

### 🔴 P1 · 短信协议签署 + 通道切换（5.6）

1. 腾讯云控制台签短信服务协议、充值短信包（建议先充 1000 条试水）。
2. 建**短信子账号** API 密钥（CAM 最小权限，别用主账号密钥）。
3. 创建应用拿 `SdkAppId`；提审**签名**「自律蜜蜂」+ **模板**「您的验证码是{1}，{2}分钟内有效」（签名/模板审核约 2 小时–2 天，⚠️ 签名主体须是公司，个人签名审核不过——这也是为什么要等公章/主体材料）。
4. 凭据到手后改服务器 `/etc/dbee/gateway.env`：
   ```
   SMS_PROVIDER=tencent
   SMS_TENCENT_SECRET_ID=...
   SMS_TENCENT_SECRET_KEY=...
   SMS_TENCENT_SDKAPPID=1400xxxxxx
   SMS_TENCENT_TEMPLATE_ID=...
   DBEE_PROD=1
   # 删除 SMS_MASTER_CODE 行（validate 会拦「tencent+万能码」）
   ```
   `systemctl restart dbee-gateway`。万能码自此死亡，Web/Android 登录走真短信（iOS 一直走云库真短信，不受影响）。
5. 验收：新手机号注册收真短信；日志只打掩码号+SerialNo；`journalctl -u dbee-gateway | grep SMS` 无明文码。
