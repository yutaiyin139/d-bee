## 4. 数据链路与计算口径

```
手环/手表 ──蓝牙──> 厂商健康 App ──授权──> 系统健康平台 / 开放 API ──只读──> DbeeHealth 插件
      ──> src/lib/health/ 统一门面 ──> { steps, activeKcal, status } ──> Dashboard
```

- **只读平台层、不直连手环**（已定决策，勿推翻）。Health Connect 是这一层的**重点方向**，见专项规划。
- 只取当天 `steps`、`activeKcal`；无历史落库、无睡眠/心率/体重同步。
- `effectiveBurnKcal = max(手动 burnKcal, activityKcal)`；「可吃回」`ACTIVITY_EATBACK_RATIO = 0.5`。
- 无活动能量时步幅法 `estimateActivityKcal()`（身高×0.45，缺省 0.72m；0.75 kcal/kg/km）。
- 连接态真源 = 云端 `profiles.health_connected`（单布尔，**无 `health_vendor`**）。
- 自测实跑：品牌矩阵 15/15、换算 8/8（10000 步/70kg/170cm → 402 kcal，50% → 201）。

## 6. 合规红线（接入前必须先过）

- 健康数据属**敏感个人信息**；云端接入需隐私政策单独告知 + 单独同意（隐私政策 §五 仍在待拍板清单）。
- 华为白皮书：用户撤销授权后须在法律时限内删除已接收数据；写入其平台的数据不上云、卸载重装会丢。
- Apple 禁止健康数据用于广告；读授权不可探测，不能据此推断用户健康状况。
- 🔴 `legal.ts`「不构成医疗诊断」—— 心率/睡眠/血氧不得做诊断色带或疗效承诺。
- 多源并存需 `health_vendor`（当前单布尔会让同账号跨 iPhone / 安卓串台）；拟与 Health Connect 落地时一并做。
