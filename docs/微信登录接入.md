# 微信登录接入（2026-10-14）

> 本文是 `docs/原生App化方案.md` §2.4 的落地记录与勘误。权威决策仍以方案文档为准，
> 但 §2.4 里「A 路线：原生 SDK 拿 code 交给 cloud.auth 换会话」这一设想，经实测
> **卡在云端而不是我们的代码**，详见下文「三、关键勘误」。

---

## 一、结论速览

| 端 | 微信登录现状 | 说明 |
|---|---|---|
| **Web / PWA** | ✅ **可用**（V1.0.1 起就有） | 走云 Relay 网页扫码，`signInWithOAuth({provider:'wechat'})` + `handleWechatWebCallback()`，**不需要自己的微信 AppID** |
| **Android 原生** | 🟡 代码侧就绪，入口已隐藏 | 原生 SDK 链路已接通并编译进 APK（`Registering plugin instance: CapacitorWechat` 已验证），但云端无「移动应用 code 换会话」接口，故入口按设计隐藏 |
| **iOS 原生** | 🟡 代码侧就绪，入口已隐藏 | 同上；iOS 编译需在 Mac mini 验证（Windows 无法构建 iOS） |

**设计原则**：入口可用性由 `src/lib/wechat.ts` 的 `isWechatLoginAvailable()` 统一裁决，
不可用时整个「或 + 微信登录」区块不渲染。这同时消除 App Store 审核的一类硬伤——
「登录方式点了没反应」是 2.1 / 4.2 的典型被拒理由。

## 三、关键勘误：原生微信登录的真正阻塞点在云端

`@tencent-ai/workbuddy-cloud-sdk` 提供的 `signInWithWechat(code, appid)`
（`lib/index.d.ts:442`）文档写明：

> 小程序 wx.login 的 code 换 Genie session。试用与正式是两套独立**小程序**，
> 必须带当前账号的 appid（`wx.getAccountInfoSync().miniProgram.appId`）。

服务端走的是小程序的 `jscode2session`；而微信开放平台**移动应用**（原生 App）拿到的
code 要走 `sns/oauth2/access_token` —— **两者不是同一个接口，不能混用**。

所以方案文档 §2.4 的 A 路线（原生 SDK 拿 code → 交给 cloud.auth）**当前走不通**。
要真正打通原生微信登录，需要按顺序满足四件事：

1. **云端**提供「移动应用 code 换会话」接口（或告知移动应用 code 的正确兑换入口）
   —— 这是唯一卡在别人手上的事，建议向 WorkBuddy 云服务方确认排期
2. 微信开放平台「移动应用」审核通过，拿到 AppID（主体认证 + 审核，数天到两周）
3. 构建时注入 `VITE_WECHAT_APPID`；iOS 再注入 `VITE_WECHAT_UNIVERSAL_LINK`
   （必须是已备案域名 + Associated Domains + apple-app-site-association，Mac 侧配置）
4. 把 `src/lib/wechat.ts` 里的 `NATIVE_CODE_EXCHANGE_SUPPORTED` 改为 `true`

四项齐备后，`isWechatLoginAvailable()` 自动翻真，入口随之出现，**业务代码零改动**。
若决定 v1 永久不做原生微信登录，直接卸载插件并删除 `wechat.ts` / wxapi / plist 段落即可，
Web 端不受影响。

## 四、踩坑记录

1. **cap sync 的 safe-delete 守卫**：本机 `cap sync` 会先整目录删除
   `android/capacitor-cordova-android-plugins/`、`ios/App/App/public/` 再重建，
   被 WorkBuddy 的删除守卫以 `ETIMEDOUT` 拦截/中断，**iOS 侧还把 public 删到只剩
   两个 0 字节占位文件**。绕法：先把目标目录 `mv` 到系统临时目录（非删除、不触发守卫），
   再跑 `cap sync` 让其完整重建。两处目录均为 gitignore 的生成物，移动无风险。
   你自己的终端里没有这个限制。
2. **插件 `implementation` 不透出微信 SDK 类型** → app 模块继承插件基类会编译失败，
   必须在 `android/app/build.gradle` 显式声明同版本微信 SDK（见上文）。
3. **APK 体积 +3.27 MB** 是接微信 SDK 的固定代价（5.05 → 8.32 MB，+65%）。
   如果将来觉得不可接受，可以只在需要微信能力的构建渠道里启用插件。

## 五、供应链提示（需要知情）

- 插件 `@capgo/capacitor-wechat`：MPL-2.0，活跃维护（v8.0.52，2026-10 发布），无已知漏洞。
- 但其 iOS 依赖 `WechatOpenSDK` 来自 **第三方 SPM 镜像** `github.com/yanyin1986/WechatOpenSDK`
  （腾讯官方不通过 SPM 分发微信 SDK）。认证类 SDK 走第三方镜像属于供应链风险，
  上线前建议：核对镜像 tag 与官方 SDK 版本一致，或在 Mac 上改用官方 XCFramework 手动集成。
