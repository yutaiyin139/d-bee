### 1.3 🔴🔴 核心问题：登记是否以「已签署的模型服务协议」为前置？

**结论：不被第三方盖章协议阻塞的概率约 75%，但必须电话确认。**

**支持「不阻塞」的三条论证：**

**(a) 文义论证（🟢 强，我认为这是最有力的一条）**
扬州发改委对登记附件的原文要求是：「模型服务协议（包含**个人信息保护、内容安全、用户责任**等条款）」。
→ 「**用户责任**」这一条款类型**只可能出现在面向终端用户的协议里**。与 DeepSeek / 阿里云签的 **API 采购合同不会约定「用户责任」**（采购合同写的是 SLA、单价、数据出境、保密、责任上限）。
→ 因此「模型服务协议」在此处的正确读法是「**（我方就）模型（所提供的）服务的协议**」，而非「模型（供应商）的服务协议」。
→ **交叉印证**：君合律所直接写作「模型服务协议（**用户协议及隐私政策**）」，用括号把两者等同；腾讯云写作「产品服务协议（**产品使用协议、隐私保护政策**）」；扬州在同一份文件里明写「**可以是用户协议或隐私政策**」。四个来源方向完全一致。

**(b) 官方口径论证（🟠 中高）**
扬州发改委原文那句「可以是用户协议或隐私政策」，**严格来说出现在「备案材料」的附件说明段（第 b 点），不是「登记材料」段**。
→ 但登记的附件与备案的附件**同名同性质**（都叫「模型服务协议」），且登记对它的条款要求**更少**（备案要满足备案表「服务与安全规范-服务」1-6 点，登记只要求 3 类条款）。
→ **举重以明轻**：要求更高的备案都允许用用户协议/隐私政策充当，要求更低的登记没有理由反而必须提供供应商盖章合同。
→ 🔴 **但这是类推推理，不是北京市明文。证据强度标 🟠。**

**(c) 实务反证（🟠 中）**
北京市 11-19 一批登记 106 款，其中包含大量**中小主体**（如「北京妙妙未来科技有限公司」「北京吉弛科技有限公司」「万境千寻(北京)科技有限公司」「北京英动青年科技有限公司」）。
→ 若登记必须提交**大模型厂商双方盖章的合作协议**，这些中小主体在 2 个月内几乎不可能拿到 DeepSeek/阿里云/字节的盖章合同（我方既有文档 `docs/iOS上线收费-可执行路径-2026-11-21.md:176` 已判定该协议「**不受你控制，可能 > 6 个月**」）。
→ 106 款同批通过 ⇒ **反证登记不以供应商盖章协议为前置**。

**支持「可能阻塞」的反向风险（🟡 须防）：**
- CSDN 一篇实操文写「登记也要交模型服务协议。很多以为『登记很简单』的人，恰恰在这一份协议上被卡——因为它**必须对应你真实在跑的产品**，不是从网上复制一份通用用户协议就能过关」→ 风险不在「是否要供应商盖章」，而在「**我方用户协议是否真的写了 AI 相关条款**」。

### 2.1 法规原文（🟢 一手来源，逐字核对：深圳政府在线 `sz.gov.cn/cn/xxgk/zfxxgj/zcfg/content/post_11289199.html`）

**《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》**（2018-11-30 施行）

> **第二条** 本规定所称具有舆论属性或社会动员能力的互联网信息服务，包括下列情形：
> （一）开办论坛、博客、微博客、聊天室、通讯群组、公众账号、短视频、网络直播、信息分享、**小程序**等信息服务**或者附设相应功能**；
> （二）开办**提供公众舆论表达渠道**或者具有发动社会公众从事特定活动能力的**其他互联网信息服务**。
>
> **第三条** 互联网信息服务提供者具有下列情形之一的，应当依照本规定**自行开展安全评估**，并对评估结果负责：
> （一）具有舆论属性或社会动员能力的信息服务**上线**，或者信息服务**增设相关功能**的；
> （二）使用新技术新应用，使信息服务的**功能属性、技术实现方式、基础资源配置等发生重大变更**，导致舆论属性或者社会动员能力发生重大变化的；
> （三）用户规模显著增加……；（四）发生违法有害信息传播扩散……；（五）地市级以上网信部门或者公安机关**书面通知**需要进行安全评估的其他情形。
>
> **第四条** 可以**自行实施**安全评估，也可以委托第三方安全评估机构实施。
>
> **第五条** 应当对信息服务和新技术新应用的**合法性**、落实法律法规规章和标准规定的**安全措施的有效性**、**防控安全风险的有效性**等情况进行全面评估，并**重点评估下列内容**：（一）安全管理负责人/信息审核人员/安全管理机构；（二）**用户真实身份核验以及注册信息留存措施**；（三）**日志信息留存**（账号、操作时间、操作类型、网络源地址和目标地址、网络源端口、客户端硬件特征）以及**用户发布信息记录的留存措施**；（四）账号/昵称/简介等违法有害信息的防范处置与记录保存；（五）**个人信息保护**以及防范违法有害信息传播扩散、社会动员功能失控风险的**技术措施**；（六）**投诉举报制度**、公布方式、及时受理处理情况；（七）为**网信部门**提供技术、数据支持和协助的工作机制；（八）为**公安机关、国家安全机关**提供技术、数据支持和协助的工作机制。
>
> **第六条** ……应当形成**安全评估报告**。报告应当包括：（一）互联网信息服务的**功能、服务范围、软硬件设施、部署位置**等基本情况和**相关证照获取情况**；（二）**安全管理制度和技术措施落实情况及风险防控效果**；（三）**安全评估结论**；（四）其他应当说明的相关情况。
>
> **第七条** 互联网信息服务提供者应当将安全评估报告**通过全国互联网安全管理服务平台提交所在地地市级以上网信部门和公安机关**。
> 具有本规定**第三条第一项、第二项**情形的，应当在信息服务、新技术新应用**上线或者功能增设前**提交安全评估报告；具有第三条**第三、四、五项**情形的，应当自相关情形**发生之日起 30 个工作日内**提交。
>
> **第八条** 地市级以上网信部门和公安机关应当依据各自职责对安全评估报告进行**书面审查**。发现报告内容、项目缺失，或评估方法明显不当的，**责令限期重新评估**；内容不清的，可责令补充说明。

**《生成式人工智能服务管理暂行办法》第17条**：「提供具有舆论属性或者社会动员能力的生成式人工智能服务的，应当按照国家有关规定**开展安全评估**，并按照《互联网信息服务算法推荐管理规定》履行**算法备案**和变更、注销备案手续。」

### 2.3 🔴 适用性判定：**应当做，且现在就做**（我与 team-lead 的倾向一致，但给出独立理由）

| 路径 | 事实 | 判定 |

| **第2条(一)** | D-Bee 有**微信小程序**（APPID `wxb7c7122de9c3ab1f`，备案管局审核中），且 App/Web 内**附设 AI 问答功能** | 🟢 **直接命中**——「小程序等信息服务**或者附设相应功能**」，措辞上「附设相应功能」是专为这种情况写的 |

**为什么「D-Bee 是工具型饮食记录、不具舆论属性」这个反向豁免论证无效（🔴 这是我要强调的重点）：**

1. **判定权不在企业**。「舆论属性」的认定是监管的裁量权，不是企业的自我声明。企业自行判定「我不具备」而不做评估，一旦监管认定具备，就是**「未按规定开展安全评估」**——这正是三案的处罚事由本身。
2. **已有三案在先，且事实模式比 D-Bee 更「工具」**。江苏案的主体是「API 中转站」，天津案是「AI 创作平台」——**都不是内容社区、都不是社交产品**，都是工具型服务，仍然被认定落入第2条。律所口径「对话、问答、聊天类服务**天然具备**舆论属性」正是对这三案的归纳。
3. **我方已在公安备案主体表单里如实勾选「本企业是否利用生成式人工智能技术向境内公众提供服务 = 是」**（既有文档 `docs/公安联网备案-四类申请材料清单与填报值-2026-11-20.md:275` 已定此口径，并明确「即使调用的是第三方已备案大模型 API，面向公众提供生成式 AI 服务这一事实成立」）。→ **若在安评上转而主张「不具舆论属性」，会与我方自己的申报形成口径矛盾**，这种矛盾在监管眼里比「功能有风险」更糟。
4. **成本-收益极度不对称**：
   - 做的成本 = 复用已盖章《算法安全自评估报告》改写 + 补 §2.4 章节 + 盖公章 + 平台上传 ≈ **1-2 个工作日**，**零外部依赖**（不需要任何第三方配合）
   - 不做的代价 = 四川案/天津案都是「**责令下线**」（对已上线 Web + 即将上架的 iOS 是致命打击）；江苏案是「警告 + 责令改正 + **从严处理责任人**」（直指法定代表人）；且会**连带拖累 12-06 的公安备案审核**（同一属地公安机关、同一账号、同一批次）
5. **第4条明文允许「自行实施」**，不强制第三方机构 → 无采购成本、无排期。珠海公安办事指南确认：材料只要「**自评估报告**（电子原件，必要，影印件加盖公章）」；「检测报告（第三方评估，**非必要**，必须上传时才需）」→ **我方走企业自评估，无需检测报告**。

### 2.5 🔴 第7条时限对「已上线」状态如何适用（最需要谨慎的一节）

**事实**：D-Bee Web（`d-bee.cn`）**已上线**，AI 问答功能**已可用** → 落入第3条**第(一)项**「具有舆论属性或社会动员能力的信息服务**上线**」→ 第7条要求「**在信息服务、新技术新应用上线或者功能增设前提交**」→ **法定时点已过，属逾期状态**。

**逾期不消灭义务，只改变处置姿态。** 三条可选路径，按推荐度排序：

| 路径 | 做法 | 评价 |
| --- | --- | --- |
| 🟢 **A（强烈推荐）** | **抓住第3条第(二)项的新触发点**：iOS 端即将上架（新客户端 = 「基础资源配置重大变更」）、支付宝原生插件在开发、小程序待发布、Android vc32 在制 —— 这些都是「**信息服务增设相关功能**」或「**使用新技术新应用使功能属性/技术实现方式/基础资源配置发生重大变更**」→ 触发**全新的**评估义务，按第(一)(二)项仍是「**上线或功能增设前提交**」→ **在 iOS 提审前提交，正好落在合法时点上，无需追认历史逾期** | **最干净**。既履行了义务，又不主动把自己钉在「逾期」的叙事里。且 iOS 上架本身就需要「已完成安全评估证明」（既有文档 §2-5 记录 Apple 2026-11-16 起对中国大陆分发新增该必填项）→ **一份报告同时满足公安 + 苹果两个要求** |
| 🟠 B | 现在就补做覆盖**现有 Web + APP** 的评估，在报告第七部分**如实写明服务上线时间与本次评估触发情形** | **诚实但暴露逾期**。可作为 A 的补充（一份报告同时覆盖现状 + 新增功能），🔴 **我建议采用 A+B 合体**：报告覆盖现有服务，触发情形写「新增 iOS 客户端及小程序功能增设」，并在「其他应当说明的情况」如实写明 Web 端上线时间 |
| 🔴 **C（禁止）** | 隐瞒上线时间，或写「服务尚未上线」 | **虚假申报**。第8条赋予监管「责令限期重新评估」权，第9条可「现场检查」，一旦发现填报与实际不符，性质从「程序逾期」升级为「**提供虚假材料**」，风险量级完全不同 |

**关于「30 个工作日」**：该期限**只适用于第3条第(三)(四)(五)项**（用户规模显著增加 / 发生违法有害信息传播扩散 / 网信或公安书面通知）。→ **D-Bee 目前不落入这三项**（用户规模未显著增加、未发生违法信息扩散、未收到书面通知）。

## 三、调研 3：《人工智能拟人化互动服务管理暂行办法》适用性

### 3.1 法规原文（🟢 一手来源：**中国政府网公报** `gov.cn/gongbao/2026/issue_12806/202606/content_7072472.html`）

> **国家网信办、国家发展改革委、工业和信息化部、公安部、市场监管总局令第21号**
> 2026年2月2日国家网信办2026年第3次室务会会议审议通过，2026年4月10日公布，**自2026年7月15日起施行**
>
> **第二条** 利用人工智能技术，向中华人民共和国境内公众提供**模拟自然人人格特征、思维模式和沟通风格的持续性的情感互动服务**（以下简称拟人化互动服务），适用本办法。
> 前款规定的情感互动服务包括通过文字、图片、音频、视频等形式，提供的**情感照护、陪伴、支持**等互动服务。
> **提供智能客服、知识问答、工作助手、学习教育、科学研究等服务，不涉及持续性的情感互动的，不适用本办法。**

**交叉验证**：国家网信办《生成式人工智能(包含拟人化互动)服务备案常见问题答疑汇总》（2026-11-09，`beian.cac.gov.cn` 官网原文）**Q4** 逐字复述第2条作为「人工智能拟人化互动服务开展安全评估的适用范围」→ 官方自己就是把第2条当作**适用范围的唯一判定标准**。

**若适用，将连带的重义务（用于说明「判定为不适用」的价值）**：第12条（须采集用户年龄 + **监护人或紧急联系人**）、第13条（**极端情绪识别与干预**，自残自杀情境须联络紧急联系人）、第14条（**未成年人模式** + 切换/现实提醒/时长限制/监护人接收风险提醒/屏蔽特定角色/限制充值）、第16条（**交互数据不得向第三方提供** + 须提供聊天记录复制/删除 + 敏感个人信息不得用于训练除非单独同意）、第17条（不满14周岁个人信息**合规审计**）、第18条（**每连续使用 2 小时须提醒**）、第19条（不得阻碍用户退出）、第22条（**上线即须开展安全评估并向省级网信部门提交报告**）、第25条（**应用商店须核验安评与备案，否则不予上架**）。
→ 🔴 特别注意第25条：一旦被认定为拟人化互动服务，**苹果/安卓商店会主动核验**，这是「认定错误」最快暴露的路径。

### 3.2 结论：🟢 **不适用**（证据强度：强）

**判定标准（第2条第3款排除条款）= 两个要件同时满足：**
1. 属于「智能客服、知识问答、工作助手、学习教育、科学研究等**工具型服务**」
2. **不涉及持续性的情感互动**

**要件 1：D-Bee「问问小蜜」是「知识问答 / 工作助手」型工具服务 → ✅ 满足**
- 功能实质：就用户的饮食问题，结合其当日营养数据，生成不超过 120 字的中文饮食建议（`server/lib/llm.mjs:155`）
- 无内容发布、无社交、无公开分发、无用户间互动 → 是**个人使用的工具**，不是「渠道」或「平台」
- 北京 11-19 登记名单中同类形态：「智能客服」（优酷）、「花小猪智能客服」、「豆瓣智能助手」、「AI小博士」（学科网，教育问答）、「豆可AI英语」——**这些正是第2条第3款明文列举的排除类型，它们走的是登记，不是拟人化备案**

**要件 2：不涉及持续性的情感互动 → ✅ 满足（四要点全部为「否」，逐点代码实测）**
