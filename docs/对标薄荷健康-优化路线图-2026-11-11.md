## 〇、一页结论

**战略认同，战术重心要改。**「不打长板、打伤口，做薄荷用户流失后的下一站」这个判断成立，且比堆功能更适合一人团队。但对照代码后发现：

| 判断 | 结论 |
| --- | --- |
| 文件里「最高优先级待补」的功能 | **大部分已实现，且更完整**（BMR/TDEE、体重曲线、Streak、MET 运动库、7/30 天报告、邀请、分享卡） |
| 当前最大瓶颈 | **不是功能，是上不了架**：软著（30–60 工作日，全局最长边）、App/小程序备案、Mac 签名、mini 体验版重传、云库实例未停 |
| 最像「薄荷伤口」的自有风险 | 🔴 **口径漂移**：代码免费额度 `3+2`，`docs/` 多处仍写「每天 10 次 AI」，白皮书写「1 分钟 3 次」→ 这就是我们自己版本的「会员货不对板」 |
| 最高 ROI 的动作 | **零生产风险的「清口径 + 立承诺」**（Wave 1），成本低于任何新功能，直接服务「更干净、更可信」 |
| 功能类真正值得做的 | 只有三项：记录可编辑 + 回收站、额度/复用显性化、提醒默认关；UGC 食物库是长期项，须等用户量 |

**一句话执行顺序**：收口未闭环 → 清口径立信任 → 通上架 → 才谈记录体验 → 最后才是护城河。

| **退款无门** | 法务 §六 文案齐（取消续订/退款/客服邮箱），但执行靠人工 SQL，微信/支付宝无自动退款回收 | 补客服侧**只读查询 + 工单留痕**工具（先不碰资损口），给明确响应时限 |
| **社区商业化过重** | 无内容流 / 无 KOL / 无评论区，只有邀请 + 脱敏榜单 | **保持**：不要为了「对标」去建社区；轻社交也要先过隐私评估 |

**文件没写、但更值得打的两张牌**：

1. **数据可携带 / 可删除** —— 已有导出（`src/lib/api.ts:572` 含 `ai_usage` 等全量导出）与 0045 真删号。做成「随时导出、随时删光」的显式入口与对外承诺，是薄荷很难跟的差异化。

### Wave 2 · 上架闸门（优先级高于任何新功能）

严格按《四端序列》§五执行，不另立方案：

1. **梯队 0/A**：补推 commit → 启动长周期资质（软著加急 / 新商户号 / 支付宝企业应用 / 催 4 项备案）→ `npm run build:weapp` **不带变量**重构建 → 用户重传体验版（新版本号 + 重设）→ **体验版** 6 项验收 + 包体积复测 → 启动云库停用 T+7 计时。
2. **梯队 B**：备案批复 → 虚拟支付签约 / 三档道具 / 消息推送开启 → mini 提审；App 备案 + 软著 → Android 上架。
3. **iOS 短路径**：Xcode≥26 → `VITE_NATIVE_ENDPOINT=https://d-bee.cn npm run build:native`（🔴 禁 `npm run build`）→ 三探针 → `cap sync ios` → 选 `DEVELOPMENT_TEAM` → Archive 上传 TestFlight。
4. **梯队 C（需拍板）**：vc17 分发渠道、`LEGAL_UPDATED`、网关收紧、凭据轮换、仓库转 private、云库停用、双开关。
5. 🚫 **梯队 D 绝不提前**：开任一收款开关、上生产 0046、部署 `xpay/apppay/iap.mjs`、补支付 env、mini 正式发版、Android 上架。

> 传播口径建议（对齐战略）：**「不用下载，扫码 30 秒记完这餐」**——mini 正式版发布后才可用，备案前不得对外宣称「已上线」。

## 八、维护与纪律

- 每完成一项，更新本文件对应状态 + 追加当日日志（`.workbuddy/memory/YYYY-MM-DD.md`）；生产项必须附实测证据。
- 改 `packages/shared/src` → `cd packages/shared && npm run build`；四端文案改动 → 同步官网 `check-facts.mjs` 快照。
- `npm test` 跑完核对 `Test Files` 数 == `ls tools/*.test.ts` 文件数（vite 强制串行，并行会静默丢文件＝假绿）；新增/放宽护栏必须红验证，一个 `it()` 只一条断言、断言在 `stripComments()` 后的代码上做。
- 原生包禁用 `npm run build`；`build:web` 会删 `dist/legal/`；native 与 web 共用 `dist/`，部署 web 前重跑 `npm run build` 并比对入口 js 文件名。
- 同一任务只在一个会话执行；决策前先征求用户同意；一次只推一项，不批量实施。
