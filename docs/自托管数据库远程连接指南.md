> 目标：从本地（你的电脑）连接到服务器 `150.158.51.106` 上的自托管 PostgreSQL 库 `dbee`，用于查看/管理数据。

## 一、连接信息

> ⚠️ 密码不写入本文档（会进 git）。真实密码存本地 `.env`（已 gitignore）或服务器
> `systemd EnvironmentFile`，本文档只用占位符。

| 项 | 值 |

| 主机 | `150.158.51.106`（SSH 隧道方式下本地连 `localhost`） |
| 端口 | `5432` |

## 二、连接方式（推荐：SSH 隧道，零公网暴露）

数据库当前**只监听 `127.0.0.1`，不对公网开放**，这是有意为之（避免真实健康数据暴露公网）。通过 SSH 隧道把本地端口转发过去：

```bash
ssh -L 5432:127.0.0.1:5432 ubuntu@150.158.51.106 -N
# 输入 SSH 密码（存本地，勿写入文档）：$SSH_PWD
```

然后在本机数据库客户端（DBeaver / Navicat / psql）里连：

- 主机：`localhost`（或 `127.0.0.1`）
- 端口：`5432`
- 数据库：`dbee`
- 用户：`dbee_app`
- 密码：`$DBEE_PWD`（见本地 `.env`）

### DBeaver 示例
1. 新建连接 → PostgreSQL
2. Host: `127.0.0.1`，Port: `5432`
3. Database: `dbee`，Username: `dbee_app`，Password: 见本地 `.env`
4. 先开 SSH 隧道（保持上面 ssh 命令运行），再点测试连接

## 三、说明

- **为什么走隧道**：服务器 PostgreSQL 的 `listen_addresses=localhost`，且 `pg_hba.conf` 无外网规则。走隧道无需改动任何服务器配置，最安全。
- **密码已重置**：`dbee_app` 原密码未知，已重置为强随机密码（存本地 `.env`，不落文档）。
- **权限已配置**：`dbee_app` 已授予全 17 表的 SELECT/INSERT/UPDATE/DELETE、序列 USAGE、函数 EXECUTE，并默认对未来新表也授权。
- **若确需直接 TCP 连公网**（不推荐）：需改 `listen_addresses='*'` + 在 `pg_hba.conf` 加外网规则 + 设防火墙白名单，暴露面较大，仅在确有需要时再操作。

## 四、后续（切换数据库的真正前置）

前端 App 走的是 `cloud.ts` 的 API（REST + LLM + auth），不是直连 PG。要完成「前端切换到自托管」，需先搭「生产化四件套」中的 REST 兼容端点 + auth/JWT 网关（详见 `docs/自托管生产化四件套.md`）。本指南只解决「你个人远程连库管理」，不涉及前端切换。
