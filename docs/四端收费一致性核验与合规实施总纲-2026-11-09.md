## 〇、结论先行（决策者只读这 6 条）

1. **「4 端完全一致」不能按字面理解。** 业务代码实际只有 **2 套**（Web/Android/iOS 经 Capacitor 共用 `src/`，mini 独立 `mini/src/`，公共层 `packages/shared`）；支付通道 **3 套**，且按平台法规**必然分叉**：iOS 强制 StoreKit IAP（Apple 3.1.1）、小程序虚拟商品强制微信虚拟支付（小程序运营规范）、Android 可自选渠道、Web 受广告法与渠道约束不得引导到不售卖的小程序。
   → **正确目标 = 权益 / 定价 / 口径 / 数据面 / 删号 / 账号体系完全一致；支付链路按平台分别合规，不强求相同。**
2. **当前只有 iOS 与 mini 具备「代码级收费链路」；两端都还没上线收费。** Web 零收款（设计如此，合规）、Android 支付 adapter 是**占位死代码**（点击会报错）。四端真实收费能力见 §1.2 矩阵。
3. **最硬的三道闸门都不在代码里**：① 备案链（5 项，4 项在管局审核中）② 平台侧商品/商户配置（ASC 3 商品、微信道具 3 档 + 二级商户进件）③ 服务端部署（0046 未上生产、网关 `xpay.mjs`/`iap.mjs` 未部署、`APPLE_*`/`XPAY_*` env 全缺）。
4. 🔴 **已被 11-09 新指令推翻（见顶部横幅）**：`11-06 已决「ICP 经营许可暂不办」` 的前提「暂不引入在线支付」已失效。《互联网信息服务管理办法》第 11 条明文「**非经营性互联网信息服务提供者不得从事有偿服务**」→ ICP 经营许可证（B25）是**全端收费的总闸门与最长杆**，应**立即**向属地通管局书面确认并启动办证，而不是等上线再补。详见新详表 §3.1。
5. **首发顺序仍是 mini → iOS → Android → Web，但性质变了**：mini 依然是第一笔收入最短路径（不依赖 ICP 经营许可证/软著、代码 100% 就绪）；**Android 不是「不做」，而是 (A) 实装**，其长周期资质（办证/软著/开放平台 AppID/商户号）**现在就并行启动**；Web 改为「办妥 ICP 经营许可证后可独立收款」，列第 6 阶段。详见新详表 §五、§六。
6. **一致性护栏 18 道 / 731 项全是源码静态扫描**，平台侧配置、迁移是否上生产、网关是否部署、运行时结算链路**零自动断言**（§1.4）。这 9 项人肉保证就是后续最容易出事的地方，必须补进验收清单。

## 六、执行铁律（引用项目纪律，勿绕过）

- 🔴🔴 `deploy-gateway.sh` = 全站永久锁死级地雷（缺 `IDENT_PEPPER` 即重置），改网关/加 env 一律走手术式脚本。
- 🔴🔴 铁律 #13：「已完成」必须附**生产侧实测证据**，本地绿 ≠ 线上绿。
- 🔴 原生包禁用 `npm run build`（白屏）；`build:web` 会删 `dist/legal/`；native 与 web 共用 `dist/`，部署 Web 前必须重跑 `npm run build` 并比对入口 js 文件名。
- 🔴 nginx reload 有优雅退出窗口 → `sleep 8` + 重试 3 次；验收一律打 `https://d-bee.cn/`。
- 🔴 小程序验收以**体验版**为准（真机调试会注入 Web API 掩盖 JSCore 缺口）。
- 🔴 产物中文形态分工具链：mini（Taro/webpack）= ASCII `\uXXXX`；Web（vite）= UTF-8 直存。
- 🔴 新增护栏 / 放宽快照基线**必须红验证**；一个 `it()` 只一条断言；断言作用于 `stripComments()` 后的代码。
- 🔴 改 `packages/shared/src` 后必须 `cd packages/shared && npm run build`。
- 🔴 改任何权益函数：SECURITY DEFINER + 入参白名单 + REVOKE authenticated 的写权限。
