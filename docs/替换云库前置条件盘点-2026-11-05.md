## 〇、一句话结论

**web 端早已在自建库，「替换云库」实际只剩三端（iOS / Android / mini）+ 一条微信登录链路。**

- 数据面权威源 = 服务器自建 PostgreSQL `dbee`（`/.cloud/healthz` 实测 `database:"dbee"`）。
- web 已切（endpoint 取 `window.location.origin`）；仍连云库的是 **mini（默认 cloud）+ iOS/Android 内测包**。
- **用户已拍板「自建库不清除、数据都是测试数据」** → 切换**不做数据迁移**，工程复杂度从「迁移问题」降为「补一条微信登录链路 + 外部域名就绪」。
- 唯一真正的硬阻断是**外部域名链**（ICP 下证 → DNS → HTTPS → 微信白名单），代码侧现在就能提前写完。

实测 `grep -rn "login-wechat" server/` = **0 命中**，缺口确认仍在。三件：

| A2 | ✅ **已完成**：`ident_kind` 扩 `wechat` | `db/migrations/0043-ident-kind-wechat.sql`：DROP+ADD CHECK 扩到 `('phone','email','wechat')`，幂等，含 0034 追踪表登记。**尚未在服务器执行**（随切换执行序 §五 步骤 3） | 已完成 |
| A3 | ✅ **已完成**：微信凭据槽位 | `config.mjs` 新增 `parseWechatSecrets()`（支持多组 `WECHAT_MINI_SECRETS="appid=secret,..."` + 单组 `WECHAT_APPID`/`WECHAT_SECRET` 简写）、`wechatApiBase`、`wechatTimeoutMs`；`gateway.env.template` 补占位；未配凭据时 `warnings()` 提示。🔴 **AppSecret 实际值待用户提供**，部署时进 `.secrets.local` | 已完成 |

> 🔴 **身份模型是核心难点 → 已解**：云库 mini 用户 uid = `wx:<openid>`，自建库 `owner_id` = 19 位纯数字串。
> **决策（11-05）**：wechat 用户的 `owner_id` **直接采用 `wx:<openid>` 形态**（`ensureUser` 加 `fixedOwnerId` 参数，
> 不走 `newOwnerId()` 发号）。实证依据：全库 `owner_id` 列均为 `text`、无长度/CHECK/uuid 约束（0030-schema.sql
> 逐表核对）；`auth.uid() RETURNS text`；RLS 与 26 个 SECURITY DEFINER 函数对 owner_id 形态无感 → **零改动兼容**。
> 身份哈希口径：`ident_kind='wechat'`；`ident_value=openid`（裸串）；`ident_hash=HMAC('wechat:'+openid, PEPPER)`；
> `ident_masked='wx****'+openid 后 4 位`（满足 `LIKE '%*%'` 约束）。
> 好消息（回迁清单已验）：mini 用的 **22 个 RPC + 11 张表 + RLS 全已在自建侧**，SDK 前缀 `/.cloud` 与网关**完全对齐**，schema 不用新建。
>
> **自测**：`tools/wechat-login-selftest.mjs`（66 项断言，内存版 app_users + 伪造 jscode2session + 裸 HTTP 报文验证
> + 真实 SDK `createWorkBuddyCloud` 亲自登录，全过）；回归 `gateway-selftest.mjs` 301 项全过、vitest 10 files/190 tests 全过。
> **安全纪律已内建**：AppSecret 只进微信接口 URL query、绝不落日志/响应；`session_key` 拿到即弃；未知 appid 直接
> 503 不外呼（防 SSRF）；微信错误码分类映射（40029/40163/41008→401 重新 wx.login；45011/45009/-1→503；配置错→503
> 不暴露原因）；IP 限流 `WX_LIMIT_PER_IP=60`。
