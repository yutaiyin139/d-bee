# 积分双扣缺陷诊断与 FEFO 修复（2026-11-17）

> 触发：用户用 18611114399 登录后反馈「积分不太准确」。本文是生产只读取证 + 代码级根因 + 四端修复的完整留证。

## 一、结论速览

- **确系 bug，且是双重扣减**：用户积分被扣两次，不是「口径体感差」。
- **根因（两个缺陷叠加）**：
  1. `expire_stale_honey()` 按**整笔**冲正过期积分，没扣除已被消费的部分；
  2. `honey_balance()` 的 `FILTER` 口径同时「排除已过期正流水」又「纳入 expire 冲正流水」，二次扣减。
- **生产实证**（账户 18611114399 → owner `179325...`，仅只读 SELECT）：
  - 当前 FILTER 口径 `balance = 0`（用户看到的值）
  - 朴素 `SUM(amount) = -66`（我上一轮误判的「修复方案」，实测仍是 0，**已证伪**）
  - **FEFO 口径 `balance = 34`（应有值）**
- **影响面**：生产库 4 笔 expire 冲正、涉及 4 个 owner（含 1 个微信 openid 账户），全部是新手 150 分整笔冲正，4/4 命中「疑似多扣」。

## 二、账户轨迹还原（owner 179325...，11 条流水）

| 时间 | 事件 | 应有余额 | 系统余额 |
|---|---|---|---|
| 10-29 | 新手奖励 +150（11-05 到期） | 150 | 150 |
| 11-02 | 打卡 +7、兑换 −100 | 57 | 57 |
| 11-05 | 新手到期：应仅 50 分作废（100 已花） | 7 | 57 |
| 11-09 | 系统按整笔冲正 −150（多扣 100） | 7 | −93 |
| 11-17 | 期间累计打卡 +27 | **34** | −66 → 截断 0 |

关键：新手 150 分里 100 已在 11-02 被兑换花掉，11-05 到期时真正该作废的只有剩余的 50；系统却按整笔 150 冲正，把已花的 100 又扣了一次。

## 三、根因代码定位

1. **数据源头** `db/functions.sql:252` `expire_stale_honey()`：
   ```sql
   FOR r IN SELECT id, amount FROM honey_ledger
     WHERE amount > 0 AND expires_at <= now() AND NOT EXISTS (...expire...) LOOP
     INSERT INTO honey_ledger (amount, reason, ref_id) VALUES (-r.amount, 'expire', 'exp:' || r.id);
   ```
   `-r.amount` 是整笔，未扣除该笔已被 redeem 消费的部分（消费是匿名池，旧实现无法归属）。
2. **查询层** `db/migrations/0040` `honey_balance()`：
   ```sql
   GREATEST(0, SUM(amount) FILTER (WHERE amount<0 OR expires_at IS NULL OR expires_at>now()))
   ```
   FILTER 排除过期正流水（+150 当它没发过），纳入全部负流水（expire −150 照扣）→ 双扣。
3. **同源扩散**：`redeem_honey`(functions.sql:555) 检查口径、两端 `getHoneyBalance()` RPC 失败回退循环（`src/lib/api.ts`、`mini/src/lib/api.ts`）都是同一套逻辑。
4. **放大项**：mini 积分页 `mini/src/pages/invite/invite.tsx` 只有 `useEffect([])`，从兑换弹窗返回不刷新余额（打卡页/我的页都有 `useDidShow`，唯独积分页缺失）。

## 四、修复方案：FEFO（先到期先消费）

积分同质，但过期按批次。消费优先冲抵最早到期的批次 → 已花部分不再随整笔过期重复作废；物理冲正流水 `reason='expire'` 在查询期一律忽略。

- **四端单一真源**：`packages/shared/src/honeyLedger.ts` 新增 `computeHoneyBalance()` 纯函数（FEFO）。
  - `src/lib/honeyLedger.ts` re-export（对齐 numfmt 惯例）。
  - 两端 `getHoneyBalance()` 回退路径改调该函数，且 `select` 增加 `reason` 字段（忽略 expire 用）。
- **服务端 RPC 镜像**：`db/migrations/0054-honey-balance-fefo.sql` 用 plpgsql 重写 `honey_balance()` 为 FEFO，与 shared 纯函数逐句同口径；含 schema_migrations 追踪、幂等。
- **mini 刷新**：`mini/src/pages/invite/invite.tsx` 补 `useDidShow` 刷新余额与流水。
- **历史数据**：**无需订正**。旧的错误 expire 冲正流水被 FEFO 忽略，天然不参与余额；`expire_stale_honey()` 保留原样（其写入被忽略，对未来无副作用）。
