### 1. 🔴🔴 生产网关**完全没有 apppay 代码**（= 收费链头号阻塞）


👉 **含义（三条，都很重要）**：
- 端点 404 **不是** env 没配（env 没配应该是 503 `notConfigured`），而是**路由根本不存在** → 生产跑的是 11-17 22:45 那次启动的旧代码（`ActiveEnterTimestamp=Tue 2026-11-17 22:45:18 CST`）。

- 🔴 **印证 11-20 文档 B3 的警告**：「生产 `config.mjs` 不解析任何支付键 → **光填 env 完全无效**，且半配拦截也失效 = 裸奔」。本轮实测确认这句是真的。

## 四、为什么「先打通支付宝单渠道」是最优解

```ts
  ? { wechat: isWechatPayAvailable(), alipay: isAlipayAvailable() }
```

| --- | --- | --- |
| 时长 | 🟢 **约 3–5 工作日**（审核约 1 工作日） | 🔴 **约 2 周**（¥300 认证 7 工作日 + 创建审核 1–7 工作日） |

- 🔴🔴 **三文件必须同批**（`apppay.mjs` + `config.mjs` + `app.mjs`）；**绝不整搬 `auth.mjs`**（断 werun 微信运动）。
- 🔴 **原生包禁用 `npm run build`**（白屏）；native/web **共用 `dist/`** 且 `build:web` 删 `dist/legal/` → 部署 Web 前必重跑并比对入口 js 名。
- 🔴 **铁律 #13**：「已完成」必附**生产侧实测证据**（本地绿 ≠ 线上绿）；`systemctl restart`/`nginx reload` 后**立即验证 = 假红** → `sleep 8` + 重试 3 次。
- 🔴 **凭据只进 `gateway.env`/`.secrets.local`**，不入库、不进日志、不下发前端；基线只登记键名与有无。
- 🔴 **护栏四铁律**：一 `it()` 一断言 / 匹配实际使用 / `stripComments()` 后做 / 两端同源须 `every()`；**新增与放宽必红验证**，红验证前必先跑**无变异对照组**。
- 🔴 **同一任务只能有一个执行会话**（44 项未提交中含另一会话的 vc32/支付宝在制品，我不越界提交）。
- 🔴 **删文件先给原因 + 影响评估、等明确确认**（「全部允许」不豁免）。
- 🔴 **存在性判定用精确等值，不用 `LIKE '前缀%'`**（本轮 `settle_app%` 误匹配 `settle_apple_purchase` 的教训）。
- 🔴 **SSH 走 `ubuntu@$DBEE_HOST:22`**，`DBEE_PORT=5432` 是 PG 端口，**别拿它连 SSH**。
