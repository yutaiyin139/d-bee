## 〇、设计判断（先说三句结论）

1. **不抄薄荷的「方案彩页」**。图 1 那页把 BMR、燃脂心率、BMI 色带、进度、达成日、营养师方案、0.1 元加赠体脂秤堆在一屏，是「转化页」不是「工具页」。自律蜜蜂的定位是干净、可信、不推销，所以本页做成**一页三区**：`目标概览 → 进度 → 这些数字怎么来的`，主操作一屏能到，无 CTA 广告位。
2. **三目标用同一个组件，只切方向语义**。`lose / keep / gain` 在 `src/lib/nutrition.ts:21-25` 已有 `GOAL_LABELS`，`Onboarding.tsx:224-241` 已有三选一 `.option` 卡。本页沿用同一套标签与顺序，**不新增第四种目标、不改名**，避免又一次口径漂移。
3. **对上一版 B1 做一处收敛**：原先写的「BMI 四档色带」改为**一行参考值 + 中性档位文字 + 解释入口**。红黄绿四档带会把参考值误读成医学判断，与 `legal.ts:384`「不提供医疗诊断 / 营养处方」的品牌边界不一致；一行文字既讲清楚了，也不越界。

## 四、三目标态规格（核心差异表）

三个方向**共用同一个 `GoalProgress` 组件**，由 `goal: 'lose' | 'keep' | 'gain'` 驱动文案模板、进度方向与强调色。数据全部来自现有 `profile` 字段：`goal` / `weight_kg` / `target_weight_kg` / `weekly_rate_kg` / `daily_calorie_target` / `height_cm` / `gender` / `age` / `activity_level`。

| 维度 | 减脂 `lose` | 增重增肌 `gain` | 保持体重 `keep` |
| --- | --- | --- | --- |
| 标签（不改） | `GOAL_LABELS.lose` = 减脂 | `GOAL_LABELS.gain` = 增重增肌 | `GOAL_LABELS.keep` = 保持体重 |
| 浅底标签色 | `--green-soft` / `--ok-ink` | `--honey-soft` / `--info-ink` | `--bg-2` / `--ink-2` |
| 起止 | 起始体重 → 目标体重（目标 < 起始） | 起始体重 → 目标体重（目标 > 起始） | **无目标体重**（`target_weight_kg` 为 null） |
| 进度方向 | 从起始向右减到目标，填充 = 已减 / 总差 | 从起始向右增到目标，填充 = 已增 / 总差 | **不画进度条**，改「波动带」 |
| 主行文案 | 已减 X kg · 还需 X kg | 已增 X kg · 还需 X kg | 近 7 天有 N 天在 ±1.0 kg 内 |
| 达成日 | 有（复用 `forecastGoal`） | 有（复用 `forecastGoal`） | **无**，改「保持得不错 / 有 N 天超出波动带」 |
| 热量口径 | `TDEE − (周速率×7700)/7`，下限 男 1500 / 女 1200 | `TDEE + (周速率×7700)/7`，无下限 | `= TDEE`，`weekly_rate_kg = 0` |
| 蛋白口径 | 1.8 g/kg（不超总热量 40%） | 1.5 g/kg | 1.5 g/kg |
| 每周节奏行 | −0.4 kg/周 | +0.4 kg/周 | 0 kg/周（显示为「维持」） |
| 解释条目第 1 条 | 「制造热量缺口，稳步掉秤」 | 「增加热量盈余，增肌增重」 | 「维持当前体重与状态」 |

🔴 **事实依据**：`nutrition.ts:61-85` 的 `calcTarget`（delta / 下限 / 蛋白系数）、`Onboarding.tsx:111` 的 `weeklyRate`、`Onboarding.tsx:234` 的三档描述文案。文案模板必须逐字复用这些既有口径，**不得另写一套**。

### 4.1 四种边界态（直接复用 `ForecastCard` 的四态，不重写）

`ReportScreen.tsx:47-88` 已定义 `insufficient / wrong_direction / reached / 正常` 四种状态与文案。本页按同样状态渲染，只把它压成一行：

| 状态 | 本页呈现 | 说明 |
| --- | --- | --- |
| `insufficient` | 「体重记录还太少，暂时算不出趋势」+ 去记体重的文字链 | 不显示进度条百分比、不显示达成日 |
| `wrong_direction` | 「方向和目标相反（每周约 ±X kg）」，`--red-soft` 底 `--risk-ink` 字 | 进度条显示但填充为 0，**不画负进度** |
| `reached` | 「已经到达目标体重附近，接下来把保持当成新目标就好」 | 不显示「还需」 |
| 正常 | 进度 + 达成日 + 「按当前节奏，仅供参考，不是承诺」 | 这句是既有文案，逐字沿用 |

### 4.2 空态与错误态

| 场景 | 呈现 |
| --- | --- |
| 档案未填（`profile` 为空） | 整页显示一张 `.card` 空态：「先填身体数据，才能算目标」+ `.btn`「去填写」→ `ProfileScreen`；**不显示 1800 兜底值冒充真实目标**（`nutrition.ts:87-89` 的 `emptyTarget()` 只是空档案兜底，不可展示为用户目标） |
| 体重读取失败 | 区 1 显示「体重数据暂时读不到」，保留其余区；不阻塞、不弹错误弹窗（沿用 `ProfileScreen.tsx:196` 的静默策略） |
| 保持态近 7 天无记录 | 「还没有足够的体重记录，先记几次看看」；不显示 0/7 这种像结论的数字 |
| `target_weight_kg` 异常（减脂却大于起始） | 不自动纠正、不猜测，显示「目标方向和数据不一致，去调整目标」+ 跳转 |

### 4.3 波动带（唯一新计算，需拍板）

保持态需要一个「带」才有得看。建议：`±1.0 kg` 围绕**近 7 天首次记录体重**，近 7 天在带内的天数 `N` 由现有 `weight_logs` 只读聚合得出，纯前端、零迁移、零新表。

🔴 `±1.0 kg` 是**产品决策不是技术默认值**，须拍板；在拍板前该值不得写进对外文案，也不得进 `packages/shared` 常量。

## 五、交互与微动效

| 交互 | 规格 |

## 六、可访问性（WCAG AA 基线）

| 项 | 做法 |
| --- | --- |
| 对比度 | 正文 `--ink` on `--surface` 远高于 4.5:1；辅助 `--ink-3` 4.64:1 / 4.92:1（`styles.css:7-9` 已修）；`--honey-dark` 4.71:1。**禁止**用 `--honey` 实底配白字（实测不足） |
| 色彩非唯一编码 | 三目标除浅底颜色外，必须有文字标签与方向词（减 / 增 / 维持）；进度不靠红绿表达好坏 |
| 触控区 | 返回、segment、ⓘ、调整目标均 ≥44×44；`ⓘ` 视觉 16px 但用 padding 撑触控区 |
| 语义 | 进度条 `role="progressbar"` + `aria-valuetext="已增 1.5 公斤，还需 4.5 公斤"`；segment `role="tablist"` / `aria-selected`；折叠 `aria-expanded` + `aria-controls` |
| 读屏顺序 | 顶栏 → 目标切换 → 当前/目标 → 进度（含文字结论）→ 四格数据 → 解释 → 主按钮；数字与单位在同一可访问名内 |
| 缩放 | 200% 缩放下 2×2 网格降为 1 列（`@media (max-width: 360px)` 或容器查询）；禁止 `user-scalable=no`（项目已定案） |
| 输入框 | 本页无输入框，不受 16px iOS 缩放规则影响；跳转到的编辑页保持 16px（`styles.css:75-85`） |
| 动效 | 见 §五 `prefers-reduced-motion` |
