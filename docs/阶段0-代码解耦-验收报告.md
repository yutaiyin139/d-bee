## 三、已知限制与遗留

1. `kv.ts` 暂无调用点（见上），属预期。
2. `cloudConfig.ts` 保留 `detectNative()` 文件内独立实现，**刻意不 import `lib/platform`**，避免模块级常量求值时的循环引用——后续维护请勿「顺手统一」。
3. 本次仅验证 Web 端；原生分支全部为**打桩占位**，函数内已写明接入点与目标实现（`takePhoto` / `startScan` / `decodeFromImage` / `exportFile` / `warmUpDecoder`）。
4. 原生端 endpoint 依赖 `VITE_NATIVE_ENDPOINT` 或回退 `CLOUD_HOST`；直连云端必须先在阶段 2 启用 `CapacitorHttp`，否则 apikey 请求头会被 CORS 预检拦掉。

## 四、下一步（阶段 1：Capacitor 骨架，约 1 周）

```bash
npm i @capacitor/core @capacitor/cli
npx cap init "D-Bee" com.dbee.app --web-dir=dist
npm i @capacitor/ios @capacitor/android
npx cap add android
npx cap add ios
```

前置：仓库需先纳入 Git（当前项目**尚不是 git 仓库**），否则 Windows ↔ Mac mini 的代码同步只能靠共享目录，换行符/权限位差异会引发难排查的构建错误。
