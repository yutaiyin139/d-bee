## 二、根因（代码级证据）

### 根因 1：把图片当「链接」分享 —— 主因

`src/lib/share.ts` 旧实现把 PNG 的 base64 塞进 Capacitor Share 的 `url` 参数：

```ts
await capShare.share({ title, text, url: `data:image/png;base64,${base64}`, dialogTitle })
```

而 `url` 的语义是「一条链接」，不是文件：

- **iOS** `node_modules/@capacitor/share/ios/Sources/SharePlugin/SharePlugin.swift:26`  
  `if let url = call.getString("url"), let urlObj = URL(string: url) { items.append(urlObj) }`  
  → `data:` scheme 被转成 NSURL，作为**链接**塞进 `UIActivityViewController`。微信的分享扩展不接受该 scheme（点微信无反应 / 不显示）；钉钉把它当一条超长链接收下，对方点开自然打不开。
- **Android** `SharePlugin.java:110`  
  `if (url != null && !isFileUrl(url) && !isHttpUrl(url)) { call.reject("Unsupported url") }`  
  → 直接抛错；旧代码 catch 后回落 `downloadBlob()`，而 WebView 没有下载管理器，`a.download` 静默失败 = 点了没反应。

`ShareOptions` 类型定义明确写着：`url` 只能是 `http / https / file://`；**`files?: string[]`（file:// URL 数组）才是分享图片文件的通道**（since 4.1.0，iOS/Android 均支持）。

### 根因 2：原生壳里 `location.origin` 生成无效邀请链接

`src/pages/InviteCenter.tsx`（两处：复制邀请口令、绘制邀请卡）原本用：

```ts
const link = `${location.origin}?invite=${encodeURIComponent(code)}`
```

- Web 线上 `location.origin = https://d-bee.cn` → 恰好正确，所以缺陷长期没暴露。
- iOS 原生壳 `capacitor://localhost`、Android 原生壳 `https://localhost`（`server.androidScheme: 'https'`）→ 生成 `capacitor://localhost?invite=XXX`。  
  这类链接印在分享卡上、或复制进口令发到微信/钉钉后，好友点开必然打不开。

### 附带发现（非本次报障主因，但同属分享链路）

- iOS 在 `capacitor.config.ts` 中**排除了 `@capgo/capacitor-wechat`**（SPM 模块名兼容 bug + 营业执照未办、`WECHAT_LOGIN_ENABLED=false`）。因此 iOS 的「分享到微信」只能走**系统分享面板**，不是微信 SDK 直连跳选好友。系统面板分享图片本应可用，无需微信 SDK；若产品要求「直接拉起微信选择会话」，是另一个需资质 + Universal Link 的独立需求。
- `Info.plist` 的 `LSApplicationQueriesSchemes` 已含 `weixin` / `weixinULAPI` / `weixinURLParamsAPI`，不是本次故障原因。

## 三、修复清单

| 文件                                          | 改动                                                                                                                                                                                                          |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json` / `package-lock.json`        | 新增 `@capacitor/filesystem@^8.1.5`                                                                                                                                                                           |
| `capacitor.config.ts`                       | iOS / Android `includePlugins` 两端都纳入 `@capacitor/filesystem`                                                                                                                                                |
| `src/lib/share.ts`                          | 原生分支改为 `Filesystem.writeFile`(Cache, base64) → `getUri()` → `Share.share({ files: [uri] })`，**不再传 `url`**；`exportFile()` 的原生占位分支一并按同一链路实装；插件缺失时明确提示「请更新 App」，不再回落 Web 下载；新增 `sanitizeShareFilename()` 防路径穿越 |
| `src/lib/shareLink.ts`（新增）                  | 对外邀请链接单一真源：`PUBLIC_SITE_ORIGIN = 'https://d-bee.cn'` + `publicSiteOrigin()` + `buildInviteLink()`。凡 `capacitor://` / `file://` / localhost / 127.0.0.1 / `.local` 一律回落公网站点                                  |
| `src/pages/InviteCenter.tsx`                | 两处 `location.origin` 拼接改为 `buildInviteLink(code)`                                                                                                                                                           |
| `tools/share-consistency.test.ts`（新增，护栏 19） | 20 项断言：原生分享必须用 `files` 不得用 `url`、零 `data:` 字面量、Filesystem 写 Cache/getUri、两端插件白名单、邀请链接各场景、文件名安全；内置反例 fixture 做红验证                                                                                            |

**Web 端行为零改动**：`isNative()` 恒 false，仍走 `downloadBlob()` 下载 PNG。

**mini 端不改代码**：三页微信转发均正常且带邀请码；图片卡片分享未实装但 UI 已降级，属于产品功能缺口而非缺陷。是否在 mini 增加「打卡卡分享」是产品决策，未擅自新增复杂度。

## 五、尚未闭环（必须区分「代码已修」与「已进包」）

🔴 **本次只改了代码与工程配置，未重新打包任何安装包，也未部署 Web。** 用户手上的安装包仍是旧行为。
