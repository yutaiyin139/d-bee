## 二、App Privacy 营养标签（5.1.1，未填则提交按钮被阻塞）

答案逐项对齐 `ios/App/App/PrivacyInfo.xcprivacy`（6 类，全部 `Linked=true` / `Tracking=false` / 用途 `AppFunctionality`）：

| 数据类型（ASC 中文） | 是否收集 | 关联到用户身份 | 用于追踪 | 用途 |
| --- | --- | --- | --- | --- |
| 电话号码 | 是 | 是 | 否 | App 功能 |
| 电子邮件地址 | 是 | 是 | 否 | App 功能 |
| 用户 ID | 是 | 是 | 否 | App 功能 |
| 健康与健身 | 是 | 是 | 否 | App 功能 |
| 照片或视频 | 是 | 是 | 否 | App 功能 |
| 其他用户内容 | 是 | 是 | 否 | App 功能 |

问卷顶层两项：

- **是否收集数据用于追踪**：**否**（`NSPrivacyTracking=false`，`NSPrivacyTrackingDomains` 为空，全仓无追踪/广告 SDK）。
- **用途**：每类只勾 **App Functionality**；**不要**勾 Analytics / Product Personalization / Developer's Advertising。

🔴 **两条最容易填错、且会导致拒审**：

1. 照片与其他用户内容**确实离开了设备** —— `src/lib/ai.ts` 把餐食照片转 data URL 随大模型请求上传，用户手写的餐食描述也一起上传。**必须如实申报这两类**，不能为省事只填前四类；Apple 会核对标签与实际行为（含每个 SDK），不符即拒。
2. 六类都选「**关联到用户身份 = 是**」（与隐私清单 `Linked=true` 一致）。

🟠 **文档里查不到、需本人确认**：是否随包带了第三方崩溃/性能/统计 SDK（若有，需另申报 Crash Data / Performance Data / Diagnostics）；
`PrivacyInfo.xcprivacy` 只声明了 `UserDefaults / CA92.1` 必要理由 API，App 层无其它采集声明。

## 三、新年龄分级问卷（2026-01-31 起必答）

🔴 **不能按 10-23 旧清单写的「预期 4+」直接选。** Apple 新问卷新增 in-app controls / capabilities / medical-wellness / violent themes 等维度，且明确要求把 **AI 助手对敏感内容出现频率的影响**计入分级。

按本项目实际情况**如实回答**的指引（最终以 ASC 问卷逐题为准）：

| 维度 | 实情 | 建议回答 |
| --- | --- | --- |
| 暴力 / 色情 / 赌博 / 恐怖 | 无 | 无 |
| 医疗 / 健康 /  wellness 主题 | **有**（热量、营养素、体重、运动、膳食计划） | 如实答「有」 |
| 生成式 AI / AI 助手 | **有**（「问问小蜜」、AI 拍照识别、AI 复盘） | 如实答「有」，并按问卷追问其对敏感内容出现频率的影响 |
| 用户生成内容（UGC） | 有手写描述/照片，但**只进自有服务器，无公开社区/聊天/分享墙** | 无公开 UGC；若有该题，按「无公开分发」答 |
| 广告 / 第三方营销 | 无 | 无 |
| 应用内家长控制 / 内容过滤 | 🟠 项目有首启同意门与隐私同意，但是否构成 Apple 定义的 in-app controls **文档查不到** | 本人按 ASC 题目定义判断 |

> ✅ 做法：**逐题按实答完，以 ASC 自动算出的分级为准**，不要为「看起来友好」手工压到 4+。
> 若算出 13+ / 16+，商店页面与可售范围会变化，但这是合规做法；反过来低报被审核发现属 2.3 元数据失实。
> 🔴 该问卷只能由账号持有人本人在 ASC 回答，且答案须与 §二 营养标签、实际功能一致。
