## 七、本轮踩到的坑（须记住，避免假绿 / 假红）

**坑 1 · `dbee-ssh.py putdir` 失败（未查明根因）**：`putdir dist /var/www/d-bee` 在第一个 `sftp.put` 即抛 `FileNotFoundError: [Errno 2] No such file`，两次重试同样失败、**0 文件上传**；但远端权限正常（`ubuntu` 属主、`WRITE_OK`），手工 import 该脚本模块后逐个 `sftp.put` **全部成功（OK=19 / FAIL=0）**。→ 结论：脚本 `putdir` 动作本身在本机环境下不可靠，**发布改用逐文件 `sftp.put` 并在之后做 19/19 sha256 逐字节验证**；根因待查（怀疑与 Windows 路径分隔符或 `os.walk` 相对路径拼接有关），**不影响本次结果**（已实证线上与本地逐字节一致）。另：`dbee-ssh.py` **没有 `getdir` 动作**，远端整目录取回须走服务器端 `cp -a` 备份 + 本地留档。

**坑 2 · `dist/` 混合污染**：native 构建与 Web 构建**共用 `dist/`**。Android 打包后 `dist/` 里是 native 16 文件，此时直接 `cp -a dist-web-postdeploy/. dist/` 会得到 **24 文件的混合产物**（5 个 native 独有 hash 文件残留），既不是 Web 也不是 native。→ 正确做法：**先整体 `mv` 移出混合目录留档，再从空目录 `cp -a` 复制**，复制后做逐字节校验（本次 19/19 IDENTICAL）。

**坑 3 · 法务页路径写法导致假象**：法务静态页是**目录形态** `dist/legal/<terms|privacy|disclaimer>/index.html`，线上正确 URL 为 `https://d-bee.cn/legal/terms/index.html`。若请求 `/legal/terms.html`，会命中 SPA fallback 返回 `index.html`（11,871 B），表现为「三页长度完全相同 + `v1.7.8` 计 0」的**假红**（且 `NONEXISTENT-xyz.html` 同样返回 200 / 11,871 B，可据此一眼识别 fallback）。→ 复核法务页务必用目录路径，并用**不存在的路径做对照**验证不是 fallback。

**坑 4 · `capacitor.plugins.json` 不在 `assets/public/`**：其真实位置是 **`assets/capacitor.plugins.json`**（vc25 / vc26 两版一致）。探针写 `assets/public/capacitor.plugins.json` 会假报缺失。另 `cordova.js` / `cordova_plugins.js` 为 **0 字节**是**正常形态**（本项目无 Cordova 插件），旧包同为 0，非退化。

**坑 5 · 产物探针字串必须取源码原文**：D1 说明的实际文案是「开关目前**仅保存你的提醒偏好**」，若按记忆用「仅保存偏好」去 grep 产物会得到 **0** 的假阴性。→ 探针字串一律先从源码常量取值（此处 `NOTIFY_UNAVAILABLE_NOTE`），再下产物。
