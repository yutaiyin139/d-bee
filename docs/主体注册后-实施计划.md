## 一、资质事实核对（**今天做，决定后面一半的路线**）

「主体注册搞定」这句话里藏着几个分叉，不同答案走完全不同的路。开工前必须先确认：

| # | 待确认项 | 为什么关键 |
|---|---|---|
| 1 | **主体类型**：有限责任公司 / 个体工商户 / 个人独资 | **个体户拿不到 ICP 经营许可证**（`备案材料清单.md` §8.2 已论证）。若是个体户：网页端**永久不能收费**，只能走 iOS IAP + 安卓商店内购（平台代收）；微信/支付宝商户号倒是能办 |
| 2 | **经营范围**是否含「第二类增值电信业务」 | ICP 经营许可证硬条件。注册时若没写，需先做经营范围变更（工商，数个工作日），否则证申不下来 |
| 3 | **注册资本**是否 ≥ 100 万（认缴即可） | ICP 经营许可证硬条件 |
| 4 | **是否已开对公账户** | 微信支付商户号、支付宝企业应用、Apple 收款（企业账号）都要对公账户 |
| 5 | **社保人数**：能否凑 ≥ 3 人在公司名下缴社保 | ICP 经营许可证硬条件，**这是主要成本**（约 ¥4000/月量级），也是唯一无法靠技术绕过的一项 |
| 6 | 现有小程序 `wxb7c7122de9c3ab1f` 当前主体是个人还是已变更 | 决定走「主体变更」还是「新注册企业小程序」 |

> **一句话结论**：主体注册完成 ≠ 可以收费。**能否在网页端合法收费，取决于 ICP 经营许可证；
> 而那张证的真实门槛是「有限公司 + 100万认缴 + 增值电信经营范围 + 3人社保 + 域名过户到公司」**，
> 周期 20–60 个工作日（不含前置准备）。在此之前，**唯一干净的收费路径是 iOS IAP**（Apple 个人账号
> 已通过，交易与收款发生在平台侧）。

## 二、总体路线：三条并行泳道

资质办理周期长且多依赖外部审批，**绝不能串行等**。按依赖关系拆三条独立泳道：

```
泳道 A（技术，零资质依赖）  ──► 自托管网关 → 切流量 → iOS 构建 → IAP 上架
泳道 B（资质，外部审批）    ──► 域名过户 → 备案变更 → 各类证 → 商户号 → 网页端收费
泳道 C（运营，轻依赖）      ──► 分享卡片 → 公众号/社群 → 彩页更新 → 技术文章
```

**优先级判断**：泳道 A 是产品可用性的命脉（云库随时可能再被冻结，自托管是主权），
且**完全不依赖任何资质**，应立刻全速推进。泳道 B 里只有「域名过户 + 备案主体变更」需要抢早
（周期最长、且卡 HTTPS 与 Universal Link），其余可以按收费节奏排。

### A1 · auth/JWT 网关（2–3 天）

端点对齐 `AuthScreen.tsx` 实际调用（已核对）：

| 端点 | 对应前端调用 |
|---|---|
| `POST /.cloud/auth/v1/verification` | `cloud.auth.sendOtp({ phone })` → 返 `{ verificationId, isExistingUser }` |
| `POST /.cloud/auth/v1/token` | `cloud.auth.verifyOtp(...)` → 查/建 `profiles` → 签发 JWT |
| `GET /.cloud/auth/v1/user/me` | `cloud.auth.getSession()` |
| `POST /.cloud/auth/v1/refresh` | 会话续期 |

**必须遵守的铁律**：网关在每笔 DB 请求前，**同时**注入
`SET LOCAL app.user_id = <sub>`（给 RLS）**和** `request.jwt.claim.sub`（给 `badge_stats` /
`leaderboard` 这类依赖 JWT 声明的函数）。少注入后者 → 榜单返回 `{"error":"not_authenticated"}`
（10-20 SQL 自测已实测到这个坑）。

JWT `sub` = 原 `owner_id`（如 `2109869577155379200`），密钥只在服务端。

**验收**：手机号登录 → 拿 JWT → `SET ROLE authenticated` 只见自己那行；`leaderboard()` 不再报 not_authenticated。

## 六、风险与红线（提审/上线前必看）

1. **🔴 网页端收费的法律红线**：ICP 经营许可证下发前，站内**不得出现真实收款入口**
   （微信/支付宝、会员订阅、付费内容）。个人备案含在线支付/会员收费 = 备案信息与内容不符，
   先整改通知、逾期注销备案 + 暂停域名解析；情节严重按《互联网信息服务管理办法》第 19 条处罚。
   **现阶段唯一干净路径 = iOS IAP（平台代收）**。
2. **🟡 Apple 账号主体不一致**：现有是**个人**开发者账号，App Store 展示的是个人姓名；
   而备案主体、隐私政策主体已变成公司。审核可能质疑主体一致性（尤其涉及健康数据 + 内购）。
   两个选择：①先用个人账号上架抢时间，后续升级；②直接办企业账号（需 D-U-N-S，等期数天–数周）。
   **建议：先申请 D-U-N-S 占位，同时用个人账号推进构建与测试，证下来再决定要不要切主体。**
3. **🟡 3 人社保是 ICP 证的真实成本门槛**：约 ¥4000/月量级 + 记账报税 ¥2000–5000/年。
   若近期不打算在网页端收费，**ICP 证可以延后申请**，先把 iOS IAP 跑起来验证付费意愿，
   再决定要不要承担这个固定成本。这是个商业决策，不是技术决策。
4. **🟡 云库去留未定**：云库已恢复但仍可能再被冻结（10-19/10-20 连续 2 天备份失败同源）。
   自托管切完前**必须保持每日备份**（`db/backups/YYYY-MM-DD.json`，30 天滚动）。
   切完后需拍板：自托管彻底替代 / 回迁 / 双写。
5. **🟢 `verify_payment_order` 当前是空壳**（`0030` 第 1171 行只查 `status='paid'`，无验签）。
   接入真实支付前**必须**先在网关补 Apple 验签分支，否则任何人可伪造凭证白拿权益。
   这是当前支付链路唯一的实质性代码缺口。
6. **🟢 数据一致性**：切换期两端并存，切流量前务必 pg_dump，切完立刻做全链路回归
   （`前端切换自托管-前置条件与步骤.md` §三 的 8 项验收清单）。
