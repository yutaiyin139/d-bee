## 一、关于「3 人社保」：结论是**必须，无法绕过**（已查证 2026 多省口径）

你问「是有限公司，一定要 3 人社保吗」——**是的，这是 ICP 经营许可证的硬性条件，没有合规的绕过办法**。
2026 年多省通信管理局口径一致，且**核查力度在加强**：

| 要求 | 细则 |
|---|---|
| 人数 | **≥ 3 名全职在职员工**，且必须是**三个不同的人**，一人不能兼两个岗位 |
| 岗位 | 需覆盖 **许可负责人 / 客服负责人 / 安全负责人**（部分地区表述为业务/技术/信息安全负责人）。安全负责人需通信或计算机相关专业背景、大专以上 |
| 法人 | **法人可以算其中一人**，另外两人必须是公司其他员工 |
| 缴纳主体 | **必须由申请公司自己缴**。母公司、关联公司、第三方人力资源公司代缴 → **一律不认** |
| 挂靠 | **挂靠社保直接驳回**，且会核查劳动合同 + 在职证明 + 社保记录三者是否完全对应 |
| 时长 | 多数地区要求近 1 个月记录，部分省份要求**连续 3 个月**。注意社保系统隔月才能打印，实操常需等 2–3 个月才有完整凭证 |
| 后果 | 提交虚假参保材料 → 警告处罚，且**处罚之日起一年内不得再次申请** |
| 抽查 | 管局会做**跨部门数据比对**（社保 vs 工商 vs 劳动合同），2026 年起「形式合规已不足以通过审核」 |

**成本量级**：3 人社保约 ¥4000/月起（含法人自己，即实际只需**再招 2 人**）+ 记账报税 ¥2000–5000/年
+ 代办 ¥5000–15000（可选，专业代办可把周期压到约 47 个工作日）。

> **省钱的现实做法**：法人自己算 1 人，再找 2 名真实的兼职/家属入职并**由公司真实缴纳社保**
> （签劳动合同、真实发薪、真实参保）。这是合法的；「挂靠」不合法且会被查出来。
> 另需注意部分地区**严查办公场地**（不接受虚拟地址/挂靠地址/住宅，可能上门或视频核验），
> 这项也是持续成本。

### 所以真正的决策不是「能不能免社保」，而是「现在要不要网页端收费」

| 方案 | 前提 | 成本 | 判断 |
|---|---|---|---|
| **A. 暂不办 ICP 证，只做 iOS IAP** | Apple 个人账号（已通过） | **0 额外固定成本** | ✅ **强烈推荐先走这条**。交易与收款发生在 Apple 侧，属「原生 App + 应用商店内购」路径（`备案材料清单.md` §8.4 已论证：个人开发者账号即可上架，实践中普遍可行） |
| **B. 办 ICP 证，网页端直接收款** | 3 人社保 + 域名过户 + 备案主体变更 + 增值电信经营范围 | **约 ¥4000/月 + ¥2000–5000/年 固定成本**，周期 20–60 工作日 | 等有真实付费数据、确认网页端收入能覆盖这个固定成本时再启动 |

**符合你的「价格低廉 + 技术可控」原则的路径是 A**：先用 iOS IAP 验证付费意愿与转化率，
零固定成本；等数据证明网页端值得投入，再背 3 人社保去办 ICP 证。
**不建议现在就办证**——每月 ¥4000 的固定支出在付费用户量起来之前是纯消耗。

两种走向的代价差别极大：

| 走向 | 网站是否中断 | 周期 |
|---|---|---|
| 管局**允许**直接变更主体 | ❌ 不中断，审核期可正常访问 | 约 1–2 周 |
| 管局**不允许** → 必须「注销原备案 → 企业主体重新首次备案」 | ⚠️ **注销后域名无法解析访问，直到新备案通过** | 注销 3–5 工作日 + 重备全流程（初审 1–2 + 管局 1–20） |

**行动**：先查本省管局规则（腾讯云备案控制台会直接提示是否可变更）。若属「不允许」省份：
- **先确认域名已过户到公司名下再提交**——管局会核对 WHOIS 持有者与备案主体一致，域名没过户必被驳回
- **关闭域名 WHOIS 隐私保护**，否则备案系统读不到真实持有者信息
- 变更前后**备案主体须同省**，且目标企业名下不能已有备案成功的信息
- 若走「注销重备」，**注销前先把 A4 切换做完并验证 IP 直连可用**，这样停站期间业务不断
- 部分省份会卡「原个人主体身份证与现企业法人须为同一人」——本项目是同一人，天然满足

## 二、总体路线：三条并行泳道

资质办理周期长且多依赖外部审批，**绝不能串行等**。按依赖关系拆三条独立泳道：

```
泳道 A（技术，零资质依赖）  ──► 自托管网关 → 切流量 → iOS 构建 → IAP 上架
泳道 B（资质，外部审批）    ──► 域名过户 → 备案变更 → 各类证 → 商户号 → 网页端收费
泳道 C（运营，轻依赖）      ──► 分享卡片 → 公众号/社群 → 彩页更新 → 技术文章
```

**优先级判断**：泳道 A 是产品可用性的命脉（云库随时可能再被冻结，自托管是主权），
且**完全不依赖任何资质**，应立刻全速推进。泳道 B 里只有「域名过户 + 备案主体变更」需要抢早
（周期最长、且卡 HTTPS 与 Universal Link），其余可以按收费节奏排。

   请求由 flash 服务并按 flash 计费。→ **文本与视觉统一用 `deepseek-flash` 即可**，不必配两个模型。
3. 🟡 **`/llm/models` 必须给 flash 标 `supportsImages: true`**。前端 `pickModel(needVision=true)`
   是 `usable.filter(m => m.supportsImages === true)` 再取 `isDefault`，标错则选不到视觉模型 → 拍照识别报错。
   另需过滤 `disabled !== true && enabled !== false`（`ai.ts:31`）。

**图片 token 成本可控**：DeepSeek 对每张图先自动缩放（低于 ~384×384 放大、高于则等比缩小到约
800×800 像素量级），**每图 token 上限恒为 384**——2000×2000 与 5000×5000 同价。
前端 `compressImage(file, maxSide=1024, quality=0.82)`（`ai.ts:333`）已在客户端压过一道，
`detail` 设 `low`（降到 512×512）主要为提速，不额外省钱。请求体上限 48 MiB，单图 base64 ≤ 32 MiB，
D-Bee 的 1024px 压缩图远低于此，**无需上 Files API**。

**验收**：拍照识别出 JSON；`askCoach` 流式回文本。

#### 成本测算（DeepSeek V4 Flash，2026-10 官方价，已计入峰值加价）
