## 一、一句话结论

**采纳薄荷的「三段卡片 + 胶囊小标题 + 2×2 网格 + 进度条 + 双卡」信息架构，用自律蜜蜂的米色底 / 白卡 / 蜂蜜黄 token 重绘；命名改回「体重管理方案」；参考图里 4 类字段不照抄。**

薄荷那张图本质是「信息密集的方案展示页」，我们现在是「一页三区的简洁 Sheet」。用户要的是**信息密度向薄荷靠拢**，不是把薄荷的配色、营销标签、医学判断一起搬过来。所以做法是：**结构借鉴、视觉不改、字段诚实**。

## 五、数据来源与「不编造」纪律

| 字段 | 来源 | 可用性 |
| --- | --- | --- |
| 身高 / 体重 | `profile.height_cm` / `current_weight_kg` | ✅ 落库 |
| 基础代谢 | `calcBmr(gender, age, heightCm, weightKg)`（`src/lib/nutrition.ts:30`） | ✅ 纯函数，输入全为落库字段；**输出不参与任何目标口径**，不与首页「还可吃」产生漂移 |
| 当前 BMI | `weight / (height/100)²`，新增 `calcBmiCore()` 放 `@dbee/shared` | ✅ 纯展示层，只走 `roundTo` |
| 起始 / 目标 / 当前体重 | `start_weight_kg` / `target_weight_kg` / `current_weight_kg` | ✅ 落库 |
| 进度百分比 | `((start − current) / (start − target)) × 100` | ✅ 现有 `buildHealthPlanViewCore()` 已有口径 |
| 期望 / 还需 | `|target − start|` / `|target − current|` | ✅ 现有 `progressText` 已有 |
| 每日热量 / 三大营养素 / 每周节奏 | 落库派生字段 | ✅ 只读，**禁止现场 `calcTarget()`** |
| **第 N 天 / 起始日期 / 达成日** | ❌ `Profile` 无创建日期字段；`forecastGoal()` 依赖报告页 `weightSeries` | 🔴 **不显示**，改一行「每周节奏」 |
| 燃脂心率 / 身体年龄 / 体型 | ❌ 无数据源、无算法 | 🔴 **不做** |

**护栏须同步收紧**：新增「方案页允许调 `calcBmr` / `calcBmiCore`，禁止调 `calcTarget`」「BMI 刻度不得出现红黄绿诊断色值」「运行时不得出现第 N 天 / 达成日 / 燃脂心率 / 身体年龄」四类断言。

## 六、三目标态差异（单态渲染，三态共用同一组件）

| | 减脂 | 增重增肌 | 保持体重 |
| --- | --- | --- | --- |
