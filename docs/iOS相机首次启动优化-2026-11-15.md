# iOS 相机首次启动优化（2026-11-15）

> 触发：用户反馈 iOS 第一次点「拍一张这一餐的照片」到相机出现比较慢。
> 结论先行：**可消除的等待已全部移出点击路径；系统授权弹窗与相机硬件冷启动属 iOS 系统行为，前端无法消除。**
> 本轮只改 `src/`（Web/iOS/Android 共用），mini 独立工程零改动；未 commit / 未构建 / 未部署 / 未真机验证（铁律 #13）。

## 1. 根因（读 @capacitor/camera 8.2.6 iOS 源码确认，非推测）

调用链：`LogSheet.handlePickMealPhoto()` → `takePhoto()`（`src/lib/capture.ts`）→ `window.Capacitor.Plugins.Camera.getPhoto()`。

点击后**串行**发生四段等待，期间 UI 零反馈（`busy` 只在拍完照、开始识别时才置位）：

| 段 | 来源 | 首次额外开销 | 能否消除 |
|---|---|---|---|
| ① 额度预检 | `checkPhotoQuota()` → `get_photo_quota` RPC | 一次网络 RTT，弱网可达数秒 | ✅ 已消除 |
| ② 插件冷启动 | Capacitor JS bridge / 原生 `CameraPlugin` 懒加载，首次 `getPhoto()` 才实例化 | 数十至数百 ms | ✅ 已消除 |
| ③ 系统授权弹窗 | `CameraPlugin.swift: showCamera()` → `AVCaptureDevice.requestAccess(for: .video)` | 等用户点「允许」 | ❌ iOS 系统行为 |
| ④ 相机硬件冷启动 | 授权回调里才 `presentCameraPicker()` 创建 `UIImagePickerController` | 约 0.5–1.5 s | ❌ iOS 系统行为 |

②③④ 每次点击都由 `showCamera()` 重走一遍；**已授权时 `requestAccess` 立即回调、相机已热** —— 这正是「只有第一次慢」的原因。

另有一处**拍完之后**的浪费（不属「调出相机」，本轮未动）：`getPhoto({ resultType:'dataUrl', quality:92 })` 不传 `width/height`，iOS 回传全分辨率（4800 万像素级）base64 → `dataUrlToBlob` 解码 → `compressImage()` 再解码一次并缩到 1600 → canvas 再编码。见 §5 待拍板 B。

## 2. 本轮优化（4 项）

1. **原生插件预热**：新增 `capture.ts: primeCamera()`，录入层挂载时 fire-and-forget 调一次 `checkPermissions()`。
   - `checkPermissions()` 在 iOS 侧只读 `AVCaptureDevice.authorizationStatus`，**不弹授权框**（`CameraPlugin.swift:131-142` 实证）。
   - 🔴 刻意不调 `requestPermissions()`：法务 `legal.ts:331` 公示相机权限触发时机是「你点击『拍照识别』时」，提前弹框与之不符，也容易被 App Store 判为过度索权。
   - Web 端 `isNative()` 短路、零操作；预热失败静默降级，点击时 `getPhoto()` 会自行再查权限。
2. **额度预检提前**：录入层挂载时后台预取 `getPhotoQuota()`（Pro 无限次，跳过预取），结果存 `quotaCacheRef`。
   `checkPhotoQuota()` 仅在「缓存明确有额度且 60s 内新鲜」时直接放行；额度为 0 / 缺失 / 过期一律仍查网络。
   🔴 **缓存只用于放行，绝不用于拦截**：真闸门仍是 `handleFile()` 里的 `claimAiQuota()`（服务端原子占用、跨设备一致）。识别成功后用服务端返回的 `guard.remaining` 刷新缓存，避免连拍误判。
3. **即时反馈**：新增 `openingCamera` 状态，点击后立刻显示「正在打开相机…」；原生端补「首次使用需允许相机权限」，Web 端不提权限（Web 走 `<input capture>` 文件选择器）。消除「点了没反应」。
4. **防连点**：开相机期间禁用「拍一张」/「换一张照片」按钮，两个拍照入口（餐盘 / 包装）都加 `openingCamera` 守卫 —— iOS 连点会重复 `present` 相机控制器，首次尤其容易卡住。

## 5. 待拍板（本轮未做，需点头才动）

| # | 选项 | 收益 | 代价 / 风险 |

| **A** | 把首次系统授权弹窗提前到「打开记录弹层」时（`requestPermissions`） | 唯一能真正消除「首次慢」的办法 | 与法务公示的触发时机冲突，需同步改文案；App Store 对提前索权敏感；属产品/合规决策 |

## 6. 生效路径（现在真机还看不到）

1. 改动在 `src/`，Web / iOS / Android 共用；Android 顺带受益（同一插件），Web 的额度预检与即时反馈同样生效。
2. **Web**：需重新 `npm run build` + 部署，线上才会变。
3. **iOS**：你 Mac 侧 `git pull` → `VITE_NATIVE_ENDPOINT=https://d-bee.cn npm run build:native` → `npx cap sync ios` → Xcode≥26 Archive，改动才进包。
4. **Android**：需重新打正式包；**mini**：独立工程，本轮零改动。
5. 本轮**未重建刚发布的 `dist` / `mini/dist`**，未碰任何生产资源。
