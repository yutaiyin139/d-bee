## 〇、一句话结论

**四端里只有 web 已经上线，其余三端全部被外部资质卡住，而且卡的不是同一件事。**

- **mini（小程序）是最可能先上的端** —— 它是**唯一不依赖软著**的端（软著是 Android/iOS 的总闸门，
  30–60 工作日且卡在只有你能做的 AI 条款决策），也不依赖 Mac。
- **Android 第二** —— 能自己构建签名包（今天已打出），但上架卡软著；**华为有免责函过渡方案**可绕开。
- **iOS 最后** —— 除软著外还卡 Mac + `DEVELOPMENT_TEAM` 未设置（Windows 无法代劳）。
- **等备案期最有价值的三件事**：① 修完 3 项代码缺口（合规/诚信，不依赖备案）；
  ② 把回迁工程的服务端三件**提前写完**（下证当天只需扳开关）；③ 推进只有你能做的资质决策。

## 一、四端架构真相：不是四套代码，是两套

这是所有「一致性」讨论的前提，必须先说清：

```
                    ┌─ web      （已上线 http://150.158.51.106）
   src/ ────────────┼─ iOS      （Capacitor webDir=dist，无独立 TS 业务代码）
                    └─ Android  （同上）

   mini/ ─────────── mini（Taro，独立代码库）

   packages/shared ─ 两端共用的真相源（rules / datefmt / numfmt 等）
   server/ ──────── 自托管网关 + PostgreSQL
```

- `ios/` 与 `android/` 目录里**没有业务逻辑**，只是 Capacitor 壳 + 原生插件；
  业务代码 100% 来自 `src/`，经 `vite build` 产物同步进壳。
- 所以「四端一致」的实际含义 = **`src/` 与 `mini/` 一致** + **两端数据面一致** + **文案口径一致**。
- `packages/shared` 是收敛工具：2026-11-04 已把「定价三副本」「会员状态四副本」收敛进去（提交 `7d61151`）。

**两条独立链**：

→ 若软著卡在 AI 条款迟迟不提交，**mini 会明显早于两个原生端上线**。这是首发建议的核心依据。

## 三、🔴 首发建议：先上 mini

### 为什么是 mini（四条硬理由）

| # | 理由 | 依据 |
| --- | --- | --- |
| 1 | **唯一不依赖软著** | 软著是原生端总闸门（30–60 工作日），且卡在「AI 条款须你亲笔手抄承诺」——只有你能决策，我无法代劳 |
| 2 | **不依赖 Mac** | iOS 的 `DEVELOPMENT_TEAM` 未设置，Windows 无法代劳，你还得腾出 Mac 时间 |
| 3 | **工程侧已 100% 就绪** | 包体 908 KB（限额 2 MB）、双层护栏已实测（构建期+运行时）、endpoint 开关代码已就绪、13 页无死链 |
| 4 | **获客成本最低** | 微信生态内分发，无需用户下载安装包；且小程序是「拉新入口」，导流到 App 更自然 |

### 为什么不先上 Android（虽然它今天已经打出包了）

Android 能构建 ≠ 能上架。它的阻断是**软著 + App 备案**，且：
- 软著未下来时华为可用《免责函》（盖企业章）过渡，但**小米/OPPO/vivo/应用宝口径不一**，需逐家核实；
- `versionCode` 仍是 14（与 11-02 旧包同号），分发前须 +1 到 15；
- 商店素材缺口：安卓截图档位（`shot-store.mjs` 只出 iPhone/iPad）、216×216 图标档位未确认；
- 应用名口径未定（`app_name=D-Bee` vs 中文名「自律蜜蜂」）—— **软著/备案/商店三处须逐字一致，定名是前置**。

→ Android 适合做**第二梯队**，等软著有结论 + 素材补齐。

### 为什么 iOS 最后

除软著外，iOS 还叠了两层：
1. **Mac 硬步骤**（补 `DEVELOPMENT_TEAM` → 编译 3 个 Swift 插件 → Archive → Upload），Windows 完全无法代劳；
2. **Apple 账号仍个人主体** → 中国区提审必弹 `ICP_NUMBER_MIIT_PROVIDER_NAME_MISMATCH`（实测为提示性非硬阻断，但根治要账号迁移组织类型，依赖 D-U-N-S）。

→ 但 **TestFlight 内测不依赖备案号**，只要 Mac 步骤做完就能真机测。建议把 iOS 拆成
「TestFlight 内测（可提前）」与「中国区上架（等资质）」两件事分别推进。

### ⚠️ 一个必须澄清的前提

mini 首发的**必要条件**是 `d-bee.cn` 就绪（ICP 下证 → DNS → HTTPS → 白名单）。
你已拍板「必须用 d-bee.cn 上线小程序端」，所以：

> **mini 的最早可上线时间 = max(ICP下证+DNS+HTTPS, 主体变更+小程序备案)**

若你说的「两天完成」指 **ICP** → 左链几天内可就绪，右链（小程序备案 1–20 工作日）成为关键路径。
若指 **主体变更** → 右链刚启动，左链仍卡在 ICP 未下证（备案期间禁止加解析）。
自查方法见《小程序上线前缺口清单》§五 阶段 0 的自查表。

## 五、🔴 今天（11-04）引入的一个状态变更，须你知悉

为打 Android 正式包，我执行了 `VITE_NATIVE_ENDPOINT=https://d-bee.cn npm run native:sync`。
`cap sync` **同时同步 ios 目录**，副作用是：

- `ios/App/App/public/` 现在是 **native-release 产物**（`kf="https://d-bee.cn"`，已追赋值链确认生效常量）；
- 而《苹果端上线前置条件总清单》§〇 记载的是「正式包数据面暂维持**云库内测**形态」——**该记载已过时**。

**影响评估**：`ios/App/App/public/` 不被 git 跟踪（实测 `git ls-files` = 0），不污染仓库；
且 iOS 目前因 `DEVELOPMENT_TEAM` 未设置**根本无法 Archive**，所以没有立即可交付物受影响。

**但这是个待爆的地雷**：将来你在 Mac 上直接 Archive，会得到一个**连 d-bee.cn（无解析）的 iOS 包** →

## 七、四端一致性前置检查机制（你的第 4 条要求）

要求是「每次改代码前，要考虑各端的一致性」。口号无用，落成两层机制：

### 7.1 改代码前的三问（人读，写进项目记忆）

1. **这段逻辑另一端有没有副本？**
   → 有：必须同时改，或**收敛进 `packages/shared`**（首选）。定价、会员状态、日期格式、数值口径
     都已经吃过「副本各自漂移」的亏。
2. **这是「必须一致」还是「允许分叉」？**
   → 判据见 7.2。**允许分叉的必须写注释说明为什么**，否则下一个人会当成 bug「修好」。
3. **改了之后产物级验证做了吗？**
   → 测试绿 ≠ 产物对。压缩后变量名会变、中文会变 `\u` 转义、分隔符肉眼分不清（见 7.3 血泪教训）。

### 7.2 一致性分类表（哪些必须齐、哪些刻意不齐）

| 类别 | 要求 | 现有实现 / 判据 |
| --- | --- | --- |
| **数值口径** | 🔴 必须完全一致 | `src/lib/numfmt.ts` 唯一权威；禁止自己写 `toFixed`/`Math.round(n*f)/f` |
| **日期格式** | 🔴 必须完全一致 | `packages/shared/src/datefmt.ts` 的 `formatCnDate`；**禁止 `toLocaleDateString`**（各端 ICU 不同步） |
| **定价** | 🔴 必须完全一致 | `packages/shared` 的 `PRICE_*` + `priceTag()` |
| **会员状态文案** | 🔴 必须完全一致 | `packages/shared` 的 `memberSubText()` + `proUntilText()`/`proNoticeText()` |
| **权益规则（额度/阈值）** | 🔴 必须完全一致 | `packages/shared/src/rules/`（`FREE_REPORT_DAYS` 等） |
| **法务公示主体** | 🟡 **刻意分叉** | mini 连云库时公示 WorkBuddy 云平台；主端公示自建库+网关直连。回迁后须统一 |
| **额度降级策略** | 🟡 **刻意分叉** | 主端 `getPhotoQuota` fail-open 给满额；mini fail-closed `degraded:true` 显示「暂时读不到」不谎报 |
| **支付入口** | 🟡 **刻意分叉** | 主端有 IAP/微信/支付宝骨架；mini **刻意无任何支付入口**（法务已公示「不销售任何商品或服务」） |
| **AI 同意门** | 🔴 应一致但**两端各漏 2 处（合计 4 个页面）** | 见 A1（= 缺口 1）。实测无门清单：mini `onboarding`/`report` + 主端 `Onboarding`/`ReportScreen`；两端共 8 个页面调 AI。修复时必须四端同步；覆盖率由护栏 5 量化跟踪 |
| **原生能力降级** | 🟡 允许分叉 | 如 `isHealthConnectable()` 恒 false 是刻意诚实降级 |
| **体重变化展示** | 🟠 **功能覆盖差异**（第三类，见下） | 主端有「已减重/较起始」，mini 0 命中 → A10 待你定 |

> 🟠 **第三类：功能覆盖差异 ≠ 分叉**。7.2 原本只有「必须一致」与「刻意分叉」两类，
> 护栏 A5 扫出了第三类：**同一功能一端有一端没有**（体重变化展示、体重趋势图）。
> 处理规则不同 —— **分叉必须修**（同一功能两种行为 = bug），
> **覆盖差异必须做产品决策**（补，或明确写进文档记为刻意省略）。
> 二者都不能靠 grep 自动判定，靠的是「一端命中、另一端 0 命中」这个信号 + 人工定性。
> 定性时必须查全端（不能只看同名文件）：`mini/src/pages/profile/profile.tsx:6` 的注释
> 就明说了趋势图是刻意改用列表，而体重变化文案全 `mini/src` 搜「已减重|较起始」= 0，属未实现。

### 7.3 机器强制：一致性护栏测试（已落地，10 项全绿）

`tools/four-end-consistency.test.ts` —— 扫描两端**源码**（用字符级状态机剥离注释后匹配，
注释转等长空格以保行号），防分叉**复发**。6 道护栏 / 10 项断言：

| 护栏 | 断言内容 | 类型 |
| --- | --- | --- |
| 1 日期格式 | 剥离注释后两端零处 `toLocaleDateString`；且两端日期确实由 shared `formatCnDate` 提供（导入关系存在 = 副本未复活）；付费墙必须调 `proNoticeText()` | 🔴 零违规 |
| 2 定价 | 两端零处硬编码价格（`[¥￥]\s*\d`）；主端付费墙必须用 `priceTag(` / `PRODUCTS` | 🔴 零违规 |
| 3 数值口径 | 手写舍入（`Math.round(...*10...)/`）清单 == 已知基线 **7 处** | 🟡 快照式 |
| 4 会员状态文案 | 两端 profile 都调 shared `memberSubText()`；mini 额度降级须为 `quotaDegraded ? null` 且留说明注释 | 🔴 零违规 |
| 5 AI 同意门 | 无门页面清单 == 已知缺口 **4 个**；调 AI 的页面总数 == **8** | 🟡 快照式（量化跟踪缺口 1） |
| 6 刻意分叉 | mini 无支付入口、两端后端不同（法务公示主体）处**必须留说明注释** | 🔴 防被顺手抹平 |

> **为何 3 与 5 用「快照式基线」而不是「零违规」**：永远红的护栏等于没有护栏。
> 这两项的存量违规是既有代码/既有缺口，一次性清掉属**有产品影响的重构**（见 A9）或
> **需你拍板的合规方案**（见 A1）。快照式的语义是「**只准减不准增**」：
> 多一条 = 新增违规（红）；少一条 = 历史债已清理（也红，逼你同步更新基线，否则护栏失去侦测力）。
>
> 🔴 **放宽快照基线后必须做「红验证」**（11-04 已做）：临时往 `Onboarding.tsx` 注入一条
> `Math.round(x*10)/10`，护栏**精准报出 `src/pages/Onboarding.tsx:123,449`**（红）→ 恢复 → 转绿。
> 没做这步的话，「把基线从 4 条改到 5 条」可能顺手把护栏改成永远绿 = 等于删掉护栏。

> ⚠️ **本节初稿写了一条护栏「禁止硬编码免费额度数字（必须走 `FREE_REPORT_DAYS`）」，
> 代码里 0 处命中——是假承诺，现已删除。原因不是偷懒，是这条不该做成 grep 护栏：**
> 代码里「7 天」有 **5 种互不相干的语义**（免费报告额度 / 连续打卡满 7 天送奖励 /
> 奖励 7 天有效期 / Dashboard 近 7 天趋势窗 / 报告区间选项 `{days:7,label:'近 7 天'}`），
> 扫数字 7 会产生大量假阳性 → 护栏永远红 → 等于没有。把 `FREE_REPORT_DAYS`
> 与报告区间选项强行统一还会造出**错误耦合**（一个是权限阈值，一个是产品可选范围）。
> 替代保障：付费墙文案必须由 shared 产出，已由护栏 2（`priceTag`）与护栏 4（`memberSubText`）覆盖。
> → **教训：文档写「护栏会做 X」之后必须回代码 `grep -c` 验证 X 真存在**，否则文档成了假保险。

🔴 **血泪教训（2026-11-04）**：`toLocaleDateString('zh-CN')` 的分隔符是**斜杠 `/`（charCode 47）不是横线**，
输出 `2026/11/30`。终端字体把 `/` 渲染得几乎和 `-` 一样，**肉眼判断必然误判**——我上一轮就凭肉眼记错了。
若没抓出来会把线上文案悄悄改掉。护栏用 `charCodeAt(4)===47` 做永久断言。
→ **纪律：判断一致性只能靠布尔断言与追赋值链，不能靠肉眼 diff 压缩产物。**
