# 多端小程序独立工程规划（微信 / 支付宝 / 抖音）

> 状态：规划稿，待拍板后动工
> 日期：2026-10-19
> 结论摘要：**小程序独立成一个工程，覆盖微信、支付宝、抖音三平台；现有 Web / iOS / Android 三端零改动，与小程序工程并行独立演进。** 共享边界 = 云服务 + 业务规则（后端真相源）。

---

## 一、为什么「独立工程」而不是「四端合一」

1. 现有三端是 **React 18 + Vite 5 + Capacitor 8**，Capacitor 官方**只支持 iOS / Android / PWA，不产小程序**（小程序无 DOM / window / 标准 fetch，用 `wx.*` API）。
2. 若强行「四端合一」，必须把整套栈换成 Taro / uni-app，会导致：
   - UI 层（十几页 + 内联样式）基本重写；
   - 三个自研原生插件（`dbee-health` / `dbee-iap` / `dbee-origin-proxy`）要维护「Capacitor 原生 + 小程序」两套桥接；
   - 打断正在进行的 iOS 首发、Android 上架节奏，风险高、收益低。
3. 后端（云函数 + 云数据库）**本就是多端共用**，前端分开的代价被大幅稀释。

**结论：独立工程。** 三端继续用 Capacitor，小程序另起一套。

---

## 二、框架选型

| 维度 | uni-app（Vue3） | **Taro 4（React）✅ 推荐** |
|---|---|---|
| 三平台支持 | 微信/支付宝/抖音/百度/快手 | 微信/支付宝/抖音/京东 |
| 与现有技术栈 | 需换 Vue | 同为 React/TS，`lib/` 业务逻辑可几乎原样搬运 |
| 性能（首屏） | 接近原生（编译时） | 略逊（运行时），Taro 4 已改善 |
| 条件编译 | `#ifdef`（最细） | `TARO_ENV` |
| 团队上手 | 需学 Vue | 零切换 |

**推荐 Taro 4（React + TS）**，理由：团队 React 栈零切换；现有 `src/lib/` 纯业务逻辑（额度、兑换、报告、识别、文案常量）可复用。

> 性能考量可忽略：D-Bee 是「工具 + 打卡 + 记录」型应用，非超长列表 / 高频交互场景。

## 三、关键平台差异（条件编译的四个切入点）

### 1. 健康数据（⚠️ 最需警惕）

| 平台 | 步数能力 | 状态 |
|---|---|---|
| 微信 | `wx.getWeRunData` 微信运动步数 | **合规风险**：多个来源显示该接口已对普通小程序下线，仅白名单健康类应用可用；返回 encryptedData 需后端 session_key 解密 |
| 支付宝 | 无公开步数接口 | 手动录入 + 打卡兜底 |
| 抖音 | 无步数接口 | 手动录入 + 打卡兜底 |

**策略：步数降级可用，不阻塞上线。** 微信端尝试接入（需先确认资质），支付宝 / 抖音端走手动记录。

### 2. 支付

| 平台 | 接口 | 说明 |
|---|---|---|
| 微信 | `wx.requestPayment` | 需微信支付商户号 |
| 支付宝 | `my.tradePay` | 支付宝开放平台 |
| 抖音 | 抖音支付 | 抖音开放平台 |

三套支付后端都需接入，但可后置——小程序先上「积分兑换 + 兑换码」解锁（云函数 `redeem_honey` 已多端可用）。

### 3. 登录

| 平台 | 接口 |
|---|---|
| 微信 | `wx.login` → `jscode2session` |
| 支付宝 | `my.getAuthCode` |
| 抖音 | `tt.login` |

三者均为「拿 code 换 openid」模式，逻辑一致，仅换取接口与 openid 字段不同。

### 4. 分享

| 平台 | 机制 |
|---|---|
| 微信 | 转发 + 朋友圈 |
| 支付宝 | 分享面板 |
| 抖音 | 抖音分享（有内容合规要求） |

## 四、落地阶段规划

### 阶段 0：工程初始化（约 0.5 天）
- 新建独立目录 `zilv-mifeng-mini/`，Taro 4 初始化（React + TS + Sass）
- 三端编译脚本：`dev:weapp` / `dev:alipay` / `dev:tt`
- 搭建共享请求层：封装指向现有云服务（app `wbapp_w6iIU6TqTyHvJxESPTxBTy`）的 API 客户端

### 阶段 1：业务规则抽成共享真相源（约 1 天，最高优先级）
- 把 `src/lib/entitlement.ts`（`FREE_DAILY_AI=3`、`AI_REDEEM_DAILY_LIMIT=2`、`HONEY_PRICE` 等）、`photoGuard.ts` 阶梯、文案常量，沉淀为独立共享包 / 共享文档
- 目标：Web 与小程序引用**同一套规则定义**，杜绝「额度口径漂移」（历史痛点）

### 阶段 2：核心功能 MVP（首个版本）
按「不依赖健康数据 + 不依赖支付」原则：
- 登录（三端 code 换 openid）
- 打卡 / 手动记录运动、饮食、体重、饮水
- 拍照 AI 识别（`chooseImage` + 云函数识别，三端通用）
- 积分兑换（`redeem_honey` 云函数）
- 文字描述识别、条码扫描

### 阶段 3：平台差异化能力（条件编译补齐）
- 微信：`getWeRunData` 步数（先确认资质）、微信支付、转发分享
- 支付宝：`my.tradePay`、支付宝分享
- 抖音：抖音支付、抖音分享

### 阶段 4：上线与合规
- 三平台分别注册、提交审核（企业主体、类目资质、软著 / 备案）
- 微信运动数据、支付需单独资质，作为后置项

## 六、风险与注意事项

- 支付宝 / 抖音的组件与 API 行为与微信有差异（scroll-view 事件、picker 样式等），需真机双端联调，不能只测微信。
- 小程序主包 2MB 限制：Taro 运行时包体增量约 +150~200KB，需预留分包空间。
- 微信运动接口政策存在不确定性，接入前务必先查官方最新权限说明，勿硬编码假设接口可用。
