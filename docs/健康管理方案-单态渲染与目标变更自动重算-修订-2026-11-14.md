## 0. 本轮修订了什么

用户在同日对话中给出的产品指令：

> 我们叫健康管理方案，在用户第一次登录的时候，选择的减脂，就展示减脂的 sheet 页，其他页不展示；在使用过程中，用户可以从减脂改为增重，只要是确认后，系统能够自动调整健康管理方案。

本文件**替代**同日早版 `docs/体重管理方案-UI设计与实施步骤-2026-11-14.md` 的**交互模型**（三态 segment 可切换），早版的**视觉规格**（设计 token、像素尺寸、可访问性、三目标差异表、明确不做清单）继续有效，不重做。早版文档保留原文未改动，作历史快照。

| 维度 | 早版（三态 segment） | 本修订版（用户指令） |
|---|---|---|
| 命名 | 体重管理方案 | **健康管理方案** |
| 呈现结构 | 一个页面 + 3 个 segment，用户临时切换预览 | **单态渲染**：只读 `profile.goal`，仅挂载对应一张 Sheet，其余两态不进 DOM |
| 首次登录 | 未专门定义 | 选减脂 → **自动且只**展示减脂方案 Sheet |
| 改目标 | 跳 `ProfileScreen` 编辑，segment 切换不写库 | **页内「更改目标」→ 确认 → 写库 → 方案自动变为新目标态** |
| 切换语义 | 本地临时态，存在「显示态 ≠ 生效态」风险 | 单一真源，显示态恒等于生效态 |

设计判断：**取消 segment 是对的**。segment 会让用户误以为「切一下就改了目标」，实际不写库；也会让「方案页显示的 1650 kcal」和「首页还可吃用的 1650 kcal」出现两份状态。单态渲染从根上消除这个漂移。

## 3. 状态机与数据流

### 3.1 首次登录

```
Onboarding(step goal: 用户选 lose)
  → result: generatePlan({ goal: '减脂' })   [既有 AI 建议，不改]
  → finish(): saveProfile({ goal:'lose', 7 派生字段, onboarded:true })
  → onDone(saved) [App.tsx:241]
      ├ setProfile(saved) / setTab('today') / setStage('main')   [既有]
      └ 【新增】setHealthPlanIntroOpen(true)                       [一次性]
  → <HealthPlanSheet mode="intro" goal="lose" />
      仅渲染 lose 态；keep / gain 态不挂载、不在 DOM
  → 「开始记录」→ 关闭 + 写一次性已读标记
```

【必须】一次性判定用 `profile.onboarded` 由 false→true 的那一次 + 一个 `healthPlanIntroSeen` 本地标记（localStorage/sessionStorage 均可，**不新增数据库字段、不做迁移**）。老用户 upgraders 不弹（他们的 `onboarded` 早已为 true）。

### 3.2 使用中改目标（核心：「确认后自动调整」）

```
HealthPlanSheet(goal=lose) 底部「更改目标」
  → GoalChangeSheet  [复用 ProfileScreen.tsx:772 编辑 Sheet]
      本地草稿态 draftGoal（此时【禁止】写库）
      展示「会改变 / 不会改变」两栏
  → 点「确认修改」
      calcTarget({ goal: draftGoal, ... })        [既有，不重写]
      saveProfile({ 7 派生字段, goal: draftGoal }) [既有]
      onProfileChanged(saved) → App.setProfile(saved)
      【新增】setHealthPlanOpen(true)  ← 自动回到方案 Sheet
  → HealthPlanSheet 以新 profile 重渲染 = gain 态
      顶部轻量提示「方案已更新为增重增肌」（一条，不堆叠 toast）
```

**「自动」的实现保证 = 单一真源**：
- `HealthPlanSheet` 是 `profile` 的纯投影，**不持有 `selectedGoal` 本地 state**；
- `draftGoal` 只存在于 `GoalChangeSheet`，确认前不落库；
- `App.setProfile(saved)` 一次写状态，首页「还可吃」、报告页预测、方案 Sheet 三处同时更新，无需手动同步、无需刷新页面。

### 3.3 会改变 / 不会改变（确认层必展示）

| 会改变（从确认之日起） | 不会改变 |
|---|---|
| 每日热量目标、蛋白质/碳水/脂肪目标 | 已记录的饮食、体重、运动历史 |
| 每周节奏（lose −0.4 / gain +0.4 / keep 0 kg） | 已生成的 7 天 / 30 天报告与「上周小结」 |
| 目标体重（`keep` 时隐藏）与预计达成日 | 打卡、连续天数、徽章、蜜糖积分 |
| 方案页标题、主行、进度条 / 波动带 | 首次 AI 建议文案（标注为历史，见 5.3） |
| 今日「还可吃」上限 | 历史「还可吃」的当时判定（不回溯重算） |

## 5. 五条硬护栏（本轮新发现，必须写进护栏测试）

### 5.1 方案页读「已落库值」，不现场重算

`buildPlanView(profile)` **只读** `profile.daily_calorie_target` / `protein_target_g` / `carb_target_g` / `fat_target_g` / `weekly_rate_kg` / `target_weight_kg` / `goal`，**不调用 `calcTarget()` 现算**。理由：首页「还可吃」用的是落库值；若方案页现场算，两处口径会在浮点/下限/`roundTo` 上漂移，出现「方案说 1650、首页说 1648」。计算层全精度，`roundTo`（`src/lib/numfmt.ts` 唯一口径）只在展示层插值那一刻调用。

### 5.2 确认前零写库

`draftGoal` 是纯本地草稿。护栏：模拟「选中 gain 但未点确认」，断言 `saveProfile` 零调用、`profile.goal` 仍为 `lose`、方案页仍为 lose 态。

### 5.3 `plan_summary` 一致性（本轮最重要的新风险）

`Onboarding.finish()` 把 `generatePlan()` 的 AI 文案以 `JSON.stringify(plan)` 写进 `profile.plan_summary`（`Onboarding.tsx:200`）。改目标后**该文案不会重生成**，若方案 Sheet 引用它，会出现「增重增肌 · 1,950 kcal」配一段「建议制造热量缺口」的减脂文案 —— 自相矛盾，且是合规风险。

**规格决策（建议）**：`HealthPlanSheet` **完全不渲染 `plan_summary`**，只展示数值（5.1 的落库字段）。AI 首次建议留在 Onboarding `result` 步骤这一历史位置。若后续要展示，须标注「首次制定于 YYYY-MM-DD 的建议，仅供参考」并加护栏断言。

### 5.4 空档案兜底

`emptyTarget()` 的 `1800 kcal / 90 g` 是兜底常量（`nutrition.ts:87`），**禁止展示成真实目标**。`!profile.daily_calorie_target` 时 `buildPlanView` 返回「待完善」态：一句「先完善身体数据，才能生成方案」+ 跳编辑 Sheet 的按钮，不显示任何数字。

### 5.5 单态断言 + 命名断言

护栏扫描 `HealthPlanSheet.tsx`：不得出现 `.segment`、不得遍历 `Object.keys(GOAL_LABELS)`、不得渲染超过 1 个目标徽标；同时扫描四端用户可见文案，不得出现「体重管理方案」，不得新增底部 tab 项。

另外：`keep` 特例（`weekly_rate_kg=0`、`target_weight_kg = 当前体重`）沿用 `ProfileScreen.tsx:260-261` 既有逻辑，方案页不得显示目标体重/达成日。

1. **首次登录落点**：推荐 A「`onDone` 后落地 today 并自动弹一次方案 Sheet」（改动最小、可单独回滚、不动 Onboarding 5 步流程）；B「改 Onboarding `result` 步骤」会与既有 AI 计划展示混在一起，不推荐。
2. **`plan_summary`（AI 首次建议）**：推荐「改目标后不展示，且方案 Sheet 零引用」；备选「标注为历史建议」；不推荐「确认时重新生成」（消耗 AI 额度、需等待、且会把纯本地改动变成网络依赖）。
3. **改目标后行为**：推荐「自动弹回新目标态方案 Sheet + 一条轻量提示」；备选「静默更新、留在我的页」。用户原话「确认后系统能够自动调整」，倾向前者。

另需确认：波动带仍用 **±1.0 kg**；历史方案一期不做（需新表 + 0045 删号联动）。
