## 三、0051 迁移与执行

新增 `db/migrations/0051-meal-entries-updated-at.sql`，对齐 `0030` 既有口径：

```sql
BEGIN;
ALTER TABLE public.meal_entries
  ADD COLUMN IF NOT EXISTS updated_at timestamptz DEFAULT now();
-- DO $$ ... schema_migrations 台账 UPSERT ... END $$;  （幂等，0034 未应用时跳过）
NOTIFY pgrst, 'reload schema';
COMMIT;
```

设计纪律：① `timestamptz DEFAULT now()`、可空、不强制 NOT NULL，与其余 5 张表逐字一致；② 140 行小表，加列瞬时完成；③ 无触发器；④ 继承 RLS；⑤ 全语句幂等；⑥ 事务内 NOTIFY，COMMIT 后 PostgREST 重载 schema。

**执行方式**：SSH → `sudo -n -u postgres psql -v ON_ERROR_STOP=1 -d dbee -f -`，SQL 由本地经 stdin 传入，**服务器上零文件落盘、密码不打印**。

> 过程记录：首次尝试 `sudo -S` 时把密码写在 stdin 第一行，但生产 sudo 已免密，密码行被 psql 当成 SQL（仅报语法错误、库未受影响）；改为 `sudo -n` + 纯 SQL stdin 后成功。两次均先用 `SELECT 'pipe-ok'` 做无害机制复验。

执行输出：`BEGIN / ALTER TABLE / DO / NOTIFY / COMMIT`，`rc = 0`。

在服务器本机对 `http://127.0.0.1:3001/meal_entries?id=eq.-1` 发 PATCH。**`id=eq.-1` 恒不匹配任何行（identity 从 1 起）→ 零数据改动**。JWT 用 `/etc/postgrest/config` 的 `jwt-secret` 在服务器内现签（密钥不出服务器、不打印），role=`authenticated`。

| 探针 | HTTP | 响应 |
| --- | --- | --- |
| **RED**：`{"definitely_not_a_column_xyz":1}` | `400` | `{"code":"PGRST204","message":"Could not find the 'definitely_not_a_column_xyz' column of 'meal_entries' in the schema cache"}` |
