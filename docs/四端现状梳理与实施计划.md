| 端 | 数据面实际指向 | 说明 |

## 三、分阶段实施计划（按新前置条件重排优先级）

### 阶段 A · 苹果端（用户指定优先；Windows 可做的已做完，剩部署与 Mac 清单）

**A1（立即可做，无需任何外部条件）— 服务器部署 IAP 链路**
1. 服务器执行 `0037-apple-iap-settlement.sql`（先 `pg_dump` 备份，走既有流程）；
2. `deploy/deploy-gateway.sh` 重新部署网关（本轮 iap.mjs/app.mjs/config.mjs 改动上线）；
3. 网关 env 配 `APPLE_BUNDLE_ID=com.dbee.app` + `APPLE_SHARED_SECRET`（App Store Connect → App 信息 → 共享密钥；**账号侧现在就能生成**）+ `APPLE_SANDBOX=1`（提审期）；
4. 部署后验证：`curl -X POST http://127.0.0.1:8080/.cloud/payment/apple/verify`（无 Bearer → 401 即通）；`iap-selftest` 已在本地过，服务器侧只需冒烟。
> 验收：verify 端点 401/503 语义正确；0037 验证段 4 条查询符合期望（见迁移文件尾注释）。

**A2（Apple 账号侧，现在就能做，不依赖对公账户）**
1. App Store Connect 创建 App（`com.dbee.app`）；
2. 配 3 个内购商品：`dbee_pro_monthly`(¥18 自动续期订阅) / `dbee_pro_yearly`(¥128 自动续期订阅) / `dbee_lifetime`(¥328 非消耗型)——**商品 ID 必须逐字符一致**（`packages/shared/src/constants/index.ts` PRODUCT_IDS）；
3. 生成共享密钥 → 回填 A1-3；
4. 评估**个人→公司账号迁移**（Apple 支持组织转移，需邓白氏编码 D-U-N-S，申请约 1–2 周，**建议现在就启动**，与对公账户并行）。

**A3（Mac 到手后，硬步骤清单——详见 `苹果iOS端-发布梳理与清单.md` §九B）**
1. `npm install && npx cap sync ios` → Xcode 编译 3 个 Swift 插件（dbee-iap/dbee-health/origin-proxy），修首次编译错误；
2. Signing：登录 Apple ID → DEVELOPMENT_TEAM → 加 In-App Purchase capability；
3. 沙盒账号真机走通「购买 → 验签 → 权益到账 → 恢复购买」全链（网关 `APPLE_SANDBOX=1` 已支持）;
4. Archive → TestFlight → 提审。
> 银行/税务信息可对公账户下来后补填；**填全之前商品不可售，但不阻塞提审准备**。

**A4（依赖备案+HTTPS）**
- webhook URL 配置：App Store Connect → Server Notifications V2 = `https://d-bee.com.cn/.cloud/payment/apple/notifications`；
- 数据面切换：`VITE_NATIVE_ENDPOINT=https://d-bee.com.cn npm run build`；
- Associated Domains（微信 Universal Link 回跳）。

### 阶段 B · Android + 华为/小米（开发者已通过，可立即启动）

**B1 — APK 产出与真机验证（立即可做）**
1. 用户本机执行 `cd android && ./gradlew assembleRelease`（签名配置已就绪；沙箱拦截 `.gradle` 缓存故由用户跑，或授权后我跑）；
2. 真机安装冒烟：登录/记录/AI 识别/健康步数（web 数据面已在服务器，Android 当前连云库，功能应全通）。

**B2 — 华为账号侧申请（立即可做，与上架并行）**
1. AGC（AppGallery Connect）创建应用（包名对齐 `capacitor.config`）；
2. 开通 Health Kit，申请**步数/热量**（基础数据 scope）；
3. 配置签名证书指纹（**用本轮生成的 `android/keys/dbee-release.keystore` 导出 SHA256**——指纹与 keystore 绑定，先配好，上架后不用改）；
4. `src/lib/health/brand.ts` 已能识别 huawei → 接入层按 `华为HealthKit接入方案.md` 补 adapter。

**B3 — 华为应用市场上架（Health Kit 的硬门槛）**
1. 软著（建议现在就申请，各商店都要，周期 1–2 个月，可加急）；
2. ICP 备案号（依赖阶段 D）；
3. 隐私政策/权限说明已有（`src/content/legal.ts`）；
4. 上架审核通过后 Health Kit 数据权限才真正可用 → 华为健康步数同步功能全量开放。

**B4 — 小米**
1. 小米开放平台创建应用 + 签名指纹；
2. 小米应用商店上架（同样要软著+备案）；
3. 小米穿戴/健康数据接入按其开放平台文档补 adapter（优先级低于华为，用户量级决定）。

### 阶段 C · 微信小程序（appid 已有，等对公+备案）

1. **微信支付商户号**：必须企业主体 + 对公账户 → **对公账户下来后立即办**（周期约 1 周）；
2. 小程序类目复核：健康管理类目在企业主体下重审（个人主体可选类目少）；
3. 支付接入：`mini` 端补 miniprogram adapter（`checkout.ts` 的 TODO 位）+ 网关补微信验签分支（`verify_payment_order` provider=wechat，复用 0037 的 settle 模式另建函数）；

### 阶段 D · 备案与域名（全局解锁项，建议最优先跟进外部流程）

1. **ICP 备案**：企业主体已注册 → 立即提交「个人→企业变更」或新备案（腾讯云流程，7–20 个工作日）；⚠️ 备案期间 `d-bee.com.cn` 保持无解析；
2. 备案生效 → DNS 加 A 记录 `d-bee.com.cn` / `www` → 150.158.51.106；
3. `bash deploy/deploy.sh https`（certbot，nginx 域名已预认领，脚本现成）；
4. HTTPS 就绪后**一口气解锁**：三端数据面切换（1.2 节）、iOS ATS、webhook URL、微信合法域名、各商店上架材料；

### 阶段 E · 安全加固（穿插做，不阻塞业务）
