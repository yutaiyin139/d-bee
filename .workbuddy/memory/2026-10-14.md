## 15:19 评估「先用微信小程序登录」路线

- 用户问：企业主体注册推进中，能否先用微信小程序解决微信登录。
- 结论：**要拆成三个目标看**——① Web/PWA 微信登录（已可用，与小程序无关）；
  ② 原生 App 内微信登录（**小程序解决不了**：个人主体无法绑定微信开放平台 → 无 UnionID →
  App 与小程序身份无法打通；且小程序运行时不存在于 App 内）；③ 微信生态独立入口（可行，
  个人主体即可启动）。
- 关键认知：目标②卡住的真正原因是**云端能力缺口**（signInWithWechat 只吃小程序
  jscode2session，移动应用 code 需 sns/oauth2/access_token），与微信资质无关；
  即使企业主体到位、拿到移动应用 AppID，云端不补接口仍跑不通。
- 新提出的**路线 B（推荐用于解 App 登录）**：App 不调微信 SDK，改用系统浏览器打开云 Relay
  OAuth 扫码页 → 回跳已备案 HTTPS Universal Link → 深链回 App 换会话。
  **完全不需要微信开放平台移动应用资质**，绕开企业主体依赖；前置是 d-bee.com.cn 备案
  （同时也是 App 备案的共同前置）+ 需云方确认 redirectTo 白名单。
- 小程序（路线 A）天花板：不能开微信支付、无 UnionID、医疗健康类目为个人主体禁区
  （D-Bee 需按「工具/生活记录」报备）；且小程序备案同样强制（7–20 工作日），
  绕开的只是开放平台移动应用审核。主体变更（个人→企业）微信支持，但老用户需重新关联。
- 产出：docs/微信登录-小程序路线评估.md（含可直接发给云服务方的 3 个确认问题）
