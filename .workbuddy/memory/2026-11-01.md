### 为什么上轮的 `.catch()` 完全没接住（机制级根因）
Capacitor core 8.5.3 `addListenerNative`：
```js
const call = addListener({eventName}, callback)          // → nativeCallback → toNative
const p = new Promise((resolve) => call.then(() => resolve({ remove })))
//                                   ↑ call.then() 无 rejection handler
```
两条致命路径：
- `cap.toNative` 返回的是 **`callbackId` 字符串**（`native-bridge.js:913`）而非 Promise → 对非 Promise 调 `.then` = **同步 TypeError**
- native 侧 `addListener:` 只 `setKeepAlive:TRUE` 存 listener、**从不 resolve/reject**（`CAPPlugin.m:105-109`）→ 失败时 `p` **永久 pending**，挂在链尾的 `.catch()` 永不触发

→ 教训：**链尾 `.catch()` 不等于「所有失败都被兜住」**。必须对「同步抛错」+「返回非 Promise」+「p 自身 reject」三路都设防。

### 🔴 面板自身致命缺陷（解释了为何连续两轮拿不到错误文本）
`index.html` 原为 `show(…, r.stack || r.message)`：
- V8（Android/Chrome）的 `error.stack` **首行含 message** → 短路无害
- iOS 用 **JSC，`error.stack` 只有调用帧、不含 message** → `stack` 存在即短路，**message 永远丢失**

后果：连续两轮（14:5x 与 16:20）都只拿到栈帧、拿不到具体错误内容，被迫发明列号映射法反推，排障成本翻数倍。已修 `describe(r)`：message 与 stack 分开取，stack 不含 head 时拼接。
👉 **通用教训：跨引擎错误上报绝不能 `stack || message`**，这是「Android 上好好的、iOS 上啥都看不到」的典型成因。
