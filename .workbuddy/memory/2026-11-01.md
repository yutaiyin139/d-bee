**根因（非项目缺陷，是文档/沟通缺陷）**：10-31 日志「给 Mac 侧的指令」写成
`git pull → npm ci → cd packages/shared… → …`，其中 **`→` 是文档箭头分隔符，不是 shell 语法**。
用户整行粘贴后：①`git` 把 `→`/`npm`/`ci` 当 refspec → `fatal: '→' does not appear to be a git repository`；
②**`npm ci` 被一并吞成 git 参数、根本没执行** → 依赖未安装；③`sh: vite: command not found` 是 ② 的直接后果。
⚠️ 注意 `postinstall` 已含 `cd packages/shared && npm run build`，故 `npm ci` 成功后 shared 会自动构建，**无需手动再 cd 进 shared**。

**已更正**：10-31 日志该段加删除线 + 红字警示 + 正确代码块（逐条独立执行）。手册 §七 一页速查本就是逐行命令、写法正确，无需改。

**教训（长期价值，已入 MEMORY.md）**：给用户的可执行指令**必须放代码块、一行一条命令**；箭头/序号等排版符号只能出现在**正文说明**里，绝不能出现在会被复制粘贴的命令序列中——用户会照抄，且失败信息（`fatal: '→'`）看起来像仓库权限问题，极易误导排查方向。
