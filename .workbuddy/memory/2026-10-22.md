### 备案「个人 → 企业」变更的坑（阿里云/华为云官方 FAQ 查证）

🔴 **各省管局规则不一致，部分省份不允许个人主体直接变更为企业主体**。两种走向代价差别大：

| 走向 | 网站是否中断 | 周期 |
|---|---|---|
| 管局**允许**直接变更主体 | 不中断，审核期可正常访问 | 约 1–2 周 |
| 管局**不允许** → 注销原备案 + 企业重备 | ⚠️ **注销后域名停解析，直到新备案通过** | 注销 3–5 工作日 + 重备全流程（初审 1–2 + 管局 1–20） |

**行动清单**：
- 先在腾讯云备案控制台确认本省是否允许直接变更（控制台会直接提示）
- **域名必须先过户到公司名下再提交**——管局核对 WHOIS 持有者与备案主体一致，没过户必被驳回
- **关闭域名 WHOIS 隐私保护**，否则备案系统读不到真实持有者
- 变更前后**备案主体须同省**，且目标企业名下**不能已有备案成功的信息**
- 若被迫走「注销重备」：**先把泳道 A4 切换做完并验证 IP 直连可用**，再注销备案，这样停站期业务不断
- 部分省份卡「原个人主体身份证与现企业法人须同一人」——本项目同一人，天然满足

### 本轮修复的三处真实缺陷（都不是改测试蒙混，是代码本身错）

1. 🔴 **LLM 段挂死（导致自测 SIGTERM 空输出的根因）**：`app.mjs` 的 `wrap()` 已 `await ctx.readJson()`
   消费请求流并把 body 作第三参传入，但 `llm.chatCompletions` 忽略第三参、**自己又 `readBody(req)` 二次读流** →
   流已 `end`，二次读永远等不到 data/end 事件 → **Promise 永不 resolve → 整个测试进程挂住**，
   被工具超时 SIGTERM 杀掉，Windows 管道下 stdout 缓冲丢失所以「空输出」。改用 wrap 传入的 body 即愈。
   （教训：Windows 下排查挂起要「watchdog 自杀 + 输出重定向到文件」，管道 + SIGTERM 会看不到任何线索。）
2. 🔴 **`newOwnerId()` 同毫秒碰撞**：13 位时间戳 + **6 位纯随机**后缀，5000 次生成撞 3 次
   （生日悖论，期望 ~12 次）。`owner_id` 是主键，撞号即数据错乱 → 改为**进程内单调序列**：
   时钟前进时重置为随机起点（保留不可预测性），同毫秒内递增，时钟回拨时冻结 ms 继续递增，绝不复用已发号。
3. 🔴 **`ensureUser` 的「撞号重试」形同虚设**：注释说撞 owner_id 会换 id 重试，但 SQL 写的是
   `ON CONFLICT (ident_kind, ident_hash)`——**只捕获身份唯一键冲突**；真撞主键会抛 23505 冒泡成 500，
   重试逻辑根本到不了 → 改**通用 `ON CONFLICT DO NOTHING`**（覆盖所有唯一约束），
   由回查区分：查得到 = 标识已存在的老用户（`created:false`）；查不到 = 仅 owner_id 撞了 → 循环换新 id。

### 安全要点（设计即落地，非事后补）

身份只存 HMAC-SHA256(+PEPPER) 哈希（11 位手机号空间仅 10^11，**无 PEPPER 可穷举反查**）；
JWT 手写 HS256（node:crypto，先验签再解析，`timingSafeEqual` 常量时间比较，30s leeway）；
refresh_token 用不透明随机串 + 内存旋转吊销；OTP 只存 HMAC 不存明文、试错上限 + 一次性消费 + token 用过即焚；
`config.validate` 启动期就拒「短密钥 / 缺 PEPPER / PEPPER=JWT_SECRET / 生产用开发占位符密钥 / 生产 + SMS_PROVIDER=log（万能码=任何人可登任何号）」；
连接池业务角色 `dbee_app` 与身份角色 `dbee_gateway` 分离（PostgREST 被打穿也读不到身份哈希）。
