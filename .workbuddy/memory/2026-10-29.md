**🔧 修复的关键 bug（首测报 `⚠️溢出`，手机组 452 未缩放）**：
- 根因：`.phones` 作为 flex 子项默认 `min-width:auto`，被内容撑到不收缩 → `clientWidth == scrollWidth` → `fitPhones()` 的 `need > avail` 永远为假，缩放从不触发，总宽 1018 > 960 被 stage 裁掉。
- 修法①：`.phones` 与 `.phone-stack` 显式 `min-width: 0`。
- 修法②：测量改用各 `.phone` 的 `getBoundingClientRect` 并集，**不用 `scrollWidth`**——后者不含 `transform: scale/translateY` 与负 margin 的视觉影响，与溢出检查（看视觉 rect）口径不一致。
- 修法③：**不要**给 `.phones` 加 `overflow:hidden`（一度加上又移除）——会把手机投影硬切成直边。

## 🔴 生产缺陷：自建网关从未实现密码登录（web 端全部设密用户登录即 400）

**发现方式**：用户在 web 端用审核演示账户 `dbeesupport@163.com` 密码登录，实测报
**400「缺少 verification_token」**。

**根因**：主端切自建网关时只实现了验证码登录。`server/lib/auth.mjs` 的 `signIn` 拿不到
`body.verification_token` 就直接拒；而 SDK `signInWithPassword` 上送的是
`{username, password}`（已从 dist 产物内 SDK 实现核对线格式）。`identity.mjs` 的
`verifyPassword()`（scrypt）**早已写好却从未被 import** —— 典型的「后端半截子」：
前端入口、SDK、哈希校验函数三处都齐了，只有路由分支缺失。

**影响面**：不止演示账户 —— web 端**所有设过密码的用户**都登不进去。演示账户还另有
审核后果（审核员拿不到我方邮箱收信权限，只能走密码登录 → Apple Guideline 2.1 拒审）。

**修复要点**（commit `8d4a0ef`）：
- `signIn` 按「有 password 且无 verification_token」分流到新增 `signInWithPassword`；
  原验证码路径逐字保留（含「不信任 body.username、以 token 内锁定标识为准」的防越权设计）。
- **标识归一化是隐性大坑**：SDK 手机侧发的是 `normalizePhone` 过的 `+86 138…` **带空格**形态，
  而库内 `ident_hash` 按**裸 11 位**算 → 不归一化 100% 查不到人。邮箱统一小写化。
- 防枚举：账户不存在 / 密码错 / 未设密码（`password_hash` NULL）**一律同文案 401**，且查无此人时
  仍对 `DUMMY_PASSWORD_HASH` 跑一次 scrypt 保持**恒定耗时**（否则可用响应时间差枚举注册账户）。
- 双维度限流：标识 10 次/15 分钟 + IP 30 次/15 分钟，锁定期间正确密码也拒，成功后 reset。
- `identity.mjs` 用**独立函数** `findUserWithPasswordByIdent`（而非给 `findUserByIdent` 加列），
  避免 `password_hash` 泄露到只读查询面。
- 日志只落掩码标识与成败，绝不落密码明文/哈希。

**验证**：新增 `tools/selftest-password-login.mjs`（10 组 **35 项断言，35/35 通过**，含验证码路径
回归完好、access-key 校验仍生效、参数类型异常不抛、日志不泄露）；线上实测 signin → 200 +
access_token（`sub` 与库内 owner 一致）、`user/me` 200、`profiles`/`meal_entries`/`honey_ledger`
带 token 读取 200、错误密码与不存在账户同文案 401、缺参 400。
