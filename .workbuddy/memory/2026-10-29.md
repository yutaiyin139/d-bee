## App Store 创意素材（Creative Assets）出图 — 完成（10:00）

**需求出处**：用户给出三个尺寸 5244×2950 / 3840×2560 / 1920×1280 要求出「产品页面信息图片」。

**查证结论（Apple 官方《Creative assets specifications》+ 3 个第三方源）**：这三个尺寸属于**创意素材**规格，不是设备截图槽位——
- 16:9 通用素材 5244×2950（产品页面标题 / 搜索结果，**仅 PNG**）
- 3:2 搜索结果图 最大 3840×2560 / 最小 1920×1280（PNG 或 JPEG）
- 硬性约束：**不得含 alpha 通道或透明度**（带 alpha 的 PNG 即使视觉不透明也会被拒）
- ⚠️ 与已交付的 10 张设备截图（iPhone 6.3" 1179×2556 / iPad 13" 2048×2732，提审必填）是**两套独立资产**；竖屏 0.46 vs 横版 1.78/1.5，比例不同**不可互相缩放顶替**。

**新增文件**：
- `creative-assets.html` — 横版营销页。品牌视觉（`--honey:#f2a93b` 等取自 `src/styles.css`）；`?ratio=16x9|3x2` 双布局（16:9 三台手机 / 3:2 两台）；`?variant=N` 三套文案；全 `vw` 单位使同一份 DOM 等比适配两种画布；`file://` 直开（相对路径引截图）；底部合规角标。
- `deploy/shot-creative.mjs` — CSS viewport = 目标像素/2 + `deviceScaleFactor=2` 得精确像素；`--only` / `--variants` 参数；溢出检测；PIL `stripAlpha()` 转 RGB 落盘。

**🔧 修复的关键 bug（首测报 `⚠️溢出`，手机组 452 未缩放）**：
- 根因：`.phones` 作为 flex 子项默认 `min-width:auto`，被内容撑到不收缩 → `clientWidth == scrollWidth` → `fitPhones()` 的 `need > avail` 永远为假，缩放从不触发，总宽 1018 > 960 被 stage 裁掉。
- 修法①：`.phones` 与 `.phone-stack` 显式 `min-width: 0`。
- 修法②：测量改用各 `.phone` 的 `getBoundingClientRect` 并集，**不用 `scrollWidth`**——后者不含 `transform: scale/translateY` 与负 margin 的视觉影响，与溢出检查（看视觉 rect）口径不一致。
- 修法③：**不要**给 `.phones` 加 `overflow:hidden`（一度加上又移除）——会把手机投影硬切成直边。
- 附带收紧：缩放下限 0.55 → 0.5。

**实证验证（不止看命令成功输出）**：
- 重跑 `--only 3x2-min`：溢出标记消失，手机组 452 → **333**（缩放生效，scale 0.8471）。
- 全量 3 张出图，页面报错 **0 条**；三种画布 scale 分别 0.8109 / 0.846 / 0.8471。
- PIL 复核：尺寸**精确** 5244×2950 / 3840×2560 / 1920×1280；mode 均为 **RGB（无 alpha）**；**无 transparency 块**；色数 25066 / 19780 / 14296；3394 / 2406 / 859 KB。
