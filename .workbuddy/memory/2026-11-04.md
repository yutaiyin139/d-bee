### 🔴 最重要的发现：vitest 并行会「假绿放行」，推翻 11-03 的记录
- 11-03 六次采样曾校准出「有 EPERM 时 exit=1，不会假绿放行」→ **今天实测 exit code = 0**。
  vitest 把 EPERM 归入 `Unhandled Errors` 打印但**不影响退出码**，被卡的测试文件完全不统计。
- 同一份代码实测对照：并行 `8 files / 150 tests`（假绿）vs 串行 `10 files / 190 tests`（真相），
  **丢 2 个文件 40 项测试**。
- 📌 教训升级：**「exit code 会不会非零」必须显式 `echo $?` 验，不能凭有无报错输出推断**
  ——11-03 那六次很可能就是看了 stderr 有字便判 exit=1。
- 📌 `rm -rf node_modules/.vite` **无效**（清缓存后并行照旧假绿），MEMORY.md 旧记录已纠正。
- 修法选在 `vite.config.ts` 而非 `package.json` 的 `test` 脚本：脚本参数只覆盖 `npm test`
  一条路径，`npx vitest run xxx` 与 IDE 测试按钮仍会假绿。代价 15.9s vs 9.4s。
