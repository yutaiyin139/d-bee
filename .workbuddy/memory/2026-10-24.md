## 12:20 iOS「拍照后没进识别」根因定位 + 修复（resultType 大小写 bug）

- **症状**：拍照功能已能用（上一轮 Info.plist 权限已修），但拍完照返回后**没进识别**——无 preview、
  无「正在识别」、无报错，界面像什么都没发生。
- **根因（iOS 独有，确凿）**：`src/lib/capture.ts` 调用 `camera.getPhoto({ resultType: 'DataUrl', ... })`，
  传的是**大写 D**；而 `@capacitor/camera` iOS 侧 `CameraResultType.dataURL` 的 rawValue 是 `"dataUrl"`
  （小写 d，`CameraTypes.swift:19`），`CameraResultType(rawValue: "DataUrl")` **大小写敏感匹配失败**
  → 回退默认 `base64`（`CameraTypes.swift:39`）→ 原生返回 `{ base64String, format, saved }` 而非 `dataUrl`。
  - `capture.ts` 只读 `photo.dataUrl`，拿到 `undefined` → `if (!dataUrl) return null` **静默返回 null**
    → `handlePickMealPhoto` 里 `if (f) handleFile(f)` 因 f=null 直接跳过 → 「无反应」。
  - **为何 Android 没事**：Android `LegacyCameraFlow.java:249` 用 `resultType.toUpperCase(Locale.ROOT)`
    再 valueOf，`"DataUrl"`→`"DATAURL"` 能匹配；iOS 是精确大小写匹配，所以只有 iOS 中招。
- **修复**（`capture.ts`）：
  1. `resultType: 'dataUrl'`（改成官方正确的小写 d）；
  2. 兜底兼容：`const dataUrl = photo.dataUrl ?? photo.base64String`，双形态都能读；
  3. 新增 `dataUrlToBlob()`（data: 前缀走 fetch blob，纯 base64 走 atob 解码）；
  4. catch 区分「用户取消」（/cancel/i）与「异常」，异常打 `console.error` 不再静默。
  - typecheck 通过。
- **教训入册**：鸭子类型探测接口的字段名/枚举值必须与官方插件源码逐一核对（大小写、字段名），
  不能凭 `definitions.d.ts` 的 TS 枚举（`CameraResultType.DataUrl = "dataUrl"`，值是"dataUrl"而非"DataUrl"）
  直觉写字面量；且 `getPhoto` 在 8.2.6 已 `@deprecated`（新 API 是 `takePhoto`，返回 MediaResult 无 dataUrl），
  后续可考虑切新 API 彻底规避。
