  （ok/empty/denied/error/unavailable/not_ready/no_plugin）+ `isUsableHealthStatus()`。
  Swift `fetchToday` 从「错误吞成 0」改为如实上报：分别捕获步数/能量两路查询的 error，
  `HKError.errorAuthorizationDenied|NotDetermined` → denied，其它 → error，成功但无样本 → empty。
  `requestAuthorization` 系统错误由 reject 改为 resolve + reason（unavailable/no_types/system_error）。

  异常态改为显示 `healthStatusHint()` 的引导文案（三处调用点共用同一措辞）。
- **OriginProxy 支持中途取消**：iOS/Android 插件各加 `cancel(streamId)` 方法 + 在途请求注册表
  （Swift 用 NSLock 保护的 `[String: URLSessionTask]`，Java 用 ConcurrentHashMap + volatile cancelled 标记 +
  disconnect 打断阻塞 read）；两端都把「主动取消」归一为 End 事件而非 Error（对 JS 是正常收尾）。
  注册表条目在 finally 里移除，否则 map 随请求数无限增长。
  JS 侧 `nativeFetch` 取 `init.signal ?? request.signal`，`nativeStreamFetch` 挂 abort 监听 →
  调原生 cancel + 关流 + 丢弃取消后到达的事件；`ReadableStream.cancel()` 也走同一路径（reader.cancel 时
  同样要终止原生连接，否则 LLM 回答会一直泵到超时）。取消异常**不回退缓冲重发**（否则会重复扣 token）。
  缓冲 `request()` 无 streamId 不可真取消，`withAbort` 只让 JS Promise 立即以 AbortError 收尾。
  方法探测统一走 `nativeHasMethod(name)` 读 PluginHeaders —— Capacitor Proxy 对任意方法名都返回函数，
  `typeof` 探测恒真不可靠。
- **iOS 付费墙禁用兜底价**：`PaywallSheet.tsx` 新增 `iosPriceState`（loading/ok/error）。
  商店价格拉取失败（adapter 缺失 / products 为空 / 缺任一在架商品 / 抛错）时 iOS **禁用购买按钮**并显示

  理由：商店价才是唯一合法成交价，展示与实际扣款不符的静态价既误导用户，也可能被审核认定为价格欺诈。
  Android/Web 不受影响（它们本来就用 PRICE_TAG 走微信/支付宝）。
