- 排查路径：`ls` 目录不存在 → 探针实验（写 probe.txt 存活）→ 排除备份 cron（03:30 才跑）、path 单元、脚本自删（grep 无任何 rm/unlink）→ YunJing 日志给出决定性证据：

- **机制**：`publish-apk.sh` 把 `REMOTE_DIR=/var/www/d-bee/download` 以环境变量传给 **Windows 原生 python.exe**（`~/.workbuddy/binaries/python/3.13.12`）。MSYS 对「值以 `/` 开头且像 POSIX 路径」的环境变量做自动路径转换 → python 侧收到 `C:/…/PortableGit/var/www/d-bee/download`。SFTP 视其为**相对路径** → 文件写进 `/home/ubuntu/C:/…` 嵌套垃圾树。上传回读用同一个污染路径所以「sha 一致」；verify 用 bash 展开的正确路径 + HTTP 实测所以全红。**「上传绿、验证红」的矛盾正是路径分裂的指纹。**
- 本机 30 秒实验复现：`REMOTE_DIR=/var/www/d-bee/download python -c "import os;print(os.environ['REMOTE_DIR'])"` → 输出 `C:/…/PortableGit/var/www/d-bee/download`。argv 传参同样中招（`python -c … "/var/www/…"` 也被转换）。
- 🔴 **新坑（编号＝㉒，⑳㉑ 已被 11-22 占用）**：**在 Git Bash 里把 POSIX 远端路径经「环境变量或 argv」传给 Windows 原生可执行文件，必被 MSYS 静默转换**。防法：加非 `/` 开头的哨兵前缀（如 `RDIR@@`）+ 接收端剥哨兵并硬校验 `startswith("/")`。`REMOTE_CMD="sha256sum '/var/www/…'"` 这类**不以 `/` 开头**的值不受影响（已实测原样到达）。
