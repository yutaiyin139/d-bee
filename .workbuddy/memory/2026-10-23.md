### 🔴 纠正一条错误记忆（重要）
之前多处记「PG 仅监听 127.0.0.1:5432」——**错**。实测 `listen_addresses = '*'`，
postgresql.conf 第 60 行显式 `listen_addresses = '*'`，且**公网 5432 TCP 可达**
（本机 Test-NetConnection OPEN）。ufw 也 inactive。
缓解现状：pg_hba 只放行 `127.0.0.1/32`、`::1/128`、以及 `114.254.3.0/24`（用户家宽段，
供远程 psql，见 docs/自托管数据库远程连接指南.md）→ 其他公网 IP 连到 TCP 后会被 pg_hba 拒
（no pg_hba entry），**数据不直接泄露**。但这是无谓攻击面。
→ 生产化建议：`listen_addresses` 收回 `127.0.0.1`（网关 + PostgREST 都走回环，不需要对外），
  或在腾讯云安全组关掉 5432 入站。远程调试要连时再临时开。

### pg_hba 现有生效规则（存档）

local replication all            peer
host  replication all 127.0.0.1/32 scram-sha-256
host  replication all ::1/128      scram-sha-256

### 踩到并已修的两个坑（都是本机 Git Bash ↔ Windows 原生 Python 的路径/守卫问题）
1. **云端域名守卫误杀**：模板注释里解释性地提到 `workbuddy.host`（说明云端版为何改写 Origin），

   （`mktemp -t` 会拼出混合分隔符的带盘符路径，是最早触发 safe-delete 的原因。）
