### 根因（两处，都在 mini 前端；网关与 0053 已于 11-17 落地，非本次问题）

- **缺陷①「连接后不刷新」**：`connectHealth()` 其实**已经**从网关拿到了解密后的 steps，但只把它拼进「已连接，今日 N 步」的**提示文本**里返回；调用方 `profile.tsx` 只 `showToast(message)`，**没有任何 state 承接这个数字**，而 `SmartDeviceSheet` 的 `liveSteps` 只在组件初始化时读一次缓存 → 用户看到的仍是旧值/占位符。
- **缺陷②「登录不实时」**：`syncFromHealth()` 被硬编码成**只读本地缓存**（`readWechatStepsCache()`），而缓存只在用户**主动点「连接微信运动」**那一刻才写入。这条硬编码源于**误读平台规范**——真实规则是「**授权弹窗**必须由用户操作触发」（不得在生命周期里弹窗），**不是**「每次读取都要用户点一次」。**已授权用户完全可以零弹窗静默读取**。因此每次登录/进入首页都只能拿到陈旧缓存，永远不实时。

### 🔴 为什么 60s 轮询**不能**做实时同步

轮询若也实时，＝**每分钟一次** `wx.login` + 一次网关 `jscode2session` 调用 → 撞微信频控（errcode **45011**）→ 整个登录链路降级 503。且微信运动数据**本身只在用户进入小程序时更新**，高频轮询拿不到更新的数据。故：实时只在**登录/进入**两个真时机，轮询读缓存。

### 🔴 去重修复（避免双倍 wx.login）

首版实现在 `useDidShow` 的登录分支里也调了 `refreshHealth(true)`，而 `setLoggedIn(true)` 会让 `useEffect[loggedIn]` 立即跑一次实时刷新 → **登录瞬间两次 `wx.login` + 两次网关解密**，与「轮询特意降级读缓存以避频控」的设计自相矛盾。修法：① 登录分支**刻意不调** `refreshHealth`（交给 `[loggedIn]` effect）② 进入分支包 `shownOnceRef.current` 守卫——冷启动 `onLoad` 与 `onShow` 会先后各触发一次，首刷由 `[loggedIn]` effect 负责，`useDidShow` 只在**非首次**（tab 切回 / 热启动）才实时刷，这正是用户反馈的「在『我的』连完微信运动切回首页，步数不更新」场景（**tabBar 页返回不 remount**）。

## 🔴🔴 HC-2 真机闪退复盘：小米 15 Ultra 点「连接运动健康」即崩（21:20）

用户实测 vc27 HCTEST 包 → **闪退**。根因是**确定性代码缺陷**，非机型兼容性问题。

### 根因（已读 Capacitor 8.5.3 源码实证，非推测）

`@ActivityCallback` 回调签名写错了。Capacitor **3+ 起契约是 `(PluginCall, ActivityResult)` 两参**，
我沿用了旧版 `(PluginCall, int, Intent)` 三参。`Plugin.triggerActivityCallback()` 实测实现：

```java
method.setAccessible(true);
method.invoke(this, savedCall, result);        // ← 只传 2 个参数
} catch (IllegalAccessException | InvocationTargetException e) { e.printStackTrace(); }
```

三参方法被两参反射调用 → 抛 **`IllegalArgumentException: wrong number of arguments`**，
而该 catch **只捕获 IllegalAccessException / InvocationTargetException** → 异常逃逸到
**主线程的 activity-result 分发链** → 进程崩溃。**授权页一返回必崩，100% 复现。**

🔴 **为什么是「点击瞬间」崩而不是授权后才崩**：`HealthPermissionsRequestModuleContract`
（API 34+ 路径）带 `getSynchronousResult()`（已 javap 实证）→ 若权限此前已授予过，
launcher **同步返回结果、根本不显示授权页** → 立即触发那个签名不匹配的回调 → 立即闪退。
与用户「一点就闪退」的现象完全吻合。

### 同时修掉的另外两处（会把任何原生异常放大成闪退的结构缺陷）

1. 🔴 **`catch (e: Exception)` 抓不住 `Error`**：Android 14+ 的 HC 走 framework 路径
   （`HealthConnectClientUpsideDownImpl` → `android.health.connect.HealthConnectManager`），
   厂商 ROM（小米 HyperOS）与 AOSP 有差异时抛的是 `NoSuchMethodError` /
   `NoClassDefFoundError` / `AbstractMethodError` —— **全是 Error 不是 Exception**，
   穿透 catch 后在**没有 handler 的 `CoroutineScope(Dispatchers.IO)`** 里直达默认
   uncaughtExceptionHandler → 闪退。
   修法：`client()` / `sdkStatus()` 的 catch 升 `Throwable`；`fetchToday()` 补 `catch (Throwable)`
   分支（置于 Exception 之后）；两个协程都挂 `CoroutineExceptionHandler`（新增 `crashGuard()`），
   `checkAvailability()` 整体再包一层 `Throwable`。
   🔴 更隐蔽的一点：Java 侧那圈 `catch (Throwable)` **形同虚设** ——
   `checkAvailability()` 只是 `scope.launch` 后立即返回，异常发生在**另一个线程**，Java 的 try 根本抓不到。
2. `androidx.activity` 在 capacitor-android 里是 **`implementation`（不传递）** →
