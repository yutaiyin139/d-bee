## 二、🔴 应用官网：**必须填 `https://www.d-bee.com.cn/`**

### 2.1 2026-11-21 实测：两个域名是两个完全不同的站

| 域名 | HTTP | 体积 | 实际渲染内容 | 能否作「应用官网」 |
|---|---|---|---|---|
| `https://www.d-bee.com.cn/` | 200 | **35,286 B** | 真·官网：导航含 首页/产品功能/定价与会员/获取方式/帮助中心/关于我们；首屏「让每一口都吃得明白」「拍一张照片，就知道这餐吃了多少热量」 | 🟢 **可以** |
| `https://d-bee.cn/` | 200 | 11,871 B | **App SPA 本体**。Playwright 渲染后 body 仅 **213 字**，可见内容是「用户协议与隐私政策」+「点击同意并继续」按钮 | 🔴 **不可以** |

**为什么 `d-bee.cn` 不能用**：
1. 官方明文要求「不得是无法访问应用详情的**登录界面**」——根路径渲染出的是同意/授权拦截页，审核员看不到任何功能详情
2. 官方还要求「官网**不支持**提供手机端小程序、公众号和 H5 等页面类型」——`d-bee.cn` 本质是 Web 版 App（H5），正是被排除的类型
3. 实测 `d-bee.cn/get.html`、`/about.html` 返回**与根路径逐字节相同的 11,871 B** → SPA `try_files` 兜底，**这些"页面"并不存在**（`contact.html` 同域名下 404）

## 六、🔴 三个必须知道的填报陷阱

### 陷阱 1：`.env:41` 的 AppID 是**小程序**的，不是移动应用的

```
.env:41  VITE_WECHAT_APPID=wxb7c7122de9c3ab1f   ← 🔴 这是小程序 AppID
```

仓库 8+ 处证据：`mini/project.config.json:5` 同源、`wechatPay.ts:32` 注释自陈语义为「微信开放平台**移动应用** AppID」（即当前值与注释语义相反）、`docs/公安联网备案-…md` §〇 标注「新增小程序（`wxb7c7122de9c3ab1f`）」。

**混填必报 `errcode=-6` / invalid appid**。本次创建通过后拿到的是**全新 AppID**，届时需替换 `.env:41`（另开会话执行）。

### 陷阱 2：三个"签名/公钥"口径别串用

| 场景 | 栏位 | 填什么 |
|---|---|---|
| **微信开放平台** | 应用签名 | **证书 MD5** `0abe7fc5005987ed9b6eae9a45fb9dc9` |
| App 备案（工信部） | 签名 MD5 值 | 证书 MD5（口径**巧合一致**，同值） |
| App 备案（工信部） | 平台公钥 | **RSA 模数** `B75808AA…4AD1`（512 hex，见 `release/App备案-三平台签名信息-20261107.md`）——🔴 **不是**公钥 MD5 |
| 公安联网备案 | 若表单要求「公钥 MD5」 | `55746718174a9ed39e71b351b0a24945` |

### 陷阱 3：改包名必须同步改 wxapi 目录

SDK 按字面类名 `<包名>.wxapi.WXEntryActivity` 回投（`MMessageActV2` 字节码实测有 `ldc ".wxapi.WXEntryActivity"` 拼接）。当前 `java/cn/com/dbee/app/wxapi/` 与 `cn.com.dbee.app` 严格对应 ✅，改包名时必须一起改。

## 七、🟡 登记完成后才能真正跑通微信登录（3 步联动，缺一不可）

当前是**「设计性休眠」**状态——`src/lib/wechat.ts:70 WECHAT_LOGIN_ENABLED=false`、`:73 NATIVE_CODE_EXCHANGE_SUPPORTED=false` → `:105/:110` 提前 return → `initialize()` **从不被调用** → `api==null` → 即便微信真回调也会被 `WechatResponseActivity` 的 `finish()` 静默丢弃。

**登记开放平台不受此影响**，但要真跑通需：

1. 换真移动应用 AppID（`.env:41`）
2. 打开上述两道开关
